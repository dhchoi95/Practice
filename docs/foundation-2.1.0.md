# 2.1.0 — 상단 원국·여섯 분야·지정일 운세

운세 결과를 열면 제목·기간 다음에 출생 원국이 보인다. 시·일·월·년 네 열은 접지 않으며, 날짜를 바꾸어도 그대로 유지된다. 이어서 날짜 선택, 여섯 분야 레이더와 숫자 요약, 총운·학업·재물·건강·연애·사업의 전체 본문을 읽는다. 기존 성격·연애 등 출생 주제에서도 같은 원국을 먼저 확인할 수 있다.

홈과 전체 메뉴에서 오늘·내일·지정일·이달·올해와 정통사주·만세력을 구분했다. 지정일에서는 한국시간 날짜를 고른 뒤 일반·면접·시험·발표·계약·만남의 참고 설명을 선택한다. 일정 선택은 기본 지수와 본문을 바꾸지 않는다. 정통사주는 상세 분석을 기본 제공하고, 만세력은 장문 풀이를 거치지 않고 원국·관계·대운을 확인한다.

## 기준과 보존

기준은 로컬 `287364976778081c8b68a867633159558c5b45bb`이며, 이전 소스 ZIP과 같은 커밋이다. 시작 시 작업 트리는 깨끗했다. 첨부 지시문 전체와 사진 세 장을 읽고 정보 구조를 참고했다. 사진의 원고·광고·브랜드를 복제하지 않았다. 원격 push·공개 배포·외부 URL 발급은 하지 않았다.

기존 역법·입력 정규화·시간 보정·대운 개시·개인정보·공유·인쇄 정책을 재사용했다. 이전 호환 해시 대상 19개는 모두 바이트 동일하다. 관계표에는 이름을 붙여 export했지만 값과 계산식은 바꾸지 않았다. 기존 일반 210개·고급 62개·기간 136개·MBTI 기본 16개/주제 96개와 과거 검토 이력은 보존했다. 이전 원고를 새 분야로 이름만 바꾸어 세지 않았다.

## 계산 사실 → 판단 → 지수·원고

`calculateAdvanced` → `calculatePeriod` → `sectorFacts` → `judgeSector` → `buildSectorReading` → `presentSector` 순서다. 브라우저와 검토용 전체 예시가 같은 표시 계획을 사용한다.

- 기준표: 오행 5, 천간 10, 지지 12, 유효 갑자 60, 십신 대응 100, 지장간 12, 절기 메타데이터 24개. 지장간 가중치는 원래 계산과 같은 0.6/0.3/0.1이며, 구성 수가 적다고 합을 1로 재분배하지 않는다. 12절만 월주 경계이며 시각은 기존 lunar-typescript 계산에서 얻는다. 관계표·시간·대운 정책도 참조할 수 있다.
- 사실: 기간 천간·지지 본기와 일간의 관계, 원국 일지·월지와 대상 기간의 충·육합, 원국 강약 후보, 원국 월·일지 본기와의 반복, 선택한 실제 대운, 세운·월운의 차이를 위치와 함께 보존한다. 기간끼리의 충을 원국 충으로 설명하지 않는다.
- 판단: 분야별 중심 1개와 전제를 충족하는 보완 최대 2개를 우선순위로 선택한다. 인성+식상, 식상+재성, 식상+관성, 비겁+재성, 원국 일지/월지 충, 육합과 충의 부재, 단일 주제의 12개 중심 상황을 구별한다. 구성 출현을 식신제살 등의 구조 성립으로 바꾸지 않는다.
- 지수: 서비스 채택 기본값 50에 선택 원고의 기여를 적용한다. 근거군마다 한 번, ±10 이내이며 전체 기여는 ±25로 제한한다. 분야별 값은 0~100으로 제한해 5 단위로 반올림한다. 기여는 원고의 `contribution`에서 검토한다. 전통 공통 산식·확률·적중률이 아니다. 현재 규칙의 실제 분포는 좁으며 범위를 억지로 넓히지 않았다.
- 총운: 일별 각 구간은 다른 다섯 분야의 동일 가중 평균이다. 월·연은 다섯 분야 각각을 실제 밀리초 구간 길이로 가중 평균해 반올림한 다음, 공개하는 다섯 지수의 평균을 다시 같은 규칙으로 반올림한다. 총운 원고의 0 기여를 총운 지수의 산식으로 오해하지 않도록 trace에 분리했다.
- 월·연: 월별 실제 절입·입춘·대운 전환을 방문해 전 구간을 집계한다. 양력 월을 합치는 과정의 인접 동일 판단 구간은 합친다. 대표 정오나 월중 하루로 대체하지 않는다. 연간 `period.stem/branch`도 연주와 일치한다. 정통사주의 5년 비교에 같은 여섯 지수를 표시한다.
- 표시: 가장 오래 적용되는 중심 풀이, 기간별 생활 계획, 대표 보완과 다른 구간의 중심 풀이를 먼저 싣는다. 모든 구간의 선택과 나머지 고유 원고는 상세에서 확인한다. 같은 원고를 구간마다 다시 인쇄하지 않는다.

지수 구간: 70 이상 활용 / 55~65 활용과 조율 / 40~50 준비와 조율 / 35 이하 범위를 줄여 살피기. 높고 낮음은 서비스가 정한 생활 주제의 요약이다. 비겁·충을 일괄 감점하거나 합·재성을 일괄 가점하는 규칙이 아니며 분야·동시 조건에 따라 기여가 다르다. 건강운은 생활 일정·활동·휴식만 다룬다.

## 미확정과 결정성

시주 미상이어도 확정된 세 기둥과 일간으로 판단할 수 있는 부분은 제공한다. 원국 전체에서 충이 없다는 판단은 모든 기둥이 있을 때만 성립한다. 시주가 없으면 충의 부재·그에 의존하는 합 보완은 확정하지 않는다. 일간 자체가 불확정이면 여섯 지수와 총운은 null, 레이더 도형은 생략한다. 결측을 0이나 50으로 채우지 않는다. 순역 미선택의 두 대운을 하나로 합치지 않는다.

도시 미상에서 요청한 태양시는 실제로 표준시를 적용했다고 안내한다. 같은 계산 객체의 원국·십신·지장간·판단을 함께 갱신한다. 한국 날짜는 Asia/Seoul 기준이며 기본 오늘은 자정 후 갱신하고 직접 고른 날짜는 유지한다. 같은 대상일인 오늘·내일·지정일은 같은 결과다. 방문 횟수·난수·날짜 해시·요일을 지수에 사용하지 않았다.

## 원고 수: 적용 레코드와 독립된 의미를 구분

| 구분 | 새 적용 레코드 | 독립된 의미 묶음 | 재사용 |
|---|---:|---:|---|
| 중심 | 216 | 72 | 6분야×12상황. 일·월·연 변형을 `variantOf`로 연결하고 분야·기간별 계획 문단 18개를 공유 |
| 보완 | 108 | 36 | 6분야×6복합 조건. 같은 본문을 세 기간에 적용하는 정책 레코드 |
| 일정 참고 | 36 | 36 | 6일정×6조건. 실제 준비 항목 2~3개 |
| 합계 | 360 | 144 | 360개 독립 원고나 의미 360종을 달성했다고 세지 않음 |

조건은 검사 가능한 스키마다. 버전·필요 입력·미확정 처리·전제·제외·근거/출처/정책 참조·중복군·상충군·우선순위·지수 기여·생활 상태 가정 여부를 기록한다. `foundation-reviews.json`과 스냅샷은 실제 과거 해시를 보존하고 현재 해시와 소유·대체·순환을 검사한다. 집필 중 재편집 이력도 남겼으며 기록 수는 독립 검토자 수나 승인 수가 아니다.

360이라는 수는 적용 데이터의 출발 규모에 해당한다. 기간마다 전혀 다른 216개 중심 의미나 보완 108개 독립 원고가 필요한 수준의 폭은 아직 부족하다. 우선 실제 18조합 모두 선택·표시·검증되도록 연결했고, 숫자를 늘리기 위한 동의어 변형은 추가하지 않았다.

## 한국어와 실제 읽기

보관된 korean-skills의 humanizer → grammar-checker → style-guide와 번역투·어미·용어 참조를 읽었다. AI 탐지 등급·단어 빈도·변경률·의도적 오타를 승인 기준으로 쓰지 않았다. 기존 문구의 실제 전후 14쌍은 `foundation-korean-edits.json`에 기준 커밋과 함께 기록했다. 새 글의 개발 중 조립 편집은 `foundation-assembly-edits.json`으로 분리했다.

서로 다른 출생 원국 3명의 일·월·연 전체 9개와 면접·시각 미상·입춘 경계 예시를 읽었다. 재물은 비용·정산·계약 자원, 사업은 역할·진행·평가, 학업은 이해·복습·답안, 건강은 생활 일정으로 구별했다. 조립 후 첫 두 문장의 뜻 중복과 본문 속 반복 정책 설명을 덜어냈다. 서로 다른 구간에는 “다른 구간에서는”을 붙였다. 이는 구현자의 읽기이며 독립 편집·명리 승인이 아니다.

반복 검사: 12명×365일·12개월·5년. 날짜·제목·간지를 제외한 실제 기본 표시 본문, 원고 ID 조합, 의미 조합을 따로 센다. 일간이 확정된 프로필의 분야별 고유 본문은 15~36개, 10일 간격 동일 본문은 29~132회/355회 비교였다. 시각 미상·태양시로 일간이 미확정인 한 프로필은 안내가 같아 본문 1개가 365일 반복됐다. 반복 0이나 365개 전부 다름을 목표로 삼지 않는다. 여전히 반복이 많아 독립 편집과 상황 폭 확대가 필요한 부분이다.

주 검사 집단의 미선정 적용 레코드는 30개다. 별도 실제 원국·1962~2050 범위 탐색에서 30개 모두 조건·우선순위를 통과하는 증거를 찾았다. 원래 12명 집단의 커버리지에 합쳐 보고하지 않는다. 논리적 도달 불가능으로 확인된 것은 0개이며, 명리 타당성이 검증됐다는 뜻은 아니다.

## 검증과 전달

필수 실행: `npm run verify`, `npm run build`, `npm run test:e2e`; 이후 실제 Chromium 출력에 `verify-print-pdfs.py`, `verify-advanced-pdfs.py`, `verify-foundation-pdfs.py`. 최종 수치와 로그 해시는 전달 ZIP의 checks.json을 기준으로 한다. 개발 중 실패·재검사도 reports에 보관한다. 이전 UI에 고정된 회귀 단언은 상단 원국·새 6분야·연간 실제 구간으로 바꾸었고, 계산·음력·DST·개인정보·공유·인쇄·정적 경로·확대 검사는 유지했다.

320·360·390·430px와 데스크톱, 실제 글자 크기 200%, 키보드, axe, 시각 미상·오류·새로고침 복구를 확인했다. 원국·그래프·본문은 PDF에 포함하고 공개 화면에서 감춘 개발 trace는 PDF에도 숨긴다. 화면 캡처는 합성 입력이며 전체 페이지 이미지와 상단 이미지가 구분돼 있다. PDF 텍스트/좌표 검증과 일부 대표 페이지의 시각 확인을 구분한다.

기존 설치 Node 24.19.0/npm 11.9.0와 시스템 Chromium·PyMuPDF를 사용했다. 새 npm ci·원격 CI·새 Lighthouse·실제 휴대전화·Instagram 인앱·공개 호스팅·물리 프린터는 실행하지 않았다. 巳 보조 지장간 순서와 가중치, 도시 좌표 출처, 강약·용신·원전의 독립 검토는 계속 대기다.

## 로컬 모바일 확인

전달 소스를 자신의 PC에 풀고 Node 24 환경에서 `npm ci`, `npm run build`, `npm start`를 실행하면 정적 서버가 `0.0.0.0:3000`에 바인딩된다. PC에서 접속을 확인한 뒤 같은 Wi-Fi 휴대전화에서 `http://PC의 실제 사설IPv4:3000` 형식으로 열 수 있다. 방화벽과 네트워크 분리는 별도 확인해야 하며 이 실기기 경로를 이번 작업에서 실행한 것은 아니다.

현재 /workspace는 클라우드 머신이다. PC의 사설 IP를 여기의 접속 주소로 안내하지 않는다. 공개·외부 접속 URL은 발급하지 않았다. 인스타 인앱 확인은 별도로 접근 가능한 테스트 호스팅이 생긴 뒤 진행해야 한다.

클라우드 환경의 `start_skill` 시작 지침은 설정 초안에 저장했다. 새 작업에서 재사용하려면 환경 설정에서 검토·저장한 뒤 개발환경을 게시해야 한다. 이 동작은 사이트의 공개 배포와 별개이며, 새 환경 복원을 직접 확인한 것은 아니다. 저장된 시작 지침 자체가 서버 실행이나 사이트 공개를 뜻하지 않는다.
