검증 환경: Linux 클라우드, Node 24.19.0 / npm 11.9.0 / ICU 78.3, Next.js 16.4.2 / React 19.3.1, 시스템 Chromium과 Playwright 1.64.1. 작업일 2026-10-20. 현재 설명 릴리스 1.0.2. 최신 접수 원본과 대응은 `external-rereview-1.0.1.md`, `review-response-1.0.2.md`에 있습니다. 이전 검토·대응 문서는 이력으로 보존합니다. 실제 개인이 아닌 합성 프로필만 사용했습니다.

## 계산 근거

보고서에서 KASI 직접 조회로 확인한 2017-02-26, 03-27, 03-28의 양/음력 기대값 3개를 전사한 회귀 검사와 역변환이 통과했습니다. 직접 조회는 이번 환경의 프록시 403으로 실패했습니다. 원본 59행 표가 없으므로 이번 작업이 KASI를 재조회한 독립 검증이라고 세지 않습니다. ICU Dangi와 다른 2017-02-26~03-27 구간에 맞춰 앱을 바꾸지 않았습니다.

접수 보고서의 23,669일 달력 비교와 1,068절입 비교는 외부 검토자의 수행 결과입니다. 이번 재실행 범위는 저장소의 29개 ICU 날짜, 72절입, 추가 3개 KASI 보고서 날짜와 정책 경계 검사입니다.

ICU Dangi로 수집한 서로 다른 29개 날짜의 한국 음력 연·월·일·윤달 기대값과 왕복이 일치했습니다. 최소 지원일, 양력 윤년, 평달·윤달 시작·29/30일, 설 전후를 포함합니다. 음력의 기대값을 실행용 한국 달력 패키지로 만들지 않았습니다.

별도 Astronomy Engine의 72절입 시각과 앱 절기 모델을 비교했습니다. 최대 모델 차이는 **44.61초**(1962년 한로), 검사 허용치는 90초입니다. 초 단위 공인 인증은 아닙니다. 2024년 대설처럼 원자료 UTC+8 날짜와 한국 날짜가 다른 경우도 검사합니다.

별도 일진 테이블과 앱 JDN 식은 30개 날짜에서 일치합니다. 자정 전후 6개 고정 사례의 일주·시주, 입춘·경칩·대설의 직전/정확한 모델 경계/직후, DST 적용·비적용·gap·fold·전날 환산, 시간 미상 경계와 양/음력 동일 순간을 검사했습니다. 이 중 정책 경계 회귀 검증은 독립 천문 비교와 구분합니다.

## 원고와 규칙

조건별 원고는 70개 기본 주제, 35개 오행 보완, 30개 기간, 28개 가벼운 유형, 17개 시간 미상·관계·집계 안내로 총 180개입니다. 오행 보완 35개는 1.0.1에서 주제별로 다시 썼고, 상징·개수의 공통 설명 5개는 별도입니다. 이 집계가 180개 해석의 의미상 독립성을 증명하지는 않습니다. 모든 원고는 automated-checked이며 human-reviewed로 꾸미지 않았습니다.

정상 일간이 있는 합성 프로필에서 종합 본문은 1,410~1,800자, 주제는 약 474~836자, 오늘은 364~388자입니다(조언·제목 제외). 일간 미확정은 일부 안내만 남겨 분량이 짧고 명확히 제한합니다. 올해·월간은 절기 구간별 원고를 함께 보여줍니다.

all/any·eq/in/gte/lte, unknown·requires·제외 조건, priority·specificity·ID 동률, 독점 그룹, 상반 stance, 배열 역순 재현, 빈 원고 중립 안내, 다른 사주의 결과 차이, 이름 무관성, 원국/기간 분리를 검사했습니다. 한 수정에서 기간 feature가 기본 성향 키워드에 섞이는 회귀를 발견해 카테고리 기준으로 고친 뒤 재검사했습니다.

## 화면과 개인정보

F-01-R 회귀 검사를 추가했습니다. 수정 전에는 1987-06-01 양력·시간 미상의 연·월·일 상세 3개가 실패하고, 1992-05-15 10:30의 확정 입력 3개는 통과했습니다. 수정 후 6개 모두 펼친 상세와 실제 PDF에서 안내가 관계값과 일치합니다. 미확정일 때는 기간 간지·경계만 표시하며 관계를 해석하지 않았다는 문구가 있고, 관계 분석·구간 풀이 요약 주장은 없습니다. 확정 입력의 기존 안내는 유지됩니다.

인쇄는 CSS 표시 확인에 더해 실제 Chromium PDF를 생성했습니다. 상세를 닫거나 연 결과 각각 4쪽의 텍스트가 같고, 사주표·표준시·8글자 집계·강약/용신 아님 안내가 포함됩니다. 연말 연간 결과 3쪽에는 2027년 1월 1일 종료 표기가 있습니다. 인쇄 후 각 상세의 원래 상태 복원과 반복 인쇄 이벤트도 검사했습니다.

실제 `out/`를 제공하는 Node 정적 서버로 검사했습니다. 홈→입력→결과, 잘못된 날짜 수정, 음력 윤달, 시간 미상, 입력 재사용·수정·삭제, 모든 메뉴 직접 진입과 새로고침, 없는 경로 404, 공유·취소·복사·인쇄, 저장소 사용 불가, 악성 별명 안전 렌더링을 확인했습니다.

폼 제출·결과·메뉴 이동에서 출생정보가 요청 URL/payload·콘솔·query/fragment에 없고 local/sessionStorage에도 남지 않았습니다. JS 비활성화 상태에서도 제출 버튼은 비활성화되고 Enter로 개인정보를 전송하지 않습니다. 정적 HTML의 form-action CSP로도 폼 전송을 차단합니다. 호스팅의 일반 접속 로그 가능성은 개인정보 안내에서 별도로 설명합니다.

320·360·375·390·430·768·1024·1440px의 홈/입력/결과 넘침 검사가 통과했습니다. 375·390·1440px에서 9개 전체 캡처를 갱신하고 별자리 195·320·390px 및 일간 미확정 390px의 4개 캡처를 추가했습니다. 여기에 확정/미확정의 연·월·일 상세 캡처 6개를 추가해 현재 원본은 19개입니다. 별자리·미확정 화면과 실제 인쇄 PDF를 직접 확인했습니다. 195px CSS 폭(390px 화면의 200% 확대에 준함), 글자 200% 확대, 키보드, 메뉴 포커스 순환·ESC·복귀를 확인했습니다. axe의 WCAG 2/2.1 A·AA 검사에서 홈·메뉴·입력·확장 결과 위반이 없었습니다. Lighthouse의 별도 이름 일치 검사에서 로고 이름을 추가 조정했고 최종 재검사도 통과했습니다.

모바일 터치·가로 방향과 미국 LA 브라우저 시간대에서 한국 날짜도 검사했습니다. 실제 iOS/Android·인스타그램 인앱 브라우저·실제 공유 시트는 미실행이며 지원/취소 분기는 자동화된 모의 API 검사입니다.

## 1.0.0 성능 측정 — 이번 수정에서 재측정하지 않음

Lighthouse **13.5.0**, Headless Chromium **151.0.0.0**, 모바일(moto g power 에뮬레이션), 기본 **simulate** 네트워크·CPU 제한으로 `out/` 홈을 로컬에서 측정했습니다. 최종 실행 시각은 2026-10-20T02:27:48Z입니다.

| 지표 | 최종 실측 |
|---|---|
| Performance | 100 |
| Accessibility | 100 |
| Best Practices | 100 |
| SEO | 100 |
| LCP | 1.906초 |
| CLS | 0 |
| Total Blocking Time | 40ms |
| 초기 요청 수 | 11개 |

첫 실행은 압축 없는 로컬 서버와 기본 링크 prefetch에서 성능 87, LCP 4.043초였습니다. 서버에 실제 gzip 전송을 추가하고 선택하지 않은 메뉴의 prefetch를 꺼 전송량을 줄였습니다. 로고의 보이는 글자와 접근성 이름 불일치도 고쳐 최종 검사에서 통과했습니다. 앱의 내용·계산·검증·측정 제한을 끄거나 낮추지 않았습니다.

```bash
CHROME_PATH=/usr/bin/chromium npx lighthouse http://127.0.0.1:3000/ --chrome-flags='--headless --no-sandbox --disable-dev-shm-usage' --output=json --output-path=reports/lighthouse-mobile.json --only-categories=performance,accessibility,best-practices,seo --quiet
```

서버는 먼저 `npm start`로 실행합니다. 최종 원본은 `reports/lighthouse-mobile.json`, 변경 전 원본은 `reports/lighthouse-initial-mobile.json`에 있습니다. 1회 로컬 실험이며 현장 속도·다른 기기·공개 호스팅·접근성 전체를 보장하는 수치가 아닙니다. 운영 호스팅에서도 압축·캐시 설정을 적용해야 합니다.
