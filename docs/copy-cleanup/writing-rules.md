# 이후 원고 작성·교정 기준

이번 요청의 작성 기준을 이후 추가 원고에도 적용합니다. 맞춤법 점수·AI 탐지 점수·변경률은 승인 기준이 아닙니다.

1. 원고 ID의 선정 조건·분야·하루/월/연 범위를 먼저 읽습니다. 확정된 계산 사실, 상징에 따른 해석, 생활 조언을 구분합니다. 조건에 없는 합격·수입·이별·질병 등 사건을 새로 넣지 않습니다.
2. 제목은 다루는 상황을 직접 보여줍니다. ‘자원의 흐름’, ‘기준을 다정하게’ 같은 뜻이 불분명한 표어로 바꾸지 않습니다. 명령형으로 통일하지 않습니다.
3. 첫 문장은 해당 분야의 상황이나 운세를 말합니다. 다음에 구체적인 이유·생활 장면을 설명하고, 조언은 필요한 만큼만 잇습니다. 모든 글을 확인·계획·기록하라는 지시로 만들지 않습니다.
4. 본문은 자연스러운 합니다체를 기본으로 합니다. 짧은 입력·오류·공유 안내에는 기존 해요체를 씁니다. 자연스러운 기존 문장은 유지합니다. 보조 용언의 허용 표기까지 확인하며 어미나 띄어쓰기를 기계적으로 바꾸지 않습니다.
5. 일반 운세에서는 공부·돈·만남·업무·식사·휴식의 말로 씁니다. 원국 상세의 십신·지장간·격국·용신은 필요한 뜻을 짧게 설명할 수 있습니다. 전문용어를 정상적인 사주표에서 삭제하지 않습니다.
6. ‘이 주제로 읽는다’, 규칙 ID·버전·원전 검토 상태·선정 과정은 운세 본문에 넣지 않습니다. 출처와 근거는 내부 기록에 남깁니다. 원고에 남은 `proposal` 필드를 근거로 문단마다 제안 박스를 다시 만들지 않습니다.
7. 새 원고는 서로 다른 조건의 작은 묶음으로 집필합니다. 문장 틀에 분야명만 바꾸는 생성, 동의어 치환, 무작위 어미 변경을 하지 않습니다. 후보 원고 하나보다 실제 중심·보충 문단이 붙은 여섯 분야 전체를 읽고 반복을 점검합니다.
8. 시간 미상·경계의 미확정 값은 채우지 않습니다. 입력 누락의 제한은 결과 전체에 필요한 위치에서 짧게 설명합니다. 같은 제한을 모든 문단 끝에 반복하지 않습니다.
9. 원국 원고의 공개 문장은 `src/content/advanced/natal-copy.json`에서 편집합니다. `natal.ts`의 기존 조건·역사적 정의를 임의로 고치지 않습니다. 분야 원고는 `src/content/foundation/sectors.json`에서 해당 레코드를 직접 고칩니다.
10. 본문/주장 연결, 버전·날짜·내용 해시를 갱신하고 과거 검토 기록과 스냅샷은 보존합니다. 현재 상태는 작성자 검토이며 독립 승인으로 올리지 않습니다. 계산 조건·우선순위·점수 기여를 함께 바꾸는 작업은 문장 교정과 구분해 검토합니다.

작업 후 `npm run verify`, `npm run build`, 관련 브라우저 검사를 실행하고 실제 인쇄 PDF도 읽습니다. 새 레코드나 의도한 조건 변경이 있으면 `audit-copy-cleanup.ts`의 고정 이전 버전과 다르다는 결과를 무조건 통과시키지 말고 변경 이유와 별도 검증을 기록합니다.

## 2.4.1 후속 교정에서 추가한 기준

- ‘있을 거입니다’ 같은 잘못된 어미를 그대로 두지 않습니다. 현재 원고의 본문뿐 아니라 근거의 반례 문장도 함께 고칩니다. 정상적인 ‘근거입니다’와 오류인 독립된 ‘거입니다’를 구분합니다.
- 조립 함수에서 ‘한 달 내내 같은 흐름은 아니겠습니다’ 같은 연결 문장을 자동으로 붙이지 않습니다. 다른 시기의 원고를 함께 보여줄 때에도 실제 저장된 완성 문단을 그대로 읽고 앞뒤 뜻을 확인합니다. 문구를 무작위로 돌려 쓰는 방식으로 반복을 숨기지 않습니다. 적용 시기와 선정 이유는 내부 이력에 보존합니다.
- 같은 재성 조건이어도 모든 분야를 돈·비용·시간 관리로 쓰지 않습니다. 총운은 선택과 만족, 학업은 이해와 적용, 재물은 수입·지출, 건강은 생활 습관과 휴식, 연애는 관심과 대화, 사업은 업무의 결과와 상대의 요구를 각각 다룹니다. 이는 원고의 관점을 구분하는 기준이며 사주 조건을 다른 계산으로 바꾸는 규칙이 아닙니다.
- 건강 원고에 새로운 질병·진단·효능을 만들거나 연애 원고에서 실제 상대와 연애 상태를 추정하지 않습니다. 일반적인 생활 제안과 실제 사건에 관한 주장을 구분합니다.
- 전체 점검에는 `npm run content:copy-review`와 기존 `npm run verify`를 사용합니다. 동일 문장 검사는 복제 여부를 찾는 보조 수단이며, 서로 다른 단어를 썼다는 사실만으로 내용이 다르다고 승인하지 않습니다. 여섯 분야를 나란히 읽어 각 문단이 어떤 상황을 다루는지 설명할 수 있어야 합니다.
- 과거 검토 스냅샷, 이전 보고서의 인용문, 오류를 재현하는 테스트는 현재 원고와 구분합니다. 과거 기록을 고쳐 오류가 없었던 것처럼 만들지 않습니다.
