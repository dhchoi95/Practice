# 사주 데이터 2.1.0 확인 결과와 다음 고도화 지시문
작성일: 2026-10-23
대상: saju-review-small.zip

## 현재 판정

**데이터가 실제로 추가되고 서비스에 연결됐다. 다만 1차 구축 완료이며, 콘텐츠 고도화가 끝난 상태는 아니다.**

이 작은 검토본에는 최신 소스와 실제 원고 JSON이 들어 있다. 따라서 파일이 작다는 이유로 내용 추가 여부를 판단하지 못하는 상태는 아니다. 과거 소스 ZIP, 개별 PNG, 배포 ZIP 등은 제외돼 있으며 이번에 확인했다고 간주하지 않았다.

### 직접 확인한 데이터

| 구분 | 적용 레코드 | semanticId 기준 의미 묶음 |
|---|---:|---:|
| 분야별 중심 원고 | 216 | 72 |
| 분야별 보완 원고 | 108 | 36 |
| 일정 참고 원고 | 36 | 36 |
| 합계 | 360 | 144 |

의미 묶음은 저장된 식별자를 집계한 수다. 144개 모두가 내용상 충분히 독립적이라는 편집 승인이나 전통 해석 검증을 뜻하지 않는다.

실제 파일:
- project/src/content/foundation/sectors.json: 중심·보완 324개.
- project/src/content/foundation/schedules.json: 일정 36개.
- project/src/domain/foundation/engine.ts: 계산 사실을 분야별 판단·지수·선택 원고에 연결.
- project/src/domain/foundation/presentation.ts: 실제 기본 본문을 조합.
- project/content-review/foundation-*.json: 집필·수정·검토 기록.

360개 전부의 현재 상태는 author-reviewed-pending-independent다. 구현자의 검토 기록이 있으며 독립 승인은 대기 중이라는 뜻이다.

## 이번에 직접 실행한 확인

Python으로 실제 JSON을 읽어 레코드·의미 묶음·검토 상태·공통 문단·선택 조건을 집계했다. 또한 제공된 예시 JSON 11개, 51개 구간에서 저장된 계산 사실을 입력으로 선택 규칙과 지수 계산을 별도 재현했다. 선택 ID·구간 지수·최종 총운 평균 관련 비교 623건에서 불일치는 없었다.

이 623건은 앱의 단위 테스트 623개를 새로 통과했다는 뜻이 아니다. 첨부된 예시의 사실값과 데이터로 선택·산식의 일관성을 확인한 비교 건수다. 출생 정보에서 그 사실값이 올바르게 계산되는지까지 독립 재계산한 것은 아니다.

이번에 실행하지 않은 항목:
- npm ci, npm run verify, 빌드와 브라우저 E2E.
- 실제 휴대전화·인스타그램 인앱·공개 운영 사이트.
- 역법·천문·도시 좌표·명리 원전의 외부 독립 대조.
- PDF 전체의 시각 검토와 웹 화면 전체 검토.

작은 검토본의 project에는 설치된 node_modules가 없다. 이번 확인은 데이터 고도화 상태에 초점을 맞춘 검토이며, 구현자가 보고한 365개 테스트·79개 브라우저 검사 등을 이번 실행 결과로 사용하지 않았다. 앱 코드는 수정·배포하지 않았다.

## 데이터 고도화가 필요한 구체적인 지점

### 1. 기간별로 레코드를 나눴지만 핵심 의미는 많이 재사용한다
- 중요도: 높음 — 사용자가 기대하는 상세한 기간별 풀이의 폭.
- 근거: sectors.json의 같은 semanticId에 해당하는 day/month/year 원고.
- 재현: overall:learn-express 등의 세 기간 레코드에서 paragraphs[0]을 비교한다. 핵심 문단은 같고 기간 계획 문단이 달라진다.
- 확인: 중심 216개는 실제로 72개 의미의 세 기간 변형이다. 보완 108개 역시 36개 의미를 세 기간에 적용한다.
- 수정 방향: 일운은 당일 행동과 짧은 관계, 월운은 진행·중간 조정, 연운은 장기 방향·대운·세운을 중심으로 새 정보를 작성한다. 모든 공통 설명을 없앨 필요는 없지만 기간 이름만 바꾸어 독립 원고로 세지 않는다.
- 확신도: 높음. 데이터 직접 대조.

### 2. 같은 분야·같은 기간의 두 번째 문단이 12개 상황에서 공통이다
- 중요도: 높음 — 본문 길이에 비해 독자에게 새로 주는 정보가 적다.
- 근거: sectors.json의 core 원고 paragraphs[1].
- 재현: day/study의 12개 중심 원고에서 두 번째 문단을 비교한다.
- 확인: 각 기간의 중심 원고 72개에서 두 번째 문단은 여섯 종류뿐이다. 즉 분야별 공통 계획 문단이다.
- 수정 방향: 공통 안내는 별도 보조 정보로 짧게 분리하고, 해당 상황의 실제 근거·반대 조건·구체적인 해석을 담는 문단으로 보강한다.
- 확신도: 높음. 본문 문자열 직접 집계.

### 3. 여섯 분야의 중심 선택 조건과 우선순위가 동일한 틀이다
- 중요도: 높음 — 분야별로 다른 판단을 하는 폭이 제한된다.
- 근거: sectors.json의 12개 중심 scenario, engine.ts의 judgeSector.
- 재현: day의 같은 scenario를 여섯 domain에서 모아 requires/exclusions/priority를 비교한다.
- 확인: 12개 중심 상황 모두 여섯 분야에서 같은 조건·우선순위를 사용한다. 본문과 점수 기여는 분야별로 다르지만 중심 상황을 고르는 기준은 공통이다.
- 수정 방향: 학업은 이해·표현·평가, 재물은 자원·분배, 사업은 역할·성과 등 각 분야가 중요하게 보는 관계와 상반 조건을 명시한다. 같은 주제가 여러 분야에 적용될 수는 있지만 모든 분야가 같은 시나리오 순위를 따르게 만들 필요는 없다.
- 확신도: 높음. 데이터 구조 직접 비교. 이것이 명리학적으로 틀렸다는 판정과는 별개다.

### 4. 원고가 사용하는 조건의 해상도가 아직 낮다
- 중요도: 중간~높음 — 같은 일간이나 비슷한 원국의 결과가 자주 겹칠 수 있다.
- 근거: engine.ts의 group·sectorFacts, sectors.json의 실제 조건.
- 확인: 십신은 비겁·식상·재성·관성·인성 다섯 그룹으로 묶어 중심 선택에 사용한다. 현재 원고의 조건 경로는 16종이다. 전체 원국에서 계산해 둔 세부 정보가 모두 원고 선택에 쓰이는 것은 아니다.
- 수정 방향: 필요한 곳에서 정·편 십신을 구분하고, 실제 위치·노출·뿌리·일지와 월지의 차이·선택 대운과 대상 기간의 관계를 추가한다. 구체적인 해석을 쓸 근거가 있을 때만 조건을 늘린다.
- 확신도: 높음. 실제 선택식과 조건 경로 집계.

### 5. 반복이 여전히 많다
- 중요도: 높음 — 재방문 경험.
- 근거: reports/foundation-2.1.0/longitudinal.json.
- 첨부 보고값: 일간이 확정된 11개 프로필의 분야별 연간 고유 일운 본문은 15~36개. 10일 간격 동일 본문 비교는 355회 중 29~132회.
- 주의: 이 장기 결과를 이번에 365일 전체 재생성하지는 않았다. JSON을 읽어 범위만 재집계했다.
- 수정 방향: 반복이 집중되는 원고·조건부터 고친다. 무작위 선택·요일·날짜 해시·동의어 변형으로 감추지 않는다.
- 확신도: 제공된 결과 파일 집계에 대해서는 높음. 전체 재실행 검증은 미실행.

### 6. 상충·중복 메타데이터의 선택 적용을 보완할 필요가 있다
- 중요도: 중간 — 향후 원고가 많아질 때 선택 품질 유지.
- 근거: types.ts의 meaningAxis/conflictGroup/duplicateGroup과 engine.ts의 judgeSector.
- 확인: 현재 judgeSector는 중심 1개와 우선순위가 높은 보완 최대 2개를 선택한다. 해당 메타데이터를 이용한 일반적인 의미 충돌·본문 중복 제어는 이 선택 함수에 구현돼 있지 않다. 점수 근거군 중복 가산 방지는 별도로 있다.
- 수정 방향: 점수 중복과 문장 중복을 구분하고, 실제 원고 조합에서 상충·중복을 검사하도록 명시적으로 구현한다. 현재 모든 출력이 모순된다는 뜻은 아니다.
- 확신도: 높음. 선택 함수 직접 확인.

## 앞으로의 고도화 방식

작업을 한 번에 끝낸다고 선언하기보다 차수별로 진행한다.

반복이 많은 결과 찾기 → 원인 조건 분석 → 해석할 수 있는 세부 특징 추가 → 필요한 원고 집필 → 전체 조합 읽기 → 고정 기준 집단과 추가 집단 비교 → 버전 기록.

매 차수에서 원고 수뿐 아니라 다음을 함께 본다.
- 새로 설명할 수 있게 된 사주·기간 조건.
- 의미가 같은 레코드를 제외한 실제 원고의 폭.
- 자주 나오는 공통 문단의 비율.
- 같은 원고가 연속되거나 10일 뒤 다시 나오는 빈도.
- 서로 다른 출생 정보의 결과가 겹치는 이유.
- 본문과 그래프, 근거와 본문의 일치.
- 자연스러운 한국어와 분야별 새 정보.
- 남아 있는 출처·정책 검토.

# Codex에 전달할 후속 지시문

현재 2.1.0은 1차 데이터 구축과 UI 연결을 마친 기준 버전으로 삼는다. 이번 작업은 데이터를 계속 개선하기 위한 다음 차수다. 기반을 처음부터 다시 만들거나 UI를 전면 개편하지 말고, 실제 선택 조건·독립된 의미·본문의 깊이를 고도화하라.

첨부된 작은 검토본에는 소스와 원고가 있다. 전체본에서 빠진 과거 ZIP·이미지·배포 산출물이 필요하지 않은 작업부터 실제로 진행하라. 없다는 이유로 데이터 작업 전체를 중단하지 마라. 기존 ID·수정 이력·검토 상태와 사용자 작업을 보존하라.

공개 배포·원격 push는 하지 않는다. 런타임 LLM/API·서버 DB·로그인·추적 기능은 추가하지 않는다. 이번 지시는 실제 데이터와 필요한 선택·조립 코드의 수정을 허용하지만, 새 메뉴·새 디자인·새 과금 구조는 요구하지 않는다.

## A. 기준을 고정한다
1. AGENTS.md와 기존 문서·정책을 읽는다.
2. 기존 원고와 실제 완성 본문을 저장하고 이번 차수의 기준 버전·해시를 기록한다.
3. 기존 12명×365일·12개월·5년 검사 집단을 그대로 유지한다.
4. 서로 다른 원국과 경계·미확정 사례를 포함하는 추가 집단 12명을 만든다. 기존 집단 결과와 별도로 보고한다.
5. 기존 테스트·계산·개인정보·상단 만세력·여섯 분야·지정일 동작을 유지한다.

## B. 개수보다 실제 부족한 조건을 찾는다
먼저 현재 결과를 재생성해 다음을 표로 정리하라.
- 분야·기간별 실제 의미 수와 본문 변형 수.
- 중심/보완/최종 표시 단계의 선택 점유율.
- 10일 간격 반복, 연속 반복, 같은 문단이 쓰이는 비율.
- 일간이 같은 다른 원국에서 겹치는 부분.
- 미선정·도달 불가·다른 규칙에 계속 밀리는 원고.
- 원고는 선택됐지만 기본 본문에 표시되지 않는 경우.
- 출처 검토가 부족해 확정하지 못하는 판단.

미확정 안내의 반복은 콘텐츠 부족으로 똑같이 취급하지 않는다. 같은 의미의 이름만 바꾼 레코드를 새 풀이로 세지 않는다.

## C. 분야마다 중요한 판단을 구분한다
현재 여섯 분야의 중심 시나리오 선택 조건·우선순위가 동일한 구조를 재검토하라.

- 학업: 인성·식상·관성의 구체적 관계, 이해·표현·평가와 그 반대 조건.
- 재물: 재성과 식상·비겁 등의 연결, 분배·관리·지출·거래 조건.
- 사업: 관성·식상·재성의 역할·성과·평가·협업 관계.
- 연애: 일지와 기간 관계 등 실제 근거, 표현과 조율. 현실의 혼인·성적 지향·상대 의도는 추측하지 않음.
- 건강: 일정·활동·휴식에 관한 편집적 해석 범위. 신체·질병·사고 예측은 추가하지 않음.
- 총운: 다른 분야의 단순 복사 대신 공통 구조와 우선순위를 연결.

하나의 특징이 여러 분야에 공통으로 적용돼도 된다. 여섯 분야가 반드시 다른 시나리오를 골라야 한다는 제약을 만들지는 마라. 다만 각 분야에서 해당 원고를 우선한 이유를 설명할 수 있어야 한다.

십신을 다섯 그룹으로 뭉친 기존 조건만 늘리지 말고 필요한 경우 정·편을 구분하라. 원국의 일지·월지·천간 노출·뿌리·대운과 기간 관계 등 이미 계산한 사실을 활용하라. 새로운 전통 해석 기준이 필요하면 출처·정책·예외를 명시하고 후보 상태를 보존하라.

합·충·형 등이 존재하는 것과 특정 격·구조·합화가 성립하는 것을 구분하라. 조건을 많이 붙이는 것만으로 깊이 있는 해석이라고 간주하지 마라.

## D. 실제 원고를 추가·개선한다
이번 차수에서는 추가 독립 의미 72개를 출발 목표로 삼는다. 기본 배분은 여섯 분야에 각 12개이지만 부족한 범위를 분석한 뒤 조정할 수 있다.

집필 방법:
1. 반복이 많은 조건을 고른다.
2. 기존 원고와 구분되는 해석 질문을 적는다.
3. 필요한 근거·반대 조건·미확정 처리를 정의한다.
4. 해당 조건에서만 선택되는 원고를 쓴다.
5. 실제 원국과 날짜에서 선택되는 증거를 남긴다.
6. 전체 보고서에서 새 정보가 생겼는지 확인한다.

72개는 수량 채우기 기준이 아니다. 확인할 수 없는 판단을 만들어내거나 문장만 바꿔 목표를 채우지 않는다. 실제 완성·검토 보류·중복 통합 수를 따로 기록한다. 작은 묶음으로 작업하되 계획서나 몇 개의 예시에서 끝내지 말고 이번 차수의 데이터·선택·검증을 끝까지 구현하라.

같은 의미를 일·월·연으로 나눈 세 레코드는 세 독립 의미로 세지 않는다. 의미 식별자가 달라도 실질적으로 같은 내용이면 통합하거나 관계를 기록한다.

## E. 공통 계획 문단을 줄인다
현재 core의 두 번째 문단은 분야·기간마다 12개 상황에서 공통이다. 이를 긴 개인 풀이의 일부처럼 반복하는 문제를 개선하라.

- 공통 안내가 필요하면 짧은 별도 안내로 옮긴다.
- 본문에는 선택 조건과 연결되는 구체적인 새 해석을 넣는다.
- 일운은 그날의 짧은 선택과 준비.
- 월운은 진행·조정·마무리 및 실제 절입 구간.
- 연운은 장기 방향·대운·세운·기간 내 변화.
- 세 기간의 글을 어미·시간 단어만 바꿔 쓰지 않는다.
- 모든 문단을 길게 만들어야 한다는 목표를 두지 않는다.
- 새 근거를 말하지 못하는 문장은 줄인다.

## F. 선택·상충·중복 제어를 실질적으로 작동시킨다
현재 메타데이터인 meaningAxis/conflictGroup/duplicateGroup을 어떤 의미로 사용하는지 정의하고 실제 선택·표시 과정과 연결하라.

- 중심 1개·보완 2개라는 개수 제한만으로 모순이 사라진다고 가정하지 않는다.
- 점수 중복 가산 방지와 문장 의미 중복 방지를 별도로 처리한다.
- 긍정·부담 요인이 함께 있으면 반대 조건을 설명한다.
- 같은 시점의 모순과 서로 다른 기간 구간의 변화를 구분한다.
- 구간·위치·선택 이유·표시 이유를 trace로 남긴다.
- 본문에 안 나온 보완 근거가 점수에 영향을 주었다면 사용자용 근거에서 확인할 수 있게 한다.
- 원고가 늘어나도 ID 순서 때문에 더 구체적인 원고가 항상 밀리는 문제가 없는지 검사한다.

## G. 한국어를 전체 결과에서 편집한다
기존 korean-skills 자료와 실제 문체 기준을 확인한다. 이를 사용했다고만 쓰지 말고 원고·조립 결과에 반영하라.

- 생활 조언만 이어 붙이지 말고 계산된 관계가 왜 그 분야의 주제로 이어지는지 자연스럽게 설명한다.
- 비슷한 “확인해 보세요 / 정해보세요 / 나누어 보세요”가 문단마다 반복되지 않게 한다.
- 추상적인 “에너지·흐름·가능성”으로 내용을 대신하지 않는다.
- 같은 제안을 본문·보완·마지막 문장에서 세 번 반복하지 않는다.
- 전문 용어를 모두 빼지 말고 필요한 것만 쉬운 설명과 함께 남긴다.
- 사진이나 다른 서비스의 원고를 복제하지 않는다.
- 자연스러움을 이유로 실제 상황을 아는 척하거나 사건을 확정하지 않는다.

수정 전후 예시는 실제 기존 문장에서 뽑고 수정 이유를 설명하라. AI 탐지 점수나 고친 글자 비율로 통과 여부를 정하지 않는다.

## H. 그래프는 근거와 함께 유지한다
- 원고가 늘었다고 높은 점수만 늘리지 않는다.
- 40~60 근처에 몰린다는 이유만으로 수치를 난수로 퍼뜨리지 않는다.
- 점수 기여와 그 해석을 문서화하고 같은 정책을 재현 가능하게 한다.
- 같은 입력·날짜·정책·버전의 결과는 고정한다.
- 출생 시각이나 일간이 미확정이면 기존 결측 처리를 유지한다.
- 총운의 동일 가중 평균, 월·연 구간 가중 집계, 날짜 경계를 검증한다.
- 면접·시험 등 일정 선택은 기본 지수를 바꾸지 않는다.
- 0~100을 실제 성공·질병·수익 확률로 설명하지 않는다.

## I. 비교해서 검증한다
기존 기준 집단과 추가 집단을 나눠 전후를 비교하라.
- 실제 의미 수, 조건 커버리지, 기본 표시 본문 다양성.
- 원고 한 개의 점유율, 공통 문단 비율.
- 10일 반복·연속 반복.
- 서로 다른 출생 정보의 결과 겹침.
- 상충·중복·미확정 전제 위반.
- 그래프와 본문의 일치.
- 긴 본문에서의 새 정보와 읽기 쉬운 한국어.

반복률이 떨어진 것만으로 품질 통과라고 하지 않는다. 명리 조건에 따른 설명이 같아야 할 날까지 억지로 다르게 만들지 않는다. 특정 비율을 맞추려고 무작위 선택을 도입하지 않는다.

새로 쓴 원고는 실제로 선택되는 사례를 확인한다. 일부 표본에서 안 나오는 것과 논리적으로 불가능한 것을 구분한다. 기존 검사 집단에서 부족한 것을 별도 탐색 결과로 덮어쓰지 않는다.

현재 저장소의 lint·typecheck·관련 단위/통합·콘텐츠 검사·빌드를 직접 실행한다. 선택·조립·UI가 바뀐 범위의 브라우저 회귀와 인쇄를 확인한다. 이전 로그를 이번 실행의 통과 증거로 복사하지 않는다.

## J. 다음 차수로 이어질 자료를 남긴다
- content-backlog.json 또는 동등한 구조에 분야·조건·문제·근거·우선순위·완료 기준을 기록한다.
- 이번에 해결한 항목을 닫고 남은 항목을 업데이트한다.
- 원고 수 증가뿐 아니라 무엇을 더 구체적으로 설명하게 됐는지 보고한다.
- 추가할 데이터가 정당화되지 않는 분야는 억지로 늘리지 말고 검토·통합·편집 작업으로 전환한다.
- 매 실행은 검증 가능한 한 차수를 완성한다. 스스로 무한 실행하거나 자동 게시하는 구조는 만들지 않는다.

최종 전달은 다음 두 묶음으로 나눈다.
1. 작은 검토본: START_HERE, 변경 요약, 실제 데이터·소스, 핵심 검사 결과·대표 전체 출력. 전체 페이지 캡처·배포 산출물·과거 중복 자료는 별도 분리.
2. 필요할 때 받는 큰 증거 묶음: 전체 장기 검사·대형 JSON·전체 캡처·인쇄 PDF·과거 비교 자료.

개별 파일 크기와 포함·제외 범위를 밝혀 모바일 다운로드 문제를 줄여라. 작은 묶음에서 빠진 자료를 확인했다고 쓰지 않는다.

마지막에는 “데이터 완성” 대신 이번 차수의 실제 개선, 남은 반복과 검토 대기, 다음 우선 작업을 보고하라. 앱의 공개 배포는 하지 마라.
