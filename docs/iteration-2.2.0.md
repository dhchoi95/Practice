분야별 우선순위는 학업의 이해·표현·평가, 재물의 활용·분배·지급 조건, 사업의 역할·제안·평가, 연애의 원국 자리 관계·표현·합의, 건강의 일정·활동·휴식, 총운의 역할과 일정 조정을 기준으로 구분했다. 관성 중심 기본 설명을 표현·평가 복합 설명보다 먼저 두는 재물·총운 사례도 있어, 여섯 분야가 항상 다른 중심을 고르게 강제하지 않았다. 세부 원고의 질문·반대 조건·기존 의미와의 연결은 `iteration-meanings-2.2.0.json`에 있다. 합·충의 출현을 합화·격국의 성립으로 확대하지 않았다.

## 선택·조립과 지수 정책

`SIX-SECTOR-CONTEXT-2.0`은 선택·조립 개정이다. 기본50, 근거군별 ±10 이하, 합계 ±25 이하,5단위 반올림, 총운의 다른 다섯 분야 동일 가중 평균, 월·연 구간 시간 가중 집계는 유지했다. 정·편 구분 때문에 성공 확률이나 점수 분산을 임의로 높이지 않았다. 기반 표의 점수 산식 표기1.0과 선택 정책2.0을 구분한다.

- `meaningAxis`: 한 실제 구간에서 같은 의미 축의 설명을 중복 선택하지 않는다.
- `conflictGroup`: 동시에 제시하지 않을 대안 묶음. `capacity`는 강약 대안, `detailed-expansion`은 한 분야의 상세 설명 대안이다. 같은 군이 모두 논리적 반대라는 뜻은 아니다.
- `duplicateGroup`: 같은 설명 계열의 중복을 막는다. 점수의 `contribution.group` 중복 가산 방지와 별개다.
- 우선순위→충족 전제 구체성→고정ID 순으로 정하고, 제외 조건·명시적 양립 불가·같은 문단·표시 개수도 확인한다. 구체성은 우선순위를 뒤집는 절대 기준이 아니다. 선택·탈락 이유와 해당 사실값을 기록한다.
- 대표 중심 원고가 실제 적용된 구간을 고른 뒤 그 구간의 보완을 모두 표시한다. 다른 구간 중심은 ‘다른 구간에서는’이라고 구분한다. 기본에 안 실린 추가 원고의 적용 구간과 모든 지수 기여 원고를 사용자용 상세에서 확인한다.

개발 중 일지 육합·충과 십신의 음양상 성립할 수 없는5개 질문을 발견했고, 원고 전제·설명을 함께 바로잡았다. 월·연의 같은 기간 천간에 서로 다른 십신을 요구하는 조건도 수정했다. 수정 전후 원문은 `iteration-feasibility-corrections.json`, `iteration-unit-corrections.json`에 보존했다. 현재216개 새 기간 레코드는 모두 실제 선택으로 확인했다. 필요조건 검사 통과만으로 도달성을 입증했다고 하지 않는다.

## 한국어 편집 전후

korean-skills의 실제 humanizer→grammar-checker→style-guide 및 번역투·문장 구조·어휘·어조 참조 문서를 읽었다. 캐시 출처·라이선스는 증거 ZIP의 skill-reference에 보존했다. 번역투와 추상 표현을 줄이고 문맥별 조사·해요체·용어를 확인한 뒤 합성 입력3명의 일·월·연 전체 본문9개를 읽었다. AI 탐지 등급·단어 빈도·오타·어미 무작위화를 승인 기준으로 쓰지 않았다. 보조 용언의 붙여쓰기 허용도 문맥에 따라 유지했다.

실제 기존 학업 일운 중심 원고의 공통 두 번째 문단은 “하루 학습에서는 새로 볼 범위를 크게 늘리기보다 지금 확인할 문제나 개념 하나를 정해보세요. 정해둔 시간 안에 직접 설명하거나 풀어본 뒤 막힌 부분을 남기면 다음 복습으로 이어가기 쉬워요.”였다. 학업·하루의12개 상황에 같은 문단을 붙이던 구조를 없애고, `learn-express`에서는 “오늘 본 개념을 질문 하나에 답하는 방식으로 다시 써볼 수 있어요.”처럼 해당 조건의 행동으로 좁혔다. 원문 전후 전체는 `iteration-korean-edits-2.2.0.json`에 있다. 

기존 사업 `month-clash`는 본문에 변경·요청·소요시간 확인을 이미 설명하고 마지막에 “일정이 바뀌면 영향을 받는 작업과 알릴 사람을 함께 적어보세요.”라는 같은 제안을 다시 붙였다. 이번에는 상황에 맞춘 “오늘 일정 변경이 있다면 영향받는 작업과 알릴 사람을 함께 적을 수 있어요.”를 두고 반복되는 마지막 제안을 제거했다. 기존216개 중심의 전후와 제거한 마지막 제안은 각각 별도 기록했다. 공통 기간 도움말3개는 개인 본문과 분리했다.

새 재물 질문은 예를 들어 ‘겁재와 월지 재성이 함께 있을 때 함께 쓸 비용의 개인별 한도를 어떻게 정할까’처럼 질문·계산 근거·생활 제안·단정하지 않을 범위를 함께 적었다. 단순히 재물운이라는 이름만 바꾸지 않았다. 기존 중심과 새 보완에서 분담·한도·확인 조언이 겹치는 사례와 ‘할 수 있어요’ 어미가 이어지는 부분은 독립 편집 대상에 남겼다.

## 비교 결과와 남은 문제

날짜·제목·간지를 제외한 실제 기본 표시 본문을 비교했다. 일주 확인 입력은 각 집단11명이다. 일간 미확정 안내 반복은 다양성 부족에 합산하지 않았다.

|지표|고정 집단 전→후|추가 집단 전→후|
|---|---|---|
|분야별365일 고유 본문 범위|15–36 → 36–65|15–34 → 27–70|
|10일 뒤 완전 동일 본문|4,031 → 4,562 / 23,430|3,749 → 4,464 / 23,430|
|서로 다른 의미에서 공유된 정확히 같은 문단 비율|24,090/95,116 → 0/87,807|24,090/95,259 → 0/89,225|

공유 비율은 `semanticId`가 다른 원고에 정확히 같은 문자열 문단이 들어 있는 경우의 표시 횟수다. 같은 원고의 재사용, 같은 의미의 기간 변형, 의미가 비슷한 다른 문장은 제거됐다는 뜻이 아니다. 모든 날에 서로 다른 풀이를 만들 목표도 아니다.

같은 일간·다른 원국의 같은 날짜 비교는 두 집단 합계39,420쌍에서 완전 동일 본문12,265→9,048건이었다. 쌍별 결과·다른 원국 사실·같이 선택된 원고를 기록했다. 차이가 없는 날은 같은 조건으로 들어간 경우이며, 동일한 원국이거나 명리상 동등하다고 단정하지 않았다.

**고유 본문은 늘었으나 10일 반복은 전체적으로 증가했다.** 학업은 두 집단 모두 감소했지만 재물·총운의 증가가 크다. 첫 개발안은 새 질문을 전부 중심으로 두어 반복이 훨씬 늘었으므로, 고정 원국 배경은 보완으로 옮긴 개선 과정도 증거에 남겼다. 그 조정만으로 반복 문제가 해결되지는 않았다. 다음 차수는 재물·총운의 중심 점유와 고정 보완이 다른 날짜 조건을 가리는지 먼저 검토한다. 난수·요일·날짜 해시·동의어로 가리지 않는다.

기본 표시 밖에 남은 선택 원고는 구간 상세에서 읽을 수 있다. 분야·기간별 점유·연속 반복·10일 반복·미표시 횟수·같은 점수 다른 의미는 comparison.json 및 before/after summary.json에 있다. 미선정·후순위 조건은 collisions-and-dominance.json에 있다. 일정 원고36개의 도달성은 별도 기존 foundation 검사에서 확인한다. 비교 스크립트의 일정 미선정 표시는 분야 통계 범위 밖이므로 분야30개 미선정과 합산하지 않는다.

## 검토와 재현

작은 검토 ZIP은 실제 소스·데이터·수정 이력·핵심 로그·집단 요약·대표 전체 본문을 포함한다. 큰 ZIP은 전체 before/after 장기 출력·큰 JSON·실제 캡처·24개 PDF·과거2.1.0 소스 비교본을 포함한다. 저장소의 reports는 git에서 제외되므로 ZIP의 증거 경로를 보관한다.

`npm run verify`, `npm run build`, `npm run test:e2e`가 기본 검사다. 장기 비교 재현은 `node --import tsx scripts/audit-iteration.ts`, `node --import tsx scripts/witness-iteration.ts`, `node --import tsx scripts/report-iteration.ts`, `python3 scripts/compare-iteration-collisions.py` 순서다. report 단계에는 보존된 before/summary.json이 필요하다. `--before`는 반드시2.1.0 체크아웃에서만 실행하며 현재 코드로 기준을 덮어쓰지 않는다. 별도 witness 탐색은 비교 집단을 바꾸지 않는다.

구현 범위는 `content-backlog.json`에 닫고, 반복 개선과 한국어·명리·출처 독립 검토는 열어 두었다. 원격 push·공개 배포·외부 메시지 전송은 하지 않았다.
