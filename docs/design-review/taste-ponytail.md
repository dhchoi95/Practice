# Taste 시안과 Ponytail 코드 정리

## 실제 적용한 지침

- [Taste Skill](https://github.com/Leonxlnx/taste-skill), commit `12af471f627f866411b4bd785b19646d3672784c`. 프로젝트 로컬 `.agents/skills/design-taste-frontend/`에 MIT 라이선스와 출처를 보관했습니다.
- [Ponytail](https://github.com/DietrichGebert/ponytail), commit `96608e078b2d5ea607c5c3b8b5a54d1c1fba6846`. 프로젝트 로컬 `.agents/skills/ponytail/`와 루트 `AGENTS.md`에 적용했습니다. 일반 코드 변경에는 Ponytail의 기본 full 원칙을 따릅니다.

이는 프로젝트 지침 형태의 설치입니다. 공식 전역 플러그인·수명주기 후크·토큰 계기판 설치라고 보고하지 않습니다. 앱 실행 의존성과 package.json/package-lock.json은 이번 작업에서 바꾸지 않았습니다. 벤치마크의 비용 절감률을 이 프로젝트의 실측값처럼 쓰지 않습니다.

## 포니테일 적용과 리팩터링

Header의 상단 메뉴에서 두 번 순회하던 처리를 한 번으로 합치고, 같은 카테고리 조회와 활성 여부 판단의 중복을 줄였습니다. Home은 기존 getCategory 도우미를 재사용하고 의미 없는 quick 별칭을 제거했습니다. 두 파일의 한 줄 JSX도 읽을 수 있게 정리했습니다. 줄 수는 포매팅 때문에 늘었으며 ‘코드 몇 % 감소’라고 주장하지 않습니다. 새 추상화·UI 라이브러리를 추가하지 않았습니다.

읽은 경로는 Home/Header → site 설정의 메뉴 배열/getCategory → 기존 메뉴·접근성 검사입니다. native dialog의 포커스 처리·ESC·닫기·aria 속성, 기존 오류 처리, 목적지 URL을 유지했습니다. 계산·선정·원고·점수·개인정보·AI 서버는 수정 범위가 아닙니다. 소수 방문자의 무료 운세 진입 화면을 기준으로 검토했으며 대규모 백엔드 부하 개선이라고 설명하지 않습니다.

이번 작업 시작 시 이미 있던 AI·출시 변경은 보존했습니다. reports/design-review/baseline에 시작 사본, refactor-only.patch에 이번 Home/Header 변경만 남겼습니다. 현재 로컬 소스에 반영했으며 원격 push나 서버 배포는 하지 않았습니다.

## 디자인 시안

방향은 Taste의 `product-performs`, seed `20261031`입니다. consumer-app, quiet, 기존 글꼴 유지로 세 방향을 받은 뒤 실제 메뉴와 오늘 운세의 동작을 그대로 보여줄 수 있는 방향을 골랐습니다. 색은 Bone/green/chocolate 계열입니다. 새 인물 사진이나 임의의 운세 결과·통계·후기는 넣지 않았습니다. 기존 SVG 그림과 브랜드 인장은 프로젝트 자료를 그대로 사용했습니다.

- 모바일 상단 메뉴 6개를 두 줄로 표시해 마지막 메뉴까지 바로 찾게 했습니다. 상단 높이가 늘어나는 대신 가로로 밀어야만 보이던 메뉴가 사라집니다.
- 빠른 메뉴4×2, 운세 카드3×3의 내용·주소는 유지했습니다.
- 오늘의 운세를 초록색으로 강조하고 제목·설명·카드의 글자와 간격을 정리했습니다.
- 과한 장식이나 새 기능을 추가하지 않고 기존 콘텐츠의 우선순위를 조정했습니다. hover는 움직임 감소 설정을 존중합니다.

시안 CSS는 `design-proposals/taste-home.css`입니다. 앱은 이 파일을 import하지 않으며 원본 globals.css의 해시도 작업 시작과 같습니다. 실제 화면은 원래 디자인을 유지합니다. 사용자가 시안을 거절하면 앱 디자인을 되돌리는 조작은 필요 없고 포니테일 적용과 코드 정리는 남습니다. 사용자가 승인하면 시안을 앱 스타일에 적용하고 결과·입력·인쇄 화면까지 맞춰 재검증합니다. 별도 새 승인을 반복 요청하는 절차는 만들지 않습니다.

## 실행한 확인

- 단위·통합421개, 기본 브라우저99개, 타입 검사와 정적 빌드 통과.
- lint 오류0개. 기존 AI 컴포넌트의 location.assign 경고1개는 이번 수정 범위 밖이며 남아 있습니다.
- 현재 원고/UI 해시 검사와 content:copy-review 통과. FAQ8개 질문/답의 문자열을 시작 사본과 대조해 같음을 확인했습니다.
- 1440/768/390/320px에서 현재 화면과 시안의 메뉴6·8·9개, 본문 내용·링크 목적지가 같고 가로 넘침이 없음을 assert로 확인했습니다.
- 시안에서 상단6개 메뉴가 실제 화면 안에 있고44px 이상 높이를 가지는지, 메뉴 키보드/ESC, 실제 출생정보 입력→원국·여섯 분야 결과를 확인했습니다.

시안 검사 도중 결과 화면에도 입력 메뉴의 활성 표시가 있어야 한다고 잘못 기대한 테스트를 바로잡았습니다. 기존 구현은 입력 화면에서만 해당 메뉴를 활성화하므로 그 행동을 보존했고, 원래 동작을 바꾸어 테스트를 맞추지 않았습니다.

## 눈으로 본 결과와 남은 범위

모바일: 모든 상단 메뉴가 보이고 오늘의 운세가 더 뚜렷합니다. 기본 메뉴 수는 유지되며 글자 대비와 구분이 좋아졌습니다. PC/태블릿: 오른쪽 오늘 운세와 주 메뉴가 한 화면에서 구분됩니다. 화면의 이름·운세 대상·실제 행동을 읽는 데 필요한 문구를 삭제하지 않았습니다.

Taste의 자동 미관 검사는 비교 참고로 실행했습니다. 기존 격자·그림·보조 라벨·구분선과 정적 화면에 관한 FAIL/WARN이 남아 있어 **Taste 전체 규칙 통과나 완성된 상용 리디자인이라고 주장하지 않습니다**. 이번 요청은 승인 전 대략적인 방향 비교이므로 사진·영상·대규모 스크롤 연출을 임의로 추가하지 않았습니다. raw 결과는 reports/design-review/taste-final.log 및 taste-final/report.json입니다. 실제 인스타그램 인앱·공개 호스팅·승인 후 전체 화면의 최종 디자인은 이번 단계에서 검증하지 않았습니다.

비교 이미지는 reports/design-review/comparison-mobile.png, PC 시안은 after/home-1440-fold.png, 전체 전후 캡처는 before/와 after/에 있습니다. 로컬 내부 미리보기 서버는 검사용이며 공개 테스트 주소가 아닙니다.
