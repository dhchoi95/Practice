# 만세력 재검토 결과와 Codex 최종 작업 지시

검토일: 2026-10-24

대상: https://spring-voice-4bdc.eogjs9595.workers.dev/

## 먼저 읽을 검토 결론

첨부된 비교분석의 큰 방향은 타당하다. 이번에 다시 실행한 범위에서도 홈페이지의 년·월·일주 계산 오류는 재현되지 않았다. 사진의 시주와 다른 부분은 같은 출생정보라도 선택한 시각 기준이 다를 때 재현됐다. 사진이나 도구 없이 생성한 GPT 답변을 무조건 정답으로 삼아 계산을 바꾸면 안 된다.

다만 첨부된 분석을 그대로 ‘검증 완료’로 받아들이면 안 되는 부분이 있다.

1. **이번에 직접 볼 수 있는 사진은 네 사람의 8개 PNG다.** `만세력1~4-top/chart.png`이며, 각 top/chart는 같은 사람의 연속된 정보다. 기존 보고서에서 말하는 별도 사진 5~9, ‘태어난 시간 모름’ 문구가 있는 사진, 최대현 사진 9는 현재 첨부 목록에 없다. 최대현의 날짜는 첨부 JSON과 문서에서 확인하고 재계산했으나 그 사진 자체는 이번에 재확인하지 못했다.
2. **00:00과 시간 모름은 다르다.** 이번 사진의 최하늘·민가윤·이병관은 화면에 00:00이 적혀 있다. 실제 자정 출생 입력이라면 사진의 무자 시주는 조건에 맞는다. 이 사진만으로 ‘사진 앱이 미상 시간을 잘못 처리했다’고 단정하지 않는다. 실제 생시를 모른다는 별도 정보가 있을 때 미확정으로 처리해야 한다.
3. **JSON의 14:30은 태양시 계산의 증거가 아니다.** 원래 파일에도 미시를 재현하기 위한 예시라고 적혀 있다. 다만 이번에는 홈페이지의 실제 보정 표시를 직접 확인했다. 아래의 14:27·14:30·14:47은 그 별도 UI 확인 결과다.
4. **두 프로그램이 일치해도 완전히 독립적인 검증은 아니다.** 첨부 계산은 lunar-javascript 1.7.7, 현재 재계산은 같은 원저자 계열인 lunar-typescript 1.8.6을 사용했다. 한국 음력 변환은 korean-lunar-calendar 0.4.0으로 재계산했다. 별도로 공식 달력의 그레고리력 열과 정수 JDN·시주 산식을 대조했다. 공식 달력이 사주 해석 전체를 공인하는 것은 아니다.
5. **새 요약 카드 3개를 필수로 추가할 근거는 이번 사진에서 확인되지 않았다.** 사진에서 확인되는 정보 순서는 프로필·출생정보 다음 원국표다. ‘일간 오행·일주 상징·월지 십신’ 카드를 새로 필수화하지 않고 사용자가 요청한 배치에 집중한다. 외부 앱의 ‘타고난 성향’ 산식도 사진 몇 장으로 확정하지 않는다.

### 직접 비교한 결과

간지 순서는 아래 표에서 **년 / 월 / 일 / 시**다. 실제 원국 화면의 열 순서는 **시 / 일 / 월 / 년**이다.

| 사례 | 현재 사진에서 읽은 원국 | 홈페이지·별도 재계산 | 판단 |
|---|---|---|---|
| 최하늘, 1994-03-31 00:00 | 甲戌 / 丁卯 / 丙辰 / 戊子 | 표준시 00:00 입력과 일치. 시간 모름 입력에서는 앞의 세 주만 확정 | 사진의 00:00이 실제 입력이라면 불일치 없음 |
| 민가윤, 1996-01-05 00:00 | 乙亥 / 戊子 / 辛丑 / 戊子 | 표준시 00:00 입력과 일치. 시간 모름 입력에서는 시주 미확정 | 양력 연도만 보고 병자년으로 바꾸면 안 됨 |
| 박선영, 1998-08-11 15:00 | 戊寅 / 庚申 / 庚寅 / 癸未 | 표준시: 甲申 시주. 서울 지방평균태양시: 癸未 시주 | 시간 기준 차이로 재현됨. 사진 앱의 보정 설정은 미확인 |
| 이병관, 1995-10-22 00:00 | 乙亥 / 丙戌 / 丙戌 / 戊子 | 표준시 00:00 입력과 일치. 시간 모름 입력에서는 시주 미확정 | 음력 변환은 1995년 윤8월 28일 |
| 최대현, 문서·JSON의 1995-11-08 15:03 | 기존 보고서는 乙亥 / 丁亥 / 癸卯 / 己未라고 기록. 해당 사진은 이번에 미제공 | 표준시: 庚申. 서울 지방평균태양시·진태양시: 己未 | 홈페이지와 재계산은 조건별 일치. 사진 원본 일치 여부는 이번 검증 범위 밖 |

홈페이지에서 직접 확인한 시각 표시:

| 입력 | 적용 설정 | 홈페이지의 최종 시각 표시 | 시주 |
|---|---|---|---|
| 1998-08-11 15:00 | 서울 지방평균태양시 | 14:27, 경도 보정 -32.1분, 균시차 미적용 | 癸未 |
| 1995-11-08 15:03 | 서울 지방평균태양시 | 14:30, 경도 보정 -32.1분, 균시차 미적용 | 己未 |
| 1995-11-08 15:03 | 서울 진태양시 | 14:47, 경도 보정 -32.1분, 균시차 약 +16.1분 | 己未 |

표시는 사이트의 분 단위 표시를 기록한 것이다. 실제 보정 계산의 초 단위 정밀도나 사진 앱의 채택 기준을 인증한 값이 아니다. 서울은 재현 조건이며 실제 출생지라고 저장하면 안 된다. 지방평균태양시와 진태양시가 같은 시주를 내더라도 같은 보정법인 것은 아니다.

한국천문연구원 음양력변환 화면에서 이번에 다시 조회한 **그레고리력 열**:

| 양력 | 한국 음력 | 일진 | JDN |
|---|---|---|---:|
| 1994-03-31 | 1994-02-20 평달 | 丙辰 | 2449443 |
| 1996-01-05 | 1995-11-15 평달 | 辛丑 | 2450088 |
| 1998-08-11 | 1998-06-20 평달 | 庚寅 | 2451037 |
| 1995-10-22 | 1995-08-28 윤달 | 丙戌 | 2450013 |
| 1995-11-08 | 1995-09-16 평달 | 癸卯 | 2450030 |

공식 화면에는 율리우스력 열도 함께 나온다. 같은 숫자의 날짜라도 다른 역법의 결과를 섞지 않는다. 공식 화면의 ‘음력간지 월’은 사주 절기 월주와 같다는 보장이 없다. 예를 들어 1998-08-11의 공식 음력간지 월은 기미이나 사주 절기 월주는 경신이다.

직접 실행한 것: 라이브 홈페이지 11개 입력·보정 조건의 원국 조회, 공식 달력 5개 날짜 조회, 별도 라이브러리 재계산, 정수 JDN 일진·일간에서 시주 산출·12운성 대응 재계산. 결과 첫 화면은 데스크톱 브라우저에서 시각 확인했다.

이번에 하지 않은 것: 최신 홈페이지 소스 감사, 전 지원 연도의 절입·역법 경계 검사, 외부 앱 설정 확인, 원본 사진 5~9 재확인, 모바일 실기기 검증, 모든 신살·공망·강약·용신·대운 개시일의 독립 검증, 성격·미래 해석의 적중률 검증. 이번 작업은 검토와 지시문 작성이며 사이트 코드 수정·배포·push는 하지 않았다.

# 아래부터 Codex 작업 지시

현재 프로젝트의 사주·운세 사이트를 아래 요구에 맞게 수정해 줘. 홈페이지는 https://spring-voice-4bdc.eogjs9595.workers.dev/ 이다. 앞의 검토 결과는 제한된 외부 검증 자료이며 소스 전체가 정상이라는 보증이 아니다. 실제 현재 소스와 기존 검증을 먼저 확인해 구현해 줘.

이번에 승인된 변경은 홈 메뉴의 구성·순서·연결, 결과 화면의 정보 배치, 제목에 맞는 기능 보완이다. 디자인은 현재 것을 유지한다. 외부 앱의 디자인을 복제하거나 사이트를 전면 재설계하지 마. 공개 배포·push·운영 환경 변경 없이 검토 가능한 로컬 결과를 만들어 줘.

## 1. 기존 작업을 보존하고 범위를 확인

AGENTS.md와 현재 변경 사항부터 확인해 줘. 내가 하던 작업을 되돌리거나 첨부 예시로 최신 소스를 통째로 덮어쓰지 마. 기존 Git 이력을 참고하되 무관한 파일까지 복원하지 마.

계산 엔진, 출생정보 모델, 조회 기간 모델, 카테고리 정의, 홈의 세 메뉴 영역, 공통 원국표, 연운·월운·일운의 결과 조합을 찾아 줘. 함수·파일 이름은 현재 소스에서 확인하고 결정해 줘. 첨부 문서의 과거 Mac 로컬 경로를 접근 가능한 경로라고 가정하지 마.

홈 메뉴의 재배치는 이번에 명시적으로 요청한 변경이다. 이전의 ‘메인을 바꾸지 말라’는 지시는 이번에 지정한 항목·순서 변경을 막지 않는다. 그 밖의 배경·폰트·색상·카드 스타일·아이콘 분위기·로고·헤더 구조를 임의로 바꾸는 근거도 되지 않는다.

## 2. 홈의 세 영역을 정확히 재배치

현재의 상단 분류 4개가 있는 영역을 5개로 바꿔 줘. 다른 위치에 새 대형 배너를 추가하는 뜻이 아니다.

**신년 운세 / 오늘의 운세 / 이번달 운세 / 지정일 운세 / 올해 운세**

바로 아래 기존 4열×2행 메뉴:

| 신년 운세 | 오늘의 운세 | 이번달 운세 | 지정일 운세 |
|---|---|---|---|
| MBTI 운세 | 만세력 | 연애사주 | 짝궁합 |

그 아래 기존 3열×3행 카드:

| 신년운세 | 오늘의 운세 | 지정일 운세 |
|---|---|---|
| 별자리운세 | 띠별운세 | MBTI 운세 |
| 대인관계 | 연애사주 | 짝궁합 |

요구한 순서와 항목 수를 지켜 줘. 영역별 표기는 위 목록을 따른다. 같은 메뉴는 같은 서비스 키·입력·결과 로직을 공유한다. 반복 노출을 이유로 세 개의 별도 계산 기능을 만들지 마.

모바일에서도 4×2와 3×3의 정보 구조를 유지하고 글씨를 지나치게 줄이지 마. 상단 5개는 접근 가능한 가로 스크롤이나 현재 스타일의 줄바꿈으로 처리해 줘. 터치 영역·키보드 초점·긴 제목·320~430px 폭을 확인해 줘.

혈액형운세·혈액형풀이는 홈·전체 메뉴·관련 추천 등 새 사용자의 진입 경로에서 제거해 줘. 지정된 묶음에서 빠지는 기존 카드는 요청한 항목으로 교체해 줘. 기존 풀이의 데이터나 유용한 엔진을 삭제할 필요는 없다. 제거된 구 URL은 오류·무관한 운세 결과로 연결하지 말고 제공 종료 안내나 적절한 호환 정책으로 처리해 줘. 정책을 보고서에 남겨 줘.

별도로 남아 있는 추천·배너·바로가기 영역도 새 명칭과 연결이 어긋나지 않게 해 줘. 지정하지 않은 영역을 전면 재편하지 마.

## 3. ‘정통사주 → 신년운세’의 의미와 기능

사용자에게 보이는 기존 정통사주 메뉴를 신년운세로 변경해 줘. 이름만 바꾼 고정 성격풀이가 되어서는 안 된다. 기존 원국 분석은 만세력과 상세 사주 해설로 보존하고, 신년운세는 그 원국을 바탕으로 **선택한 해**를 풀이하는 화면으로 구성해 줘.

기존의 원국·십신·신강신약·격국·용신·희신·대운·세운과 직업·재물·연애 해설을 명칭 변경 때문에 삭제하지 마. 출생 원국에 관한 고정 해설과 선택 연도에 따라 바뀌는 해설을 구분해 볼 수 있도록 연결해 줘. 연간 월별 해설을 이미 지원한다면 유지하되, 미구현 월별 해석을 그럴듯한 문장만으로 채워 넣지 마.

신년운세와 올해 운세의 역할은 다음을 기본 제품안으로 적용해 줘. 이 구분과 기본 연도는 외부 사진으로 검증된 사실이 아니라, 두 메뉴가 겹치지 않게 정리한 구현 방향이다.

- **신년운세**: 기본으로 다가오는 새해를 보여 주는 연도 선택형 종합 화면. 한국시간이 2026년이면 최초 기본 연도는 2027년이다. 현재 해를 포함해 엔진이 실제 지원하는 다른 해도 선택할 수 있다. 이미 사용자가 고른 연도가 있으면 그 선택을 유지한다.
- **올해 운세**: 한국시간의 현재 연도를 바로 보는 화면. 날짜가 바뀌어도 브라우저의 현지 시간대가 기준을 바꾸지 않는다.
- 같은 출생정보·같은 연도·같은 계산 설정이라면 두 화면의 기반 해석과 점수는 일치해야 한다. 신년운세는 원국 요약과 연간 종합 내용을 충분히 보는 진입점, 올해 운세는 현재 해의 결과를 바로 보는 진입점이다.

선택 연도·양력 연도와 입춘 기준 간지 구간을 혼동하지 마. 올해라는 제목 때문에 1월 1일부터 무조건 새 간지년을 적용하지 않는다. 기존 기간 구간 계산이 있다면 공유하고 연초 입춘 전 구간을 다루는 정책을 명시해 줘.

페이지 제목·홈 카드·전체 메뉴·버튼·탐색 경로·공유 제목·메타 정보가 새 명칭에 맞아야 한다. 내부 엔진 이름과 기존 URL을 무조건 바꿀 필요는 없다. 외부에 공유된 구 URL도 끊기지 않게 해 줘.

## 4. 각 메뉴가 실제로 해야 하는 일

| 메뉴 | 입력·기간 | 결과와 분리 원칙 |
|---|---|---|
| 신년운세 | 한 사람의 출생정보 + 선택 연도 | 출생 원국 요약 + 해당 해의 총운·학업·재물·건강·연애·사업. 연간 종합·상세 원국으로 연결 |
| 오늘의 운세 | 한 사람의 출생정보 + 한국시간 오늘 | 오늘의 여섯 분야만. 지정일 선택·다른 기간의 상세 결과를 혼합하지 않음 |
| 이번달 운세 | 한 사람의 출생정보 + 현재 월 | 이달의 여섯 분야. 양력 월 표시와 절기 월주 계산을 구분. 월 안의 절입 전후를 하나의 간지로 무조건 덮지 않음 |
| 지정일 운세 | 한 사람의 출생정보 + 직접 선택한 날짜 | 선택 날짜를 크게 표시하고 그 날의 여섯 분야만. 날짜를 선택하기 전에는 오늘 결과를 대신 노출하지 않음 |
| 올해 운세 | 한 사람의 출생정보 + 한국시간 현재 연도 | 올해의 여섯 분야. 신년운세와 같은 연도를 보면 같은 계산을 공유 |
| MBTI 운세 | 사용자가 직접 고른 16유형 | 유형별 특징을 반영한 생활·관계 중심 읽을거리. 출생정보로 유형을 추정하지 않음 |
| 만세력 | 한 사람의 출생정보 + 계산 기준 | 출생 원국·십신·지장간·오행·지원하는 상세표. 신년운세 결과로 단순 대체하지 않음 |
| 연애사주 | 한 사람의 출생정보 | 타고난 연애 성향과 관계에서 살필 점. 두 사람 궁합이나 지정일 운세를 섞지 않음 |
| 짝궁합 | 서로 구분되는 두 사람의 출생정보 | 실제 두 원국을 비교. 한 사람의 연애사주를 재활용해 같은 결과를 내지 않음 |
| 별자리운세 | 별자리 직접 선택 또는 생일 기준 | 별자리 기준의 결과. 사주 원국에서 얻은 개인 예측으로 표시하지 않음 |
| 띠별운세 | 띠 직접 선택 또는 명시된 생년 경계 정책 | 같은 띠·같은 기준 날짜·같은 버전이면 같은 결과. 출생 연도의 경계 정책을 설명 |
| 대인관계 | 한 사람의 출생정보 | 대화·협력·거리 조절 등 관계 주제. 연애 결과와 제목만 다른 복사문 금지 |

가벼운 유형별 운세의 날짜 정책이 없다면 이번에는 오늘 기준으로 정하고 한 곳에서 공유해 줘. MBTI·별자리·띠는 개인 사주와 다른 분류형 콘텐츠라는 안내를 진입 화면에 짧게 제공해 줘. 같은 분류·같은 날·같은 버전에 누구나 같은 결과가 나오는 것을 숨기지 마. 새로고침할 때마다 랜덤으로 다른 문구를 주지 마.

일간·월간·연간·지정일 운세의 여섯 분야는 **총운 / 학업 / 재물 / 건강 / 연애 / 사업**으로 유지해 줘. 기존 그래프·점수가 있다면 이번 메뉴 개편을 이유로 산식이나 수치를 바꾸지 마. 생시 미상에서 사용한 정보의 범위는 결과 해설에 맞게 안내해 줘. 동일한 조건에서 점수와 서술이 서로 반대라면 원인을 대조하고 별도 보고해 줘.

선택 날짜·조회 연도는 출생정보와 다른 상태다. 조회 기간을 바꿨다는 이유로 출생 원국이 바뀌면 안 된다. 계산 설정을 바꾸면 해당 원국과 그 원국에 의존하는 결과를 함께 갱신해 줘.

지정일 운세는 면접·만남·일정 준비를 생각해 볼 수 있는 내용으로 쓰되 합격·불합격을 단정하거나 운세 점수만으로 면접을 취소하라고 권하지 마. 현실적인 준비 조언은 해당 날짜의 해석과 자연스럽게 연결하고, 같은 주의문을 분야마다 반복하지 마.

짝궁합은 A·B 입력이 뒤섞이지 않도록 해 줘. 이름은 선택이며 계산에 쓰지 않는다. 성별로 관계 역할·선호를 추정하지 마. 두 사람 중 한 사람의 시간이 미상이어도 알려진 정보로 가능한 비교와 미확정 항목을 분리해 줘. 동의 없는 연락처·사진·정밀 위치·불필요한 개인정보 입력은 추가하지 마.

## 5. 신년운세·만세력 첫 결과 화면의 정보 배치

현재의 색상·카드·폰트·오행 색 구분·헤더·배경을 유지하고, 사진의 **내용 구성과 순서**를 참고해 줘. 사진 앱의 캐릭터·로고·장식·광고·브랜드는 복제하지 마. 새 캐릭터 제작이나 대형 시각 요소 추가는 요청하지 않았다.

출생정보 입력 뒤의 첫 결과 화면은 다음 순서다.

1. 해당 페이지 제목. 신년운세라면 조회 연도와 변경 기능을 함께 표시.
2. 출생정보 요약: 선택한 이름/별명 또는 자연스러운 대체 제목, 양력 생일, 한국 음력 생일과 평달/윤달, 입력한 출생 시각 또는 시간 모름, 정보 변경 버튼.
3. 적용한 계산 기준 한 줄: 표준시/지방평균태양시/진태양시, 실제 선택 도시. 상세 보정 값은 펼쳐서 확인.
4. **접히지 않은 사주 원국표**. 왼쪽부터 시주 / 일주 / 월주 / 년주. 일주는 ‘나’ 표시.
5. 짧은 만세력 풀이 또는 펼침 해설·만세력 상세 연결.
6. 신년운세 페이지에서는 선택한 해의 여섯 분야 풀이가 이어짐. 만세력 페이지에서는 원국의 상세표가 이어짐.

원국표의 행은 천간 십신 → 천간 → 지지 → 지지 십신 → 지장간 → 12운성을 기본으로 검토해 줘. 한자와 한글 독음, 오행을 함께 읽을 수 있어야 한다. 시주 미상인 열은 자리와 제목을 유지하고 ‘시간 모름/미확정’으로 표시한다. 시주를 지워 열 개수를 바꾸거나 자정 값으로 채우지 마.

지장간·12운성은 검증한 규칙을 사용해 줘. 12운성은 계산 근거와 표를 확인해 실제 구현해 줘. 명칭 차이도 정규화해 줘. 예: 临官/건록, 冠带/관대, 墓/묘, 死/사. 토의 운성 등 채택 방식이 나뉘는 항목은 기준을 문서화해 줘. 이 표가 사주 원국을 대신 바꾸지는 않는다.

핵심 회귀 예: 경금 일간 未=관대, 申=건록. 계수 일간 未=묘, 申=사. 시주가 바뀌면 시주 십신·지장간·12운성도 함께 바뀌어야 한다.

사진에 있는 12신살·공망을 보여 주려면 대상 기준(년지/일지 등)과 채택 표를 먼저 정하고 검증해 줘. 이미 지원하면 유지하고, 검증하지 못한 항목은 현재 미지원이라고 분명히 남겨 줘. 빈칸을 임의의 값으로 채우거나 사람별 사진 값을 하드코딩하지 마. 원국표의 핵심 구현과 미지원 신살 전체 구현을 같은 완료 항목으로 섞지 마.

사진의 ‘초년/청년/장년/말년’ 표시는 원국 계산값이 아니다. 사용할 경우 전통적 구분이라는 뜻을 짧게 밝히고 정해진 사건이나 객관적 인생 구간처럼 해석하지 마. 배치를 닮게 하려고 불필요한 문구를 늘릴 필요는 없다.

이번 사진에서 확인하지 못한 요약 카드 3개를 필수로 신설하지 마. 이미 있는 유용한 요약이 있다면 중복 없이 배치할 수 있지만, 월지 본기 십신 하나를 사람의 성격 전체나 확정 격국으로 표시하지 마.

출생정보가 없는 방문자에게는 입력 화면을 보여 줘. 예시 원국을 개인 결과처럼 출력하지 마. 기존 세션에 유효한 정보가 있다면 재사용·변경이 가능하게 하되 새 영구 저장을 임의로 추가하지 마.

## 6. 계산은 정상 부분을 보존하고 확인된 문제만 수정

앞의 기대값은 검증에 쓰되 정답 사진에 맞추기 위한 계산 변경은 하지 마. 특히 다음을 지켜 줘.

- 시간 모름은 내부 값부터 미상으로 유지한다. 모름과 00:00을 다르게 계산한다.
- 출생 도시가 없으면 서울을 실제 출생지로 간주하지 않는다. 태양시를 요청했는데 도시가 없는 경우의 처리와 실제 적용 기준을 명시한다.
- 표준시에서 태양시를 적용할 때 경도 보정과 균시차를 구분한다. 한국 출생이라는 이유로 일괄 30분 차감하지 않는다.
- 보정으로 날짜가 바뀌면 일·시주가 일관되게 바뀌어야 한다. 음력 생일의 원래 입력과 보정 후 명리 일시를 구분한다.
- 역사적 표준시·서머타임을 다루는 지원 범위와 정책을 확인한다. 지원하지 않으면 지원한다고 표시하지 않는다.
- 외부 라이브러리가 UTC+8 기준 절기 시각을 돌려주는 경우 한국시간 숫자를 그대로 비교하지 않는다. 실제 동일 순간으로 바꾸어 연주·월주·대운 경계를 판정한다.
- 연주 입춘 경계와 월주 절입 경계를 구분한다. 일주 변경 0시/23시 정책을 명시하고 일관되게 사용한다.
- 한국 음력 변환과 사주 절기 월주를 별도로 다룬다. 1995년 윤8월 28일은 윤달 플래그가 필요하고 평8월 28일과 같은 입력이 아니다.
- 월령·지장간을 반영한 강약 판단과 단순 오행 글자 개수는 다른 지표다. 사진의 50·40·60·20 같은 점수에 맞추려고 가중치를 조절하지 않는다.
- 시간 미상에서 여섯 글자만 집계했다면 그 기준을 밝힌다. 완전한 여덟 글자의 비율인 것처럼 표시하지 않는다.
- 지장간의 구성·본기·표시 순서와 지지 음양·본기 천간 음양의 차이는 기준을 분리한다. 子는 지지 자체로 양이고 본기 癸는 음이므로 서로 다른 의미의 기호를 비교해 오답 판정하지 않는다.
- 생시 미상의 대운 개시 날짜와 전체 강약을 확정하지 않는다. 계산 가능한 방향과 미확정 개시일은 구분할 수 있다.

현재 코드가 이 요구를 이미 올바르게 처리하면 유지해 줘. 새로 계산 엔진을 교체하거나 의존성 버전을 올릴 이유로 삼지 마. 실제 오류가 발견되면 재현 입력·기존 출력·원인·수정 출력·검증 자료를 먼저 남겨 줘.

## 7. 읽기 쉬운 한국어와 데이터 생성

이전 작업의 VIDEO-KO-1 집필 규칙이 있다면 유지해 줘. 이번 메뉴 변경을 이유로 문체를 이전의 어색한 설명체로 되돌리지 마. 첨부 영상에서 가져온 문장을 그대로 서비스에 복사하지 말고 독립적으로 집필해 줘.

일반 운세 본문은 자연스러운 합니다체로 쓰고 ‘어떤 시기인지 → 구체적인 상황 → 짧은 조언’이 읽혀야 한다. 후보·전제·기간 천간·자원·구조 같은 내부 용어를 설명하느라 첫 문장이 무엇을 말하는지 모르게 하지 마. 계산 근거는 상세 설명과 내부 자료에 보존한다.

정통 명리 상세에서는 전문 용어를 사용할 수 있지만 용어의 뜻과 해당 원국에서 왜 그런 판단인지 설명해 줘. 알고 있는 것과 미확정인 것은 구분하되 모든 문단에 같은 주의문을 반복하지 마.

새 기능에 필요한 원고는 현재 조건과 의미를 정한 뒤 작은 묶음으로 작성해 줘. 문장 수를 채우기 위한 공통 조언·동의어 치환·조각 문장 무작위 결합은 사용하지 마. 생성한 원고를 전문가 검수 완료나 새 외부 근거로 표기하지 마. 현재 문장이 충분하면 이번 UI 개편을 이유로 원고 전체를 갈아엎지 마.

별도 유료 API나 서비스 실행 중 LLM 호출은 추가하지 마. AI는 개발·집필을 돕고, 서비스에서는 검토한 규칙과 데이터로 결과를 재현한다.

## 8. 검증은 조건과 기능을 함께 확인

프로젝트의 기존 필수 검사를 실행하고 변경에 필요한 회귀 사례를 추가해 줘. 계산이나 상태가 달라지는 핵심 검증을 우선하고 단순 마크업 복제 테스트로 분량만 늘리지 마.

### 원국 계산

1. 앞의 다섯 날짜를 표준시로 검증한다. 세 사람의 00:00과 시간 미상을 각각 분리한다. 최대현의 사진은 현재 없지만 문서상의 입력·기대값으로 조건 검증할 수 있다.
2. 박선영·최대현을 서울 지방평균태양시로 조회했을 때 시주가 각각 癸未·己未가 되는지 확인한다. 최대현 서울 진태양시도 己未이며 지방평균태양시와 최종 시각이 다름을 확인한다.
3. 실제 도시 좌표·초 단위 값·표시 반올림을 먼저 확인한다. 사진과 다른 분 표시를 맞추기 위해 내부 시각을 분 단위로 버리지 마. 경계 판정은 계산 정밀도를 유지한다.
4. 한국 음력 변환 다섯 건과 1995-10-22 ↔ 1995년 윤8월 28일 왕복을 검증한다.
5. 소스의 절입 순간을 기준으로 직전·직후를 검증한다. UTC+8 원자료와 KST 간 한 시간 차이가 문제를 드러내는 입력을 포함한다. 경계 시간은 임의로 꾸며내지 않는다.
6. 15시 경계, 보정으로 전날로 이동하는 자정 부근, 정책상 일주 변경 경계를 확인한다. 연주·월주와 일주·시주에 적용하는 시간 기준이 뒤섞이지 않아야 한다.

### 화면과 상태

1. 홈 상단 5개, 다음 8개, 다음 9개가 지정한 순서로 보이고 각각 올바른 기능에 연결되는지 확인한다.
2. 신년운세의 기본 다음 해와 연도 변경, 올해의 현재 해 고정, 오늘의 날짜 고정, 지정일의 실제 선택 날짜를 확인한다.
3. 같은 연도를 본 신년운세와 올해 운세가 같은 기반 결과를 내는지 확인한다. 연도 변경 전후에 원국 자체가 유지되는지도 확인한다.
4. 만세력의 독립 진입, 입력 요약·원국 4열·미상 표시·상세 펼침·12운성을 확인한다. 접힌 토글을 열어야만 원국을 볼 수 있는 상태로 되돌리지 마.
5. MBTI 유형·별자리·띠를 바꾸면 맞는 데이터가 선택되는지 확인한다. 같은 날 반복 조회가 재현되는지도 확인한다.
6. 짝궁합에서 A만 바꾸기, B만 바꾸기, 한 사람 시간 미상, 두 사람 이름만 변경하기를 확인한다. 실제 해석과 관계없는 이름 변경으로 계산이 바뀌면 안 된다.
7. 시각 설정을 바꿨을 때 원국·십신·지장간·12운성·관련 상세 풀이가 함께 갱신되는지 확인한다. 이전 결과의 캐시가 남지 않아야 한다.
8. 모바일 폭에서 상단 5개·4×2·3×3·원국 4열이 읽히는지 직접 화면으로 확인한다. 표 행 제목·한글 독음·터치 영역·가로 잘림·고정 버튼을 확인한다.
9. 기존 개인정보 안내와 실제 동작이 일치하는지 확인한다. 출생정보·두 사람 궁합 입력이 URL·공유 링크·분석 이벤트로 새로 노출되면 안 된다. 새로고침·입력 삭제 정책도 유지한다.

브라우저 실행이 안 되면 실제 원인과 미실행 범위를 분리해 보고해 줘. 단위 테스트나 build 성공을 모바일 시각 검증 완료로 쓰지 마. Lighthouse 점수와 본문 개수도 계산·문장 품질·기능 완성의 증거로 대체하지 마.

## 9. 완료 보고와 결과물

다음을 한국어로 구분해서 알려 줘.

- 실제 발견한 계산 오류와 재현 입력. 오류가 없어서 유지한 계산.
- 요청한 세 메뉴 영역의 변경과 각 메뉴의 기능 연결.
- 신년운세·올해 운세의 역할과 기본 연도 정책.
- 출생정보 요약→원국표→해설·해당 운세로 이어지는 결과 배치.
- 구현한 기능, 기존 기능을 재사용한 부분, 검증하지 못해 남긴 부분.
- 실행한 검사와 직접 본 화면, 실행하지 못한 검사.
- 바뀐 파일과 검토 가능한 변경 내역. 사용자가 확인할 실제 화면 또는 로컬 실행 방법.

‘사진과 같으니 사주 정확도 검증 완료’라고 보고하지 마. 조건별 계산 일치와 제품 기능 구현을 따로 설명해 줘. 이 작업에서는 공개 배포·push를 하지 마.
