# 현재 집필·교정 기준 VIDEO-KO-1 / 2.3.0

2026-10-24 사용자 요청으로 전수 교정합니다. 이전192개 부분 편집의 미완료 범위를 이번 차수에 포함합니다. 이전 해요체 고정·추상명사 중심 설명·확인과 계획만 권하는 규칙을 되살리지 않습니다.

## 문장 기준

- 제목은 본문이 다루는 상황을 직접 드러냅니다. 감성적인 표어로 바꾸지 않습니다. 질문·명령형 하나로 통일하지 않습니다.
- 일반 운세는 자연스러운 합니다체로 씁니다. 어떤 시기인지 먼저 전하고, 실제로 있을 수 있는 상황을 설명한 뒤 필요한 짧은 조언으로 잇습니다. 모든 원고를 같은 문장 수와 순서에 억지로 끼워 맞추지는 않습니다.
- MBTI·띠·별자리는 분류형 읽을거리입니다. 개인에게 특정 사건이 일어난다는 도입을 만들어 붙이지 않습니다. 날짜는 정해진 편집 순환에만 사용합니다.
- 전문 해설은 용어를 쓸 수 있지만 뜻과 이 원국에서 확인한 근거를 풀어 씁니다. 내부 변수명·후보 선정 과정이 일반 운세의 첫 문장을 차지하지 않게 합니다.
- 버튼·입력·오류·공유·짧은 안내는 자연스러운 해요체를 유지할 수 있습니다. 이미 쉬운 표현을 합니다체로 바꾸기 위해 억지로 고치지 않습니다.
- 공통 주의문은 적절한 위치에 둡니다. 각 문단에 경고를 반복하거나 생활 제안만 늘려 길이를 채우지 않습니다. 시각·일간 미확정 같은 결과에 직접 영향을 주는 한계는 생략하지 않습니다.
- 실제로 알지 못하는 직장·연애·혼인·건강·재산을 단정하지 않습니다. 합격·매출·질병·이별 등의 사건을 확정하지 않습니다. 원래 없던 조건이나 길흉 판단을 문장 교정에 끼워 넣지 않습니다.

## 새 원고를 추가할 때의 순서

1. 대상 메뉴·분야·기간, 적용 조건·제외 조건·필요 입력·모를 때의 처리, 전달할 의미를 먼저 적습니다. 기존 원고의 제목만 바꾸어 새 의미로 세지 않습니다.
2. 기존 원고를 검색해 같은 상황인지 대조합니다. 새 상황에는 조건이 필요합니다. 조건 없는 동의어 치환이나 기간 단어 변경을 데이터 고도화로 보고하지 않습니다.
3. 한 번에 5~10개 이하의 작은 묶음으로 **완결된 문단**을 집필합니다. 사용할 말투를 정한 뒤 한 사람이 읽을 결과의 흐름을 생각합니다. 무작위 문장 조각 결합과 서비스 실행 중 LLM 호출은 쓰지 않습니다.
4. 자연스러움과 뜻의 보존을 따로 읽습니다. 뜻은 원고의 적용 조건·예외·전문 용어·불확실성을 기준으로 대조합니다. 실제 상태를 안다고 가정한 문장은 고칩니다.
5. 조사·맞춤법·띄어쓰기를 문맥과 함께 살핍니다. 제한된 어휘 정규식은 보조 도구일 뿐 한국어 문법이나 해석의 정답 판정기가 아닙니다. 인용 대화는 실제 말투를 유지할 수 있습니다.
6. 일·월·연을 각각 읽습니다. 월간에 분기 조언이 들어가는 등의 범위 혼선을 피합니다. 연간에는 꾸준히 이어갈 조건, 월간에는 해당 월 안의 조정, 일간에는 하루 안의 상황이 자연스러워야 합니다.
7. 실제 선택기로 조립한 여섯 분야를 읽습니다. 중심·보완 문단이 같은 말을 되풀이하는지, 조언끼리 충돌하는지 확인합니다. 그래프의 지수와 본문은 동일한 선택 레코드를 사용합니다.
8. 알려진 생시·생시 미상·일간 미확정·절입 경계의 화면과 실제 PDF를 읽습니다. 유형 선택·일정 선택·조회 연도 변경은 각 기능 범위를 지킵니다.
9. 변경 레코드의 버전·해시·원문 스냅샷·구현자 재검토 기록을 추가합니다. 이전 기록을 수정하거나 자동으로 전문가·독립 검수 완료 상태를 부여하지 않습니다. 생성한 초안을 외부 관찰 자료로 다시 인용하지 않습니다.

## 검사와 승인 범위

`npm run verify`와 `npm run build`, `npx playwright test`를 실행합니다. 콘텐츠 수정 후에는 `scripts/record-editorial-review.ts --all-current-edition`, `scripts/check-integrated.ts --record`, `scripts/check-foundation.ts --record`로 해당 원고의 구현자 기록을 갱신합니다. 이전 스냅샷과 이력을 먼저 보존해야 합니다. `scripts/record-final-editing.ts`는 이번 편집 이행을 명시하고 보호 필드를 대조하는 도구이며, 변경을 독립 승인하는 도구가 아닙니다. 다음 차수에는 기준 버전·허용 범위와 기록을 먼저 정합니다. 새 원고와 변경 문구를 실제로 읽은 뒤 `scripts/final-writing-inventory.ts --record-author-review`로 전수 교정 해시를 추가합니다. 이 명령은 구현자 재검토 기록일 뿐 독립 승인이 아닙니다. 일반 verify는 이 플래그를 쓰지 않으며, 새롭거나 바뀐 원고에 현재 기록이 없으면 실패합니다.

`node --import tsx scripts/final-writing-inventory.ts`는 런타임 원고·설명과 UI·동적 문구의 전체 목록을 출력합니다. 새 저장소나 레코드가 생기면 목록에도 추가해야 합니다. 누락·중복 ID와 현재 해시를 대조하고, 유지한 문장도 검토 범위에 포함합니다. 실험 원고4개는 교정 범위에 포함하되 운영에서 활성화하지 않습니다.

AI 탐지 점수·단어 빈도·변경률·문자열 수·원고 길이·테스트 개수를 문장 품질 합격 기준으로 쓰지 않습니다. 자연스럽게 보이려는 오타나 무작위 어미 변경도 쓰지 않습니다. 계산 검증과 미래 해석의 적중률은 별개입니다. 이 작업의 의미 검토는 구현자 검토이며 독립 명리 검토는 대기합니다.
