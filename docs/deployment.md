# 정적 배포와 운영 준비

배포·도메인 구매·외부 계정 변경은 자동으로 실행하지 않았습니다. 이 문서는 준비한 정적 파일을 운영자가 공개할 때의 절차입니다.

1. Node 24.19.0에서 `npm ci`를 실행합니다.
2. `npm run verify`를 실행합니다. 실패하면 빌드 전 원인을 확인합니다.
3. 실제 도메인을 결정했으면 빌드 환경의 `NEXT_PUBLIC_SITE_URL`에 스킴을 포함한 실제 HTTPS origin을 설정합니다. 미설정이면 canonical을 생략하고 sitemap은 빈 목록을 반환합니다. 예시 도메인을 실제 canonical처럼 발행하지 않습니다.
4. `src/config/site.ts`의 서비스명·필요 시 실제 인스타그램 링크, 공개 OG 카드의 일반 문구, 개인정보 안내의 실제 운영자·연락처·호스팅 정책을 확인합니다. 인스타그램 설정이 비어 있으면 링크가 나오지 않습니다.
5. `npm run build` → `npm start` → `npm run test:e2e` 순서로 정적 산출물과 내부 경로 직접 진입·새로고침을 검사합니다.
6. `out/` **전체**를 정적 호스팅의 문서 루트로 올립니다. Node 서버·DB·비밀키는 운영에 필요 없습니다. API 키가 요구되는 호스팅을 고를 필요는 없습니다.
7. 각 `/fortune/.../`, `/result/.../`, 안내 경로의 `index.html`을 제공하고 없는 경로는 `404.html`과 404 상태를 반환하도록 합니다. 모든 요청을 홈으로 돌리는 SPA fallback은 사용하지 않습니다.
8. HTTPS·압축(Brotli/gzip)·정적 파일 캐시를 설정합니다. `/_next/static/` 해시 파일은 장기 캐시, HTML은 갱신 확인을 권장합니다. referrer-policy, nosniff, 위치·카메라·마이크 차단 정책은 로컬 정적 서버 구현을 참고합니다.

메뉴·공유의 링크에는 생년월일과 개인 결과가 들어가지 않아야 합니다. `/result/`는 noindex와 sitemap 제외를 유지하세요. noindex가 개인정보 접근 통제 수단은 아니며 입력을 정적 HTML·URL에 넣지 않는 구조를 보존해야 합니다.

공유는 HTTPS Web Share → 클립보드 → 직접 복사 대안 순서입니다. 호스팅 접속 로그와 실제 개인정보 미전송은 별개이므로 운영자의 로그 정책을 안내에 반영하세요. 분석·광고 도구를 나중에 추가할 경우 현재 개인정보 안내를 그대로 두면 안 됩니다.

콘텐츠·정책 변경은 버전과 함께 다시 빌드해야 합니다. 오늘·연도는 브라우저에서 한국시간으로 갱신하므로 빌드 날짜로 고정되지 않습니다. 공개 후 인스타그램 iOS/Android 인앱 브라우저에서 입력·공유 취소·복사·인쇄 안내·큰 글자·회전 상태를 직접 확인하세요.
