# 과거 검토를 보존하는 방법

KR-04는 원고와 검토 도구를 별도 임시 복사본에 둔 뒤 실제 CLI로 재현했다. 본문만 고치고 정확한 새 해시를 가진 기록을 추가해도 이전 기록이 stale이어서 실패했다. 원본 프로젝트는 재현 과정에서 수정하지 않았다. 실행 로그는 baseline/KR04-actual-cli-before.log에 있다.

이제 `supersedes`로 무엇을 대체했는지 명시한다. 기존36개 기록은 날짜·이름·역할·상태·원고 해시·주장 해시를 그대로 보존한다. 1.3.0 작업 중의 교정 기록도 삭제하지 않고 후속 기록으로 연결했다. 같은 원고 버전이어도 콘텐츠 해시가 다르면 별도 대상이다.

`review-snapshots.json`은 각 해시의 실제 원고를 보존한다. 같은 rule ID의 여러 버전이 들어갈 수 있으며 해시로 구별한다. 검토 도구는 해당 원고에서 나온 주장인지와 그 주장 해시를 확인한다. 현재 원고와 직접 비교하는 대상은 대체되지 않은 마지막 기록이다. 과거 기록도 자기 원문·주장 해시가 맞아야 한다. 과거 승인이 새 원고에 이어지지는 않는다.

다음은 실패한다: 스냅샷/버전/주장 해시 불일치, 현재 묶음에서 수정해 기록이 필요한 원고의 미검토 또는 오래된 마지막 기록, 다른 원고의 주장을 잘못 참조, 없는 대체 대상, 다른 원고 대체, 순환, 두 후속 기록이 같은 대상을 대체하는 분기, 대체 날짜 역전. 각 동작을 단위·통합 검사로 확인했다.

`npm run content:record -- --all-current-edition`은 명시적으로 실행할 때만 현재 묶음의 수정 원고에 구현자 교정 기록과 스냅샷을 추가한다. 최신 해시가 같으면 아무 기록도 추가하지 않는다. 기존 원문이 보존되지 않았다면 이전 해시를 덮지 않고 먼저 스냅샷을 보존하라고 중단한다. 모든 결과를 검사한 다음 로컬 JSON을 갱신한다. 이 명령은 verify나 build가 자동 실행하지 않는다.

`npm run content:review`는 읽기 검사이며 파일 내용을 승인 상태로 바꾸지 않는다. 새 기록은 implementation-author / implemented-pending-independent-review다. 현재 독립 편집·명리 검토 완료를 부여한 기록은 없다. 전문가 검토와 문장 편집 검토를 구분하며, 어느 것도 미래 적중률 인증은 아니다. schema가 이름의 진위나 검토자의 자격을 인증하는 것도 아니다.

공통 설명5개와 근거 정의25개의 공개 문장은 public-text-edits-1.3.0.json에 별도 변경 전후 해시·버전·역할·대기 상태를 기록했다. 원고 rule 검토 기록이 이 문장들까지 독립 승인한 것처럼 표현하지 않는다. UI 문구는 콘텐츠 묶음 버전과 전체 소스 해시에 연결한다. 모두 로컬 자료이며 방문자 입력이나 식별 해시 수집 기능이 아니다.

이번 묶음은 수정한 정상179개와draft4개의 현재 교정 기록을 요구한다. 변경하지 않은31개에 새 검토를 꾸며 붙이지 않는다. 공통 설명과 정의는 별도 편집 기록으로 대조한다.
