# Codex에 전달할 지시문

기존 사주·운세 사이트의 한국어 원고를 개선해 줘. 이번 작업은 문체와 콘텐츠 편집이다. 메인 페이지를 재설계하거나 카테고리·계산·점수·개인정보 처리를 바꾸는 작업이 아니다. 기존 화면과 기능을 유지하고 작성된 멘트의 품질에 집중해 줘. 공개 배포·push는 하지 말고 검토할 수 있는 로컬 변경과 보고서를 만들어 줘.

## 1. 적용할 자료와 우선순위

이 ZIP의 README.md, 02-writing-rules.md, 06-before-after.md를 먼저 읽어 줘. 01-reference-transcripts.md는 사용자가 제공한 화면 녹화에서 추출한 참고 자료다. 서비스에 그대로 복사해 배포하지 말고 일반적인 말투·문장 전개를 참고해 독립적으로 집필해 줘. 판독 보류 부분을 사실처럼 메우지 마.

이번 기준 VIDEO-KO-1을 이전 대화의 문체·분량 규칙보다 우선한다. 이전 파일·기록을 삭제하라는 뜻은 아니다. 충돌하는 집필 규칙만 문서에서 대체하고 무엇을 철회했는지 남겨 줘.

철회·완화할 것:
- 해요체 고정. 운세 본문은 자연스러운 합니다체로 통일해 줘.
- 모든 본문에 원국·기간·조건·주의문을 빠짐없이 넣기.
- ‘운·기회·기운·성과·인연’까지 추상어라는 이유로 일괄 금지하기.
- 사건을 확정하지 않으려고 모든 문장을 확인·기록·분류·계획하라는 지시로 바꾸기.
- 문장 수와 글자 수를 맞추기 위한 반복, 조각 문장 무작위 조합.
- 원고 수나 고유 문자열 수가 많다는 이유로 고도화 완료라고 판단하기.

계속 유지할 것:
- 실제 계산과 조건, 제외 조건, 근거 추적, 동일 입력·동일 기간·동일 버전의 재현성.
- 메인 디자인 보존. 오늘·내일·이달·올해·지정일 운세와 정통사주의 내용 분리.
- 지정일 입력은 지정일 운세에서만 다루기. 오늘 운세에 날짜 선택을 섞지 않기.
- 점수와 그래프 산식은 이번 작업에서 변경하지 않기.
- 개인정보, 알 수 없는 출생 정보 처리, 런타임 LLM 미사용 원칙.

## 2. 먼저 실제 원고와 조합 방식을 파악

최신 작업 경로와 AGENTS.md를 확인하고 현재 변경 사항을 보존해 줘. 제공된 교정안의 기준은 이전 로컬 프로젝트이므로 현재 레코드와 다를 수 있다.

운세 원고가 들어 있는 파일, 정통사주 설명, 만세력 해설, 선택 엔진, 조합 후처리, UI 안내문을 찾아 원고 목록을 만들어 줘. 단순 개수 외에 어떤 원고가 실제 사용자에게 출력되는지 확인해 줘. 전문 근거가 일반 본문에 노출되거나 범용 보충문이 의미를 흐리게 하는 지점도 찾아 줘.

공개 문구를 바꿀 때 추출 자료에 없는 내용을 이미 검증된 지식처럼 넣지 마. requires에 특정 관계가 존재한다는 사실만으로 무조건 길운·흉운을 새로 정하지 마. 원래 의미가 불분명하거나 조건과 문장이 맞지 않으면 ‘의미 검토 필요’로 따로 기록하고 규칙을 추측해 바꾸지 마.

## 3. 문체 목표

독자가 첫 문장만 읽어도 어떤 하루·한 달·한 해인지 알 수 있어야 한다. 이후 구체적인 상황과 짧은 조언이 자연스럽게 이어져야 한다.

권장 흐름은 ‘기간의 핵심 판단 → 일상에서 나타날 법한 상황 → 주의점 또는 마무리 조언’이다. 항상 같은 어순이나 네 문장 틀에 맞추지는 마. 명령만 늘어놓지 말고 운세로 읽히는 서술을 먼저 해 줘.

예를 들어 ‘인성과 식상의 연결을 학습·표현의 주제로 읽었어요’가 아니라 ‘배운 내용을 직접 풀어내는 공부가 잘 맞는 날입니다’처럼 써 줘. 내부의 계산 근거는 보존하고 별도 해설에서 확인할 수 있게 유지해 줘.

영상의 일간·연간 본문을 주된 문체 참고로 사용해 줘. 별자리의 반말, 반복적인 코디 글, 상대의 외도·질병·수익·합격을 확정하는 표현은 따라 하지 마. 모범으로 삼을 문장과 그렇지 않은 문장이 한 영상 안에도 섞여 있다.

‘가능성이 있을 수 있겠습니다’처럼 유보를 겹치지 말고 한 번이면 충분하다. ‘당신·에너지·가치·균형·구조·흐름·소중한 시간’을 내용 없이 반복하지 마. 이 단어들을 기계적으로 금지하거나 모두 같은 단어로 치환하지도 마.

## 4. 분야와 기간을 구분해 집필

운세 여섯 분야는 총운·학업·재물·건강·연애·사업이다. 여섯 제목 아래 같은 계획·확인 조언을 반복하지 마.

- 총운: 우선할 일과 전반적인 진행 방향. 다른 다섯 분야의 복사 요약 금지.
- 학업: 이해·복습·기억·답안·설명·진도. 학생이나 시험 응시 상태를 전제하지 않기.
- 재물: 들어올 돈·나갈 돈·가격·정산·조건·분배. 당첨·수익률·손실 사실을 확정하지 않기.
- 건강: 휴식·일정·생활 리듬 등 생활 범위. 질병·장기·수명·진단을 만들어내지 않기.
- 연애: 관심·표현·대화·약속·거리감. 연애 상태나 상대 의도를 모르면 단정하지 않기.
- 사업: 일·준비·평가·협력·제안·진행. 재물운과 같은 돈 조언만 반복하지 않기.

일간은 보통 3~5문장의 완성된 단락부터 시작하되 필요한 곳은 길게 써도 된다. 월간·연간은 일간의 ‘오늘’을 ‘이달·올해’로 치환한 글이면 안 된다. 준비·지속·조정·장기 부담을 해당 기간에 맞게 설명해 줘. 월간·연간이라는 이유로 근거 없는 월별 사건이나 상·하반기 전환을 만들지는 마.

정통사주는 원국→신강·신약→격국·용신→십신→대운→세운의 분석 근거를 유지하되 전문 용어 뒤에 뜻과 생활 해석을 연결해 줘. 새 영상의 일간 문체만으로 정밀 분석 데이터를 완성했다고 보고하지 마. 실제 미구현 계산이나 불확실한 판단을 글로 채워 넣지 마.

## 5. 42개 교정안부터 대조

03-authored-drafts.json과 04-rewrites.jsonl에는 실제 이전 레코드에 대응한 독립 집필 초안 42개가 있다. 모두 editorial-draft이며 외부 검수 완료가 아니다. 영상 원문에서 가져온 문장으로 취급하지 마.

tools/merge_rewrites.py를 기본 dry-run으로 실행해 줘. 원본 해시가 다르면 실패한 레코드를 최신 원고와 대조해 새 교정안을 만들어 줘. 해시 검사를 없애거나 구버전 전체 파일로 덮어쓰지 마. 이 도구는 문장 필드 이외를 변경하지 못하게 만든 보조 도구이지 프로젝트의 전체 갱신 절차가 아니다.

42개도 무조건 적용하지 말고 다음을 읽고 확인해 줘:
- 실제 적용 조건과 원래 핵심 의미가 유지되는가.
- 기존 길흉 판단·점수 기여도와 충돌하는 새로운 평가를 만들지 않았는가.
- 사업·연애 등 관련 분야에서 구체적인 내용으로 읽히는가.
- 해당 원고와 함께 선택되는 보충문, 동일 semanticId의 다른 기간·변형 원고와 모순이 없는가.

의미 차이가 있으면 문장 교정과 해석 규칙 변경을 분리해 보고해 줘. 이번 작업에서 조용히 규칙까지 바꾸지 마.

## 6. 나머지는 작은 묶음으로 직접 생성

별도 유료 API나 파인튜닝을 전제로 멈추지 마. Codex가 현재 세션에서 파일을 읽고 직접 초안을 쓸 수 있다.

1. tools/export_briefs.py로 원고를 분야·기간별 12개 안팎의 묶음으로 내보낸다.
2. 각 레코드의 유지할 의미를 한국어 한 문장으로 정한다. 내부 자료에 두고 독자 본문에는 복사하지 않는다.
3. 같은 의미의 새 초안을 두 개 쓴다. 단순 어미·동의어 교체는 초안 두 개로 세지 않는다.
4. 더 읽기 쉬운 초안을 골라 문단 전체를 편집한다. 자동 무작위 문장 결합은 사용하지 않는다.
5. 원고 ID·원본 해시·교정 전후·유지한 의미·확인하지 못한 사항을 남긴다.
6. 해당 분야의 가까운 원고와 중복·상충하는지 비교한다.

실제 프로젝트의 검증 절차에 따라 콘텐츠 버전과 리뷰 해시·생성 인덱스를 갱신하되 검수하지 않은 글에 expert-reviewed·independent-reviewed 같은 상태를 붙이지 마. 기존 검수 완료 상태도 문장이 바뀌었다면 그대로 신뢰하지 말고 프로젝트 정책에 따라 재검토 대기 상태로 돌려 줘. 과거 원고와 변경 이력은 남겨 줘.

## 7. 데이터 확장은 표현보다 상황을 늘리기

현재 숫자만으로 충분하다고 판단하지 마. 540개 레코드와 180개 semanticId가 서로 다른 540가지·180가지 사건을 의미하지는 않는다. 같은 상황의 기간별 버전, 부가 문단, 변형을 나누어 세어 줘.

분야별로 실제 선정 조건이 뒷받침하는 상황이 어디에 몰려 있는지 살펴봐 줘. 협력·자기표현·경쟁·지출·준비·일정 변화처럼 다른 이야기를 할 수 있는 근거가 있는지 정리해 줘. 부족한 상황에 대해서만 새 의미 레코드의 조건·제외 조건·충돌 규칙을 제안하고 별도 검토 대상으로 남겨 줘. 문장만 다르게 써서 독립적인 해석이 늘었다고 보고하지 마.

7개 영상은 문체 예시다. 사주 계산 규칙이나 해석 근거를 추출하는 데이터베이스로 취급하지 마. 추가 생성문에는 synthetic/editorial-draft 표시와 출처 구분을 붙이고, 생성한 글을 새로운 관찰 자료나 전문가 근거로 다시 사용하지 마.

## 8. 실제 완성 결과로 검수

문장 레코드 단위 검사만 하지 말고 실제 엔진에서 같은 입력으로 여섯 분야 전체를 생성해 읽어 줘. 성별·연령·출생시 미상·현재 생활 상태를 모르는 입력, 주요 경계일, 서로 다른 선정 조건을 포함해 줘. 현재 있는 테스트를 활용하고 핵심 공백에만 의미 있는 검증을 보태 줘.

- 동일 입력·동일 기간·동일 버전 결과가 반복 실행해도 같은가.
- 원고의 길흉 표현이 점수·그래프와 뜻이 맞는가. 다른 경우 문장과 원래 의미를 우선 대조하고 점수를 임의 조정하지 마.
- 여섯 분야가 같은 조언을 반복하거나 서로 상충하지 않는가.
- 같은 의미의 핵심문과 보충문을 두 번 이어 붙이지 않는가.
- 일간·월간·연간 차이가 실제로 드러나는가.
- UI에서 문단이 끊기거나 전문 태그·내부 메모가 노출되지 않는가.
- 메인 화면과 메뉴, 각 카테고리의 범위가 이전과 같은가.

가능하면 모바일 폭에서 완성 본문을 확인해 줘. 실행하지 못한 화면 검증은 이유와 함께 따로 밝혀 줘. Lighthouse·맞춤법 검사·금칙어 검사·AI 탐지 점수만으로 글이 자연스러워졌다고 결론 내리지 마.

## 9. 완료 보고

무엇을 바꿨는지 쉽게 한국어로 설명해 줘. 바뀐 파일, 실제 교정한 원고 수, 실제 서로 다른 의미 수, 참고 원문과 추가 생성문 구분, 교정 전후 대표 예시, 직접 실행한 검사와 미실행 항목을 포함해 줘. 42개만 적용했다면 전체 완료라고 쓰지 마. 의미 자체가 부족해 남긴 항목도 따로 정리해 줘.

내가 확인할 수 있도록 완성된 여섯 분야 결과를 하루치 이상 보여 줘. 이번 작업에서 공개 배포나 push는 하지 마.
