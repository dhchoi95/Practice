# 운세 문장 개선 자료

첨부 영상 7개를 참고해 운세 글의 작성 기준을 새로 잡았습니다. 이전에 만든 문체 규칙 중 충돌하는 것은 이 자료의 VIDEO-KO-1 기준으로 대체합니다. 대화 기록이나 기존 파일을 삭제하지는 않았습니다.

## 이번에 한 작업

- 영상 7개의 250프레임을 OCR로 읽고 겹치는 화면을 대조했습니다. 광고·메뉴를 제외한 운세 본문을 정리하고 일부 잘못 읽힌 단어를 원본 화면에서 다시 확인했습니다.
- 일간 3세트의 여섯 분야, 띠·별자리, 연간 3세트의 본문을 구분했습니다. 같은 내용의 중복 화면은 새 자료로 세지 않았습니다. 코디 문단은 앱의 본문이므로 기록하되 문체 모범으로 삼지 않았습니다.
- 기존 원고와 비교해 집필 규칙을 만들고, 실제 레코드 42개에 대응하는 새 원고를 작성했습니다. 일간 30개, 월간 6개, 연간 6개입니다.
- 현재 원고를 소규모 집필 자료로 내보내는 도구와 문장 필드만 바꾸는 병합 도구를 만들었습니다. 이번에는 병합 검증만 했습니다.

**사이트의 원고·화면·계산·점수는 이번 작업에서 수정하지 않았으며 공개 배포도 하지 않았습니다.** 첨부 자료는 다음 Codex 작업에 적용할 교정안입니다.

## 가장 큰 문제와 해결 방향

기존 글은 사주 용어를 설명하거나 일의 순서와 확인할 항목을 나열하는 데 치우쳤습니다. 쉬운 말로 바꾼 글도 업무 조언처럼 읽히는 경우가 많았습니다. 참고 영상의 읽기 좋은 부분은 먼저 어떤 운세인지 밝히고, 구체적인 상황과 짧은 조언으로 이어집니다.

새 기준은 자연스러운 합니다체입니다. ‘운·기회·성과·인연’을 무조건 빼지 않고, 뜻이 드러나는 문장에서 사용합니다. 계산 근거는 별도로 보존하고 일반 본문에는 반복하지 않습니다. 한 문단을 완성해 쓴 뒤 전체 결과에서 다시 읽습니다.

## 파일 안내

| 파일 | 용도 |
|---|---|
| 01-reference-transcripts.md | 광고를 뺀 작업용 전사. 판독 보류 부분 표시. 원문 인증본은 아님 |
| 02-writing-rules.md | 채택할 문체·철회할 규칙·분야별 집필 기준 |
| 03-authored-drafts.json | 독립적으로 새로 쓴 원고 42개. 원본 영상에서 추출한 문장이 아님 |
| 04-rewrites.jsonl | 실제 기존 ID와 원본 해시를 붙인 교정안. 제목·본문·추가 조언만 변경 가능 |
| 05-codex-prompt.md | Codex에 그대로 전달할 통합 지시문 |
| 06-before-after.md | 실제 기존 원고와 교정안 비교 |
| 07-validation.json | 직접 실행한 검사 결과와 검증하지 못한 범위 |
| tools/export_briefs.py | 현재 원고를 분야·기간별 소규모 집필 묶음으로 추출 |
| tools/merge_rewrites.py | 원본 변경 여부·ID·허용 필드 검사. 기본은 파일을 바꾸지 않는 dry-run |

## 적용할 때 주의할 점

비교 기준은 직전 작업의 로컬 프로젝트 `saju-category-fix`입니다. 현재 운영 사이트나 GitHub 최신본과 동일한지는 이번에 확인하지 않았습니다. 원본 해시가 다르면 최신 내용을 읽고 교정안을 다시 맞춰야 합니다. 검사를 우회해서 덮어쓰지 마십시오.

42개는 적용 후보인 `editorial-draft`입니다. 전문가 검수 완료나 독립 검수 완료 상태가 아닙니다. 영상 원문을 서비스 원고로 그대로 배포하는 자료도 아닙니다.

## 더 나은 고도화 방법

지금 데이터에는 540개 레코드, 180개 semanticId, 30개 scenario가 있습니다. 레코드 수는 독립적인 해석 상황의 수와 같지 않습니다. 같은 상황의 일간·월간·연간 버전과 부가 문단이 함께 들어 있기 때문입니다.

1. 완성된 여섯 분야 결과를 읽고 어색한 곳을 먼저 고릅니다. 원고 하나가 괜찮아도 조합하면 같은 조언이 반복될 수 있습니다.
2. ‘말을 먼저 건네기’, ‘속도를 늦추기’, ‘함께할 기회’, ‘지출 조건 살피기’처럼 서로 다른 상황이 충분한지 점검합니다. 실제 조건이 뒷받침하는 범위에서 늘립니다.
3. 의미를 설명한 내부 자료와 독자가 읽을 본문을 분리합니다. 해석 자체가 빈약한 레코드는 문장만 늘리지 않고 별도 의미 검토 대상으로 남깁니다.
4. 한 번에 12~20개씩 초안 두 개를 쓰고 하나를 편집합니다. 새 문장을 또 새 근거처럼 취급하지 않습니다.
5. 사람 검수자는 명리 용어를 몰라도 ‘어떤 시기이며 왜 그런 조언을 하는지’ 한 번에 설명할 수 있어야 합니다.

별도 학습 모델이나 실시간 API 없이도 Codex가 이 과정을 수행할 수 있습니다. 잘 읽히는 대표 원고와 명확한 의미 자료를 제공하는 일이 우선입니다. 무작위 어미 교체, 동의어 치환, 원고 수만 늘리는 방식은 핵심 해결책이 아닙니다.

## 실행 예

아래 명령은 이 폴더에서 실행합니다. `/path/to/project`는 최신 프로젝트 경로로 바꿉니다.

```bash
python3 tools/export_briefs.py /path/to/project /tmp/saju-writing-briefs --batch-size 12
python3 tools/merge_rewrites.py /path/to/project 04-rewrites.jsonl
```

두 번째 명령은 검사만 합니다. 실제 변경은 문장과 의미를 검토한 다음 별도 작업으로 진행합니다. `--apply` 옵션은 로컬 JSON의 문장 필드만 바꾸며 공개 배포는 하지 않습니다. 프로젝트의 콘텐츠 버전·리뷰 해시·생성 인덱스 갱신까지 수행하는 완전한 마이그레이션 명령은 아닙니다.
