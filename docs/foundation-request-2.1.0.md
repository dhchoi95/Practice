이 문서는 아직 실행하지 않은 이전 「사주·운세 기반 데이터 구축 지시문」을 대체한다. 이번에는 데이터만 만들고 연결을 미루는 작업이 아니라, 현재 2.0.0 소스를 바탕으로 데이터·조립·결과 화면·홈페이지를 함께 개선한다. 공개 배포·원격 push는 작업 범위가 아니다.

# 여기부터 Codex에 전달할 본문

당신은 기존 한국어 무료 사주 사이트의 데이터·계산 연동·콘텐츠·모바일 UI를 개선하는 개발자다. 첨부한 2.0.0 소스를 읽고 아래 결과를 실제로 구현하라. 계획서나 샘플 데이터만 작성하고 끝내지 마라.

가장 중요한 결과는 다음 세 가지다.

1. 오늘·내일·지정일·이달·올해 운세는 총운·학업운·재물운·건강운·연애운·사업운 여섯 분야를 중심으로 보여준다.
2. 사주를 사용하는 결과 화면에서는 사용자의 출생 사주 원국을 맨 위에 시각적으로 명료하게 펼쳐 보여준다. 만세력 표는 접지 않는다. 만세력 설명과 계산 세부 사항은 접을 수 있다.
3. 정통사주는 입력한 출생 사주와 만세력을 바탕으로 원국·강약·격국·용신·십신·대운·세운을 충분히 해설한다. 지정일 운세는 그 원국과 선택 날짜의 관계를 계산한다.

런타임 LLM/API, 로그인, 결제, 유료 DB 없이 현재 정적·브라우저 계산 구조를 유지한다. 개발 과정에서 AI로 원고를 집필할 수 있지만, 서비스 이용 시에는 일반 코드와 검토 가능한 데이터만 사용한다.

## 1. 시작 순서와 기존 결과의 보존

- 저장소의 AGENTS.md, README, 첨부 START_HERE와 review-request, 원래 통합 요구를 읽는다.
- 2.0.0 구현 보고서의 완료 주장과 실제 확인 결과를 구분한다.
- 실제 작업 저장소와 첨부 ZIP의 차이가 있으면 비교 후 현재 사용자 작업분을 보존한다. ZIP을 무조건 덮어쓰지 않는다.
- 계산 정책, 입력 정규화, 대운·기간 경계, 개인정보 처리, 원고 ID·검토 이력을 조사한다.
- 기존 코드와 데이터를 조사하고 필요한 부분만 확장한다. 새 계산 엔진을 처음부터 별도로 만들지 않는다.
- 이전 작업에서 핵심 파일을 바이트 동일하게 유지하라는 요구가 있었다면, 이번 UI·연동 변경에 필요한 수정은 이번 지시가 허용한다. 변경 이유와 회귀 검사를 남긴다. 옛 보존 규칙을 핑계로 새 요구를 우회하거나 테스트·검토 이력을 삭제하지 않는다.
- 바로 구현에 착수하되, 시작 시 변경할 범위와 기본 화면 구성을 간단히 설명한다. 이미 정해진 여섯 분야·상단 원국·지정일 메뉴를 다시 사용자에게 선택시키지 않는다.
- 공개 배포, 외부 전송, 원격 push는 하지 않는다. 로컬 구현·로컬 미리보기·검토 자료까지 완성한다.

## 2. 메뉴와 역할을 명확히 분리한다

### 운세
오늘 / 내일 / 지정일 / 이번 달 / 올해.
이 그룹의 본문 구조는 항상 여섯 분야다.
- 총운
- 학업운
- 재물운
- 건강운
- 연애운
- 사업운

사업운은 사업자만을 대상으로 하지 않는다. 직장·취업·면접·업무·거래·자영업 등 사회활동을 포괄하되, 실제 생활 상태를 입력받지 않았으면 어느 상태라고 단정하지 않는다. 화면에는 사업운을 유지하고 짧게 “직장·일·사업”을 설명할 수 있다.

### 사주
정통사주 / 만세력 / 기존 성격·연애·직업 등 출생 사주 기반 주제.
출생 원국 자체와 그 해석이 중심이다. 정통사주를 여섯 분야 점수의 반복 설명으로 축소하지 않는다.

### 기타
띠·별자리·혈액형·MBTI 등 기존 메뉴는 유지한다. 이들을 출생 사주 기반 운세로 혼동하게 연결하지 않는다. 이번에 타로·관상·토정비결·이사택일까지 새로 구현하지 않는다. 현재 핵심 작업의 완성도를 우선한다.

## 3. 결과 화면의 기본 구조

### 운세 결과 화면
순서:
1. 간결한 결과 제목, 대상 날짜 또는 기간.
2. 항상 펼쳐진 “내 사주 원국” 네 열 표.
3. 날짜·기간 선택과 오늘/내일/지정일 또는 해당 기간 전환.
4. 여섯 분야 레이더 그래프와 읽을 수 있는 지수 요약.
5. 여섯 분야 이동 링크.
6. 총운 → 학업운 → 재물운 → 건강운 → 연애운 → 사업운 전체 본문.
7. 지정일의 일정 참고 사항이 있다면 부가 설명.
8. 기간 구간·근거·계산 방식 등 접을 수 있는 세부 내용.
9. 입력 수정·다른 풀이·공유·인쇄 등 보조 기능.

최상단의 제목·최소한의 안내 외에 긴 인사말, 대운 설명, 정책 선택 설명, 기술적인 주의문을 원국보다 앞에 여러 화면 배치하지 않는다. 원국이 페이지 중간에서 처음 나타나면 미완성이다.

각 분야는 처음부터 본문이 보이게 한다. 한 분야를 누를 때마다 다른 본문을 교체하는 구조나 여섯 본문을 모두 접어놓는 구조는 쓰지 않는다. 이동 링크는 본문 앵커 역할을 한다.

오늘·이달·올해가 공통 UI를 사용해도 제목·기간 설명·본문의 시간 범위는 각각 달라야 한다.

### 정통사주 결과 화면
1. 제목과 입력 요약.
2. 항상 펼쳐진 원국표.
3. 핵심 구조 요약.
4. 목차.
5. 원국 분석·분야 해석·대운·세운.
6. 원국 관계·용어·정책·시간 보정 비교 등의 보조 설명.

같은 출생 정보와 계산 정책을 사용하면 운세 화면과 정통사주·만세력 화면의 원국이 일치해야 한다.

## 4. 상단 만세력 표: 사진의 정보 구조를 반영한다

### 네 열 배치
왼쪽부터 시주 / 일주 / 월주 / 년주.
원본 데이터의 키 순서를 바꿀 필요는 없다. 렌더링 순서만 명시하고, 키로 연결한다. 배열 인덱스가 달라져 십신·지장간이 다른 기둥에 붙지 않게 한다.

### 기본으로 보여줄 행
- 기둥 이름.
- 천간의 십신. 일주의 천간은 “일간 · 나” 등으로 표시.
- 천간: 큰 한자, 한글 이름, 음양·오행 보조 정보.
- 지지: 큰 한자, 한글 이름, 음양·오행 보조 정보.
- 지지 본기 기준 십신. 이 기준을 짧게 표시.
- 지장간: 해당 지지의 실제 구성 글자. 채택 순서와 표기 기준을 설명에서 확인 가능하게 한다.

큰 천간·지지 8개 칸이 화면의 중심이어야 한다. 기존의 긴 설명 카드 네 개를 옆으로 나열하는 것으로 대체하지 않는다.

### 추가 행
12운성·신살·공망은 기존에 검증한 계산이 있으면 표시할 수 있다. 사진을 채우려고 없던 값을 임의 생성하지 않는다. 새로 지원하려면 채택 표·산출 규칙·독립 대조·테스트를 추가하고 이후에 표시한다. 이번 필수 완료 조건은 원국·십신·지장간이다. 추가 항목의 미지원 상태를 숨기지 않는다.

### 시각적 표현
- 오행마다 구분되는 칸 색상. 색만으로 정보를 전달하지 않고 한글·한자·오행 이름을 병기.
- 전통 오행 색채를 참고하되 모바일 대비를 확보한다. 흰색 금 칸은 경계선과 글자 대비를 유지한다.
- 일주를 알아보기 쉽게 표시하되 나머지 기둥을 흐리게 만들지 않는다.
- 320px에서도 네 기둥의 핵심 글자는 한 화면 폭 안에 읽히게 한다. 글자를 무작정 축소하거나 표 전체를 가로 스크롤에 숨기지 않는다.
- 표의 설명은 “만세력 풀이 보기”, 계산 기준은 “시간 보정·계산 기준” 같은 별도 disclosure로 둔다.
- 출생 시각 미상은 시주 자리에 “시간 모름”을 표시한다. 임의 시주를 넣지 않는다.
- 년·월·일주가 경계 때문에 미확정이면 해당 칸을 솔직하게 표시한다.
- 화면 낭독기에서 기둥과 행의 연결을 알 수 있는 의미 있는 table 구조를 우선한다.
- “초년운/중년운/말년운”을 사진처럼 장식용으로 추가할 필요는 없다. 넣는다면 해석 정책을 갖춘 별도 설명으로 다룬다.

### 중요한 일관성
상단 표는 사용자의 출생 원국이다. 지정일을 바꿔도 이 표는 바뀌지 않는다. 대상 날짜의 일진·연월일 간지는 “선택한 날짜의 간지”로 별도 표시한다. 출생 원국과 대상일 명식을 뒤섞지 않는다.

표준시·평균태양시·진태양시를 바꾸면 동일한 계산 결과 객체에서 원국·십신·지장간·후속 해석을 함께 갱신한다. 상단은 옛 표준시 표이고 본문만 진태양시인 상태를 만들지 않는다.

원국을 보려면 상세 분석 체크박스부터 켜야 하는 구조를 제거한다. 계산 정책 변경은 보조 설정이며 원국표 표시 여부를 결정하는 토글이 아니다.

## 5. 여섯 분야에서 실제로 써야 할 내용

원고는 “상징이 이런 뜻이다”라는 사전 설명에서 끝내지 않는다. 실제 계산에서 확인한 조건을 바탕으로 해당 기간에 어떤 점을 살필지 구체적으로 설명한다.

### 총운
- 기간의 핵심 방향과 가장 중요한 상반 요인.
- 기회가 되는 주제와 부담이 되는 주제.
- 일을 넓힐 때인지 정리할 때인지 등, 선택한 해석 정책의 결론과 이유.
- 다른 다섯 분야를 복사해 나열하지 않는다.
- 점수 하나를 설명하려고 근거 없는 하루의 사건을 만들어내지 않는다.

### 학업운
- 공부·자격 준비·자료 이해·복습·집중·발표·시험 준비.
- 학생이라고 가정하지 않는다. 성인의 자격 공부나 업무 학습에도 읽힐 내용.
- 인성·식상·관성 등 채택한 해석 관계를 어떻게 연결했는지 조건을 붙인다.
- 합격·불합격·점수 상승을 확정하지 않는다.
- 일운은 오늘의 공부 방식·준비, 월운은 학습 계획·중간 점검, 연운은 장기 학습·자격 계획으로 시간 범위를 달리한다.

### 재물운
- 수입을 얻는 활동, 지출·정산·분배·거래 조건·돈의 관리.
- 재성이 나타났다고 자동으로 부자가 된다는 본문을 쓰지 않는다.
- 같은 재성도 원국·강약 후보·비겁·식상 등과 연결되는 조건을 구분한다.
- 구체적 종목·수익률·당첨·우연히 지갑을 줍는 사건을 예언하지 않는다.
- 일운과 월·연운에서 실제로 참고할 계획의 크기가 달라야 한다.

### 건강운
- 휴식·활동량·생활 리듬·일정의 과밀 등 일상 관리에 한정한다.
- 개인의 실제 신체 상태를 계산했다고 표시하지 않는다.
- 특정 질병·장기 이상·사고·수명·임신 등을 사주로 추정하는 규칙을 만들지 않는다.
- 지수는 건강 상태나 발병 확률이 아니다. 이 분야의 생활 조언을 표현한 참고 지수라는 설명을 도움말에 둔다.
- 모든 사람에게 똑같은 수면·물 마시기 문구만 붙이지 않는다. 선택된 업무·활동·긴장·휴식 주제와 중복 없이 연결한다.
- 원고에 근거 없는 의학적 원리를 끼워 넣지 않는다.

### 연애운
- 만남·대화·표현·관계의 속도·기존 약속·서로 기대하는 바.
- 미혼·기혼·연애 중·솔로, 상대의 성별이나 의도를 임의로 추정하지 않는다.
- 관계 상태를 선택받지 않으면 누구나 읽을 수 있는 본문을 쓴다. 필요하면 “새로운 만남이라면 / 관계를 이어가는 중이라면”으로 분기.
- 연락·고백·결혼·이별을 확정하지 않는다.
- 연애운을 일반 대인관계 문장으로만 채우지 않는다.

### 사업운
- 일의 진행·역할·평가·면접·협상·제안·거래·업무 조율.
- 사업자에게는 거래·운영, 직장인에게는 업무·평가로 읽힐 수 있게 작성한다.
- 현재 직업을 모르면 현재 직장이나 매출이 있다고 단정하지 않는다.
- 관성·식상·재성 등이 연결되는 복합 조건을 다룬다.
- 재물운과 구별한다. 사업운은 일의 방식과 진행, 재물운은 자원과 돈의 흐름을 중심으로 쓴다.

## 6. 문단 구조와 읽는 분량

각 분야에는 다음을 자연스러운 문장으로 담는다.
1. 핵심 풀이.
2. 그 풀이가 나오는 중요한 조건.
3. 해당 기간에 참고할 구체적인 상황.
4. 도움이 될 행동과 주의할 부분.

이 네 항목을 항상 똑같은 소제목으로 찍어내라는 뜻은 아니다. 2~3개 문단 안에서 연결해도 된다.

참고 분량:
- 일운: 분야당 대략 250~450자. 여섯 분야 합계 약 1,500~2,700자.
- 월운: 분야당 대략 350~600자.
- 연운: 분야당 대략 450~750자. 월별 흐름은 별도 보조 정보로 구성 가능.
- 총운이 다른 분야보다 조금 길어도 된다.

분량은 제품 가독성의 출발점이다. 근거가 적거나 미확정인 경우 문장을 부풀리지 않는다. 반복되는 전제 설명·주의문을 글자 수에 포함해 목표를 채우지 않는다.

“좋은 일이 생길 수 있어요. 신중하게 행동하세요. 자신을 믿어보세요” 같은 문장으로 여섯 분야를 채우면 불합격이다. 전문 용어의 정의도 본문 전체를 대신할 수 없다.

## 7. 그래프와 본문을 한 판단 결과에서 만든다

### 그래프
- 총운·학업·재물·건강·연애·사업 여섯 축의 레이더 그래프.
- 축 순서를 모든 화면에서 고정한다. 권장: 위 총운 → 시계방향 재물 → 연애 → 사업 → 건강 → 학업. 본문 순서는 총운·학업·재물·건강·연애·사업으로 유지해도 된다.
- 작은 화면에서 축 이름과 도형이 잘리지 않게 viewBox·여백을 설계한다.
- 직접 만든 SVG 등 가벼운 구현을 우선한다. 단순 그래프 때문에 큰 차트 패키지를 무조건 추가하지 않는다.
- 같은 값을 텍스트 목록·표로도 확인 가능하게 한다. 도형이 유일한 정보가 되면 안 된다.
- 차트 축을 누르면 해당 본문으로 이동할 수 있게 하되 키보드와 터치 접근을 제공한다.
- 점수의 최댓값·최솟값과 기준은 날짜별로 변하지 않는다. 오늘 표본에 맞춰 자동으로 도형을 확대하지 않는다.

### 지수 정책
지수는 공개한 서비스 해석 정책을 시각화한 참고 지수다. 전통 명리학의 공인 점수·실제 사건의 확률처럼 표현하지 않는다.

구현할 정책:
1. 분야별 판단 규칙이 근거·도움 요소·부담 요소·해석 결과를 반환한다.
2. 지수와 본문은 이 동일한 판단 결과를 사용한다.
3. 분야별 최종 지수는 0~100 범위, 5 단위 정도의 거친 정밀도를 기본으로 한다. 소수점으로 거짓 정밀도를 주지 않는다.
4. 점수 구간의 이름과 의미를 문서화한다. 높은 지수는 대체로 활용할 요소가 많은 해석, 낮은 지수는 조율·준비가 더 필요한 해석으로 정의한다.
5. 총운은 기본적으로 다른 다섯 분야의 동일 가중 평균을 사용하고 동일한 반올림 규칙을 적용한다. 총운 본문은 원국·기간의 공통 주제를 별도 조합한다. 가중치를 달리할 필요가 있으면 근거와 버전을 기록한다.
6. 미확정은 0점이나 중립 점수로 몰래 바꾸지 않는다. 적용 가능한 판단이 충분한지 확인하고 부족하면 null·산출 보류로 처리한다.
7. 일부 분야가 미확정이면 총운도 “일부 항목 미반영”을 표시하거나 산출을 보류한다. 레이더 결측값을 0으로 연결해 나쁜 운처럼 보이게 하지 않는다.
8. 시각 미상이어도 확인 가능한 세 기둥·일진 관계로 판단할 수 있으면 그 범위의 원고와 지수를 사용한다. 일간 자체가 미확정인데 개인 지수를 만들지는 않는다.
9. 동일 의미의 관련 규칙이 여러 번 중복 가산되지 않게 근거군별 한도와 우선순위를 둔다.
10. 비겁은 항상 나쁨, 재성은 항상 좋음, 충은 무조건 감점, 합은 무조건 가점으로 처리하지 않는다.

서비스 가중치가 전통 공통 산식이라고 주장하지 않는다. 규칙별 점수 기여·가중치·상한·정책 버전을 trace와 문서로 검토 가능하게 한다.

그래프를 먼저 난수로 만든 후 그 값에 맞춰 본문을 고르는 것은 금지한다. 생일·날짜 해시, 요일, 방문 횟수를 운세 지수 근거로 쓰지 않는다.

그래프가 긍정적인데 본문은 전반적 부정인 경우, 반대 요인과 분야 구분을 설명하거나 판단 조립 오류를 수정한다. 의도적으로 상충하는 문장을 붙여 양쪽에 맞는 척하지 않는다.

## 8. 지정일 운세를 정식 기능으로 만든다

사용자가 “그날 면접이 있는데 어떤 점을 참고할까?”를 확인할 수 있어야 한다. 메뉴명은 “지정일 운세”, 보조 설명은 “내 사주로 선택한 날 살펴보기” 정도로 한다.

### 필수 동작
- 홈페이지·운세 메뉴·결과 화면에서 지정일 진입 가능.
- 출생 정보는 기존 세션을 재사용. 없으면 먼저 입력.
- 날짜 선택 후 해당 날짜의 여섯 지수와 여섯 본문을 표시.
- 선택한 날짜를 제목과 결과에 명료하게 표시.
- 오늘·내일·지정일이 같은 날짜를 가리키면 같은 판단·지수·기본 본문.
- 달력 날짜 검증, 지원 범위, 빈 입력·잘못된 입력 처리.
- 한국 날짜 기준 기본 오늘. UTC 날짜 문자열을 잘라 한국의 오늘을 정하지 않는다.
- 자정이 되어도 사용자가 고른 지정일은 유지. “오늘”으로 돌아갈 때 기본 날짜를 사용.
- 새로고침 시 출생 정보가 사라지는 기존 정책을 유지하고 재입력 안내를 제공.
- 선택 날짜의 원국인 것처럼 출생 표를 교체하지 않는다.

### 선택적 일정 맥락
자유 서술형 AI 채팅은 만들지 않는다. 다음과 같은 선택형 맥락을 추가한다.
- 일반
- 면접
- 시험·자격
- 발표·협상
- 계약·거래
- 만남·중요한 약속

선택은 여섯 기본 지수를 바꾸지 않는다. 같은 사람·같은 날의 기본 운세가 “면접” 버튼을 눌렀다고 달라지면 안 된다. 맥락에 맞는 추가 설명만 고른다.

각 추가 설명:
- 사주에서 참고하는 요소.
- 그 일정에서 유의해 볼 점.
- 실제 준비 체크 2~3개.

면접은 사업운의 역할·평가와 학업운의 준비·표현 관련 조건을 참고한다. 이름이 면접이라는 이유만으로 모든 원고에 “합격 가능성이 높다”를 붙이지 않는다.

예를 들어 “낮은 점수이므로 면접을 취소하세요”가 아니라, 해당 해석에서 준비·설명을 강조하는 이유와 답변·일정·이동 확인처럼 실제로 할 수 있는 준비를 제시한다. 합격·불합격, 특정 회사의 판단, 가장 좋은 면접 시간을 알아냈다고 주장하지 않는다.

선택 날짜를 운세만으로 변경·취소하도록 지시하지 않는다. 일정 참고 영역에 “면접 일정은 준비 상태와 회사 안내를 우선해 정하세요”처럼 짧고 구체적인 안내 한 번이면 충분하다. 본문 전체를 주의문으로 채우지 않는다.

이번 필수 범위는 지정일 단일 조회다. 여러 날짜 비교는 2차 개선으로 남길 수 있다. 이를 위해 임의의 합격 확률이나 길일 순위를 만들지 않는다.

## 9. 기간별 계산과 서술을 일치시킨다

기존 고급 기간 계산을 우선 활용한다.
- 원국: 고정된 출생 구조.
- 대운: 실제 시작·종료 시점.
- 세운: 채택한 입춘 경계.
- 월운: 채택한 절입 경계.
- 일운: 채택한 날짜 경계.

화면의 “이번 달”, “올해”는 양력 기간이되, 그 안의 명리학적 경계를 구분해 설명할 수 있어야 한다. 월초·월중·월말의 임의 일자를 대표로 뽑아 월 전체인 것처럼 표시하지 않는다.

월·연 지수는 관련 구간별 판단을 기간 전체에 맞게 집계한다. 예: 실제 구간 길이를 반영한 가중 평균. 선택한 집계법·반올림을 명시한다. 단순 정오 샘플값을 전체 기간의 확정 점수로 쓰지 않는다. 구간별 차이를 확인할 수 있는 보조 내용도 둔다.

연간 전체 본문이 오늘 날짜를 기준으로 매일 교체되지 않아야 한다. 조회한 연도·정책·원고 버전이 같으면 연간 결과는 같아야 한다. 조회 시점의 현재 대운을 연간 모든 날짜에 소급 적용하지 않는다.

일운은 원국과 실제 대상 일진을 사용한다. 원국의 월지·일지·시주, 대상 지지와 원국의 관계, 세운·월운·대운 등 채택한 조건을 함께 살핀다. 일간과 대상 천간만으로 모든 본문을 정하지 않는다.

해석이 비슷한 날은 있어도 된다. 날짜만 바뀌고 같은 본문이 기계적으로 10일마다 재생되는 문제는 검사하고 개선한다. 365일 모두 달라 보이게 하려고 무작위 수식어나 동의어를 붙이지 않는다.

## 10. 데이터 구조: 사실·해석·원고·표현을 분리한다

현재 타입과 검토 이력을 재사용하며 다음 의미를 표현할 수 있게 확장한다.

### 계산 사실
- 출생 입력 정규화, 적용 시간 정책, 원국.
- 십신·지장간·오행·원국 관계.
- 신강·격국·용신 등의 채택 정책 후보와 불확실성.
- 대운과 기간의 간지·관계.
- 대상 기간의 경계 구간.

### 분야별 판단
- domain: overall / study / money / health / love / business.
- periodKind: day / month / year.
- evidenceRefs, policyVersion.
- 긍정·부담·반대 요인.
- 우선 적용한 규칙과 제외 이유.
- 지수 기여와 최종 지수, 유보 여부.
- 지수 구간과 본문 조립에 필요한 해석 태그.

### 원고
- ID·버전·검토 이력.
- 분야·기간·역할.
- requires·premises·exclusions.
- 필요한 입력과 미확정 처리.

## 12. 실제 원고 구축량과 우선순위

목차만 만들지 말고 실제로 선택되는 원고를 집필한다. 기존 62개 고급·136개 기간 등은 현재 코드로 다시 집계하고 유지·수정·신규를 구분한다.

이번 목표:
1. 여섯 분야 × 일·월·연의 18개 조합에 각 12개 수준의 의미 있는 중심 원고: 약 216개.
2. 원국과 기간의 둘 이상 근거를 연결하는 분야별 보완 원고: 약 108개.
3. 지정일의 6개 일정 맥락에 각각 6개 수준의 상황별 참고 원고: 약 36개.
합계 약 360개를 구축 출발 규모로 삼는다.

이는 새 원고 360개를 무조건 추가하라는 뜻이 아니다. 기존에 적합한 자료는 유지·개선하고 집계에 포함하되 그대로 밝힌다. 숫자는 제품 작업량 목표이지 전통 이론의 기준이나 정확도 증거가 아니다.

중심 원고는 단순 십신 10개 매핑으로 끝내지 않는다. 지지 관계·원국 특징·기간의 맥락·상반 조건을 반영해 실제 선택 차이를 만든다. 원고의 제목·어미·기간 단어만 바꾼 것을 독립 원고로 세지 않는다.

분량을 채우기 위해 분야와 관계없는 원고를 생성하지 않는다. 건강운에 검증되지 않은 신체 예측을 넣어서 원고 수를 채우지 않는다. 의미상 중복 제거 후 실제 원고 수와 부족한 커버리지를 보고한다.

작업이 길어지면 기준표·스키마 → 18개 조합의 실제 동작 → 보완 원고 → 지정일 맥락 순으로 완성한다. 중간 단계에서 완료라고 멈추지 않는다. 범위상 검증 불가능한 항목만 명확히 보류한다.

## 14. 자연스러운 한국어로 쓴다

사용자는 과도한 추상어·번역투·인위적인 다정함을 싫어한다. 사진의 구조는 참고하되 본문을 복사하지 않는다. 사진 속 “지갑을 줍는다” 같은 사건 예언이나 지나치게 격식 있는 문체까지 따라갈 필요는 없다.

- 차분하고 자연스러운 존댓말.
- 제목은 “학업운”, “재물운”처럼 바로 알 수 있게. 장식적인 제목으로 대체하지 않는다.
- 소제목이 필요하면 “익힌 내용을 정리할 때”, “지출보다 정산을 먼저”처럼 내용을 예고한다.
- “섬세한 기준을 나에게도 다정하게”, “에너지를 현실적 성과로 전환하는 흐름”, “가능성을 품고 나아가세요” 같은 문장을 그대로 통과시키지 않는다.
- “오늘은 ~한 날입니다”만 반복하는 본문을 쓰지 않는다.
- 전문 용어는 근거에 필요할 때 짧게 설명하고 생활 상황으로 연결한다.
- 매 문장에 “예측이 아니에요”, “확정하지 않아요”, “실제 상황을 보세요”를 붙이지 않는다. 공통 설명은 도움말에 한 번, 조건부 설명은 필요한 위치에만.
- 문장이 자연스러워도 새 정보가 없으면 삭제한다.
- 단어 바꾸기만 한 3문단을 상세 원고로 세지 않는다.
- 사용자의 직장·연애·재산·건강·성격을 이미 아는 척하지 않는다.
- 근거가 불충분한 친밀한 호명이나 상담사 연기를 하지 않는다.

저장소에 포함된 korean-skills 자료를 확인하고 humanizer·grammar-checker·style-guide의 실제 적용 가능한 지침을 읽는다. 읽지 않은 skill을 적용했다고 보고하지 않는다. 해당 자료는 문체 보조이며 계산·명리 판단의 검증을 대신하지 않는다.

한국어 편집 보고서에는 기존 문구의 실제 수정 전·후·이유를 최소 12쌍 제시한다. 새로 작성한 글에 가상의 수정 전 문장을 만들지 않는다. 문장당 AI 점수나 기계적인 교체 비율을 합격 기준으로 쓰지 않는다.

## 15. 홈페이지와 탐색 구조를 개선한다

기존 분위기는 전통적인 운세 사이트의 친숙함을 유지하되 정돈한다. 과도한 보라색 그라데이션·네온·AI 대시보드·챗봇 중심 화면을 만들지 않는다.

- 오늘 운세.
- 내일 운세.
- 지정일 운세.
- 이번 달 운세.
- 올해 운세.

한 화면에 위 메뉴가 반드시 모두 큰 카드로 들어가야 하는 것은 아니다. 핵심 진입이 눈에 잘 보이도록 구성한다. 운세와 사주를 시각적으로 구분하고 기존 성격·연애·띠·별자리 등의 접근도 유지한다.

만세력 독립 메뉴는 기존 계산을 재사용하고 상단 원국·관계·오행·대운 등으로 이어진다. 원국을 보기 위해 긴 장문 사주 풀이를 거쳐야 하지 않는다.

기존 경로를 가능한 한 유지한다. 새 지정일·만세력 경로는 현재 정적 export 구조에 맞게 생성한다. category 타입, generateStaticParams, sitemap, 링크, 메타데이터, 메뉴 정렬을 함께 점검한다. 존재하지 않는 정적 경로를 링크로만 추가하지 않는다.

메뉴 이름·버튼·FAQ를 새 동작과 맞춘다. 예를 들어 태양시를 지원하면서 FAQ에는 “표준시만 사용”이라고 남기는 일이 없어야 한다. 브랜드명은 별도 요청 없이 바꾸지 않는다.

- 365일 전부 다르게 만들었다는 이유만으로 품질 통과라고 하지 않음.

### 실제 읽기
서로 다른 원국 3명 이상에서 일·월·연, 지정일 면접, 시각 미상, 경계 사례 등 최소 9개 전체 결과를 읽는다.
- 분야별 새 정보가 있는가.
- 재물과 사업이 같은 본문인가.
- 학업과 사업이 공부·일 단어만 바꾼 것인가.
- 건강운이 질병 추정으로 넘어갔는가.
- 그래프와 본문이 반대로 말하는가.
- 학술적 정의와 제한 안내만 있고 운세 풀이가 없는가.
- 사람이 읽기에 자연스러운가.
실제로 사람이 독립 검토하지 않았으면 독립 편집·전문가 승인이라고 쓰지 않는다.

### UI·브라우저
- 최초 결과에서 원국표가 보이고 토글 조작 없이 읽힘.
- 각 화면에서 시·일·월·년의 데이터 위치가 정확함.
- 여섯 축과 여섯 본문이 실제 데이터로 연결됨.
- 본문 이동, 날짜 선택, 입력 수정, 다른 메뉴, 뒤로 가기.
- 신규 정적 경로의 직접 접속.
- 글자 확대·키보드·결측 차트·작은 화면.
- 입력 데이터가 네트워크·URL·콘솔·저장소에 남지 않는지.
- 인쇄/PDF에서 표·그래프·본문 누락 여부.
- 기존 공유·인쇄·입력 지우기·개인정보 동작 회귀.

검증 명령은 현재 package.json을 기준으로 lint·typecheck·관련 단위/통합·빌드·E2E를 실행한다. 필요한 패키지나 브라우저가 없어 실패하면 실제 원인과 미실행 범위를 구분한다. 과거 보고서의 점수·통과 건수를 이번 실행 결과로 복사하지 않는다.

## 19. 최종 전달물

1. 실제 수정된 소스와 데이터.
2. 계산 사실 → 분야 판단 → 지수·본문의 구조 설명.
3. 기준표·판단 정책·원고 스키마와 검사 도구.
4. 기존 유지·수정·신규·보류 원고 수 및 의미상 중복 집계.
5. 오늘·지정일·이달·올해·정통사주·만세력의 전체 예시.
6. 모바일 화면 검토 자료. 작업 중 확인용과 사용자에게 전달하는 자료를 구분한다.
7. 실제 실행한 테스트·명령·결과와 미실행 항목.
8. 변경 파일·주요 위험·남은 검토 사항.
9. 다음 검토자가 재현할 수 있는 START_HERE와 검토 ZIP.
10. 로컬 모바일 테스트 방법.

모바일 테스트 안내는 실행한 사실에 근거한다.
- 로컬 서버를 같은 Wi-Fi의 휴대전화에서 열 수 있는 경우 실제 바인딩 주소·포트와 접속 형식을 안내한다.
- 클라우드 개발 환경이면 PC의 사설 IP 주소만 주고 접속 가능하다고 하지 않는다.
- 외부 공개 URL을 발급하지 않았다면 아직 외부 접속 URL이 없다고 밝힌다.
- 실기기로 실행하지 않았다면 모바일 뷰포트 검증과 실제 휴대전화 검증을 구분한다.
- 이번 지시에는 공개 배포가 포함되지 않는다.

최종 설명은 “기능 추가 완료”가 아니라, 실제로 어디서 원국이 보이고 여섯 분야가 어떻게 달라졌으며 지정일을 어떻게 조회하는지부터 말한다. 원고 수·테스트 수를 예측 정확성이나 독립 명리 검증의 증거로 바꾸지 않는다.
