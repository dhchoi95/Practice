# 구조와 데이터 흐름

```text
한국 음력 입력 ─ 한국 달력 어댑터 ─ 양력 날짜
                                    │
시·분 / 시간 미상 ─ IANA 시간대 ─ 표준시·가능한 순간
                                    │
                        절기 어댑터 + 자체 간지 정책
                                    │
                     확정 기둥 / null + 관계 feature
                                    │
  JSON 원고 ─ 스키마 검사 ─ 저장소 ─ DSL 선택·충돌·중복 처리
                                    │
                         읽기용 섹션·조언 → React
```

`domain/calendar`는 달력 변환·시간대·절기 자료를 감쌉니다. `domain/saju`는 자체 일진·시주, 절입 연월주, 오행 분류와 천간 십성을 다룹니다. DOM·React·Storage에 의존하지 않습니다. `domain/fortune/period.ts`가 출생 순간과 별개인 대상 기간을 나눕니다.

`domain/interpretation`은 선언형 스키마, `ContentRepository`, 조건 평가와 선택을 분리합니다. UI가 JSON을 제각각 읽지 않습니다. `requires`와 unknown을 통과한 규칙만 priority 내림차순 → specificity 내림차순 → ID 오름차순으로 선택합니다. 독점 그룹당 하나, 동일 의미 축의 서로 다른 stance는 함께 고르지 않습니다. 동률과 원고 배열 순서에도 결과가 같습니다.

종합사주는 주제별 기본 모듈을 함께 읽되 반복되는 일간 소개·관찰 과제를 제외합니다. 문단은 자르지 않고 1,800자 예산에 맞는 섹션만 담습니다. 실제 보이는 규칙만 적용 ID에 기록합니다. 조언과 문단은 정확한 문자열 기준으로 중복을 제거합니다. 한국어의 의미 중복을 완전히 자동 판정하는 시스템은 아니며 원고 검토가 필요합니다.

공통 오행 설명은 별도 5개 모듈이며 선택된 보완 원고 앞에 한 번 조합합니다. 결과의 `sharedExplanationIds`는 실제 보이는 모듈만 기록하고 `appliedRuleIds`와 구분합니다. 일간 미확정 안내는 성향 해석 원고 수에 넣지 않으며, 기간 관계를 알 수 없을 때 앞/뒤 구간의 해석으로 꾸미지 않습니다.

결과 화면의 `usePrintDetails`는 브라우저의 `beforeprint`에서 모든 풀이 상세의 기존 열림 상태를 저장하고 펼칩니다. `afterprint`와 컴포넌트 해제 때 복원하며, 반복 이벤트도 원래 상태를 덮어쓰지 않습니다. 버튼·브라우저 메뉴·키보드 인쇄에 같은 처리를 사용합니다.

`SessionProvider`는 페이지 이동을 가로질러 메모리 상태만 유지합니다. 저장되는 파일·DB·localStorage·sessionStorage·쿠키가 없습니다. 새로고침/새 문서 결과 진입 시 입력 안내를 보여줍니다. 다른 사람 보기·입력 지우기는 출생정보와 가벼운 선택을 모두 비웁니다. 원시 입력은 공급자와 폼 안에 제한하며 결과 컴포넌트에는 계산 객체를 제공합니다. 별명은 React 텍스트로만 렌더링합니다.

Next App Router의 `/fortune/[category]`, `/result/[category]`, `/[info]`는 허용 목록으로 사전 생성합니다. 개인 결과의 HTML은 일반 골격뿐이며 브라우저에서 계산·선택합니다. 결과 경로는 noindex이고 sitemap에 포함하지 않습니다. API 라우트·Server Action·SSR 개인 입력 처리가 없습니다.

홈은 계산 엔진이나 풀이 JSON을 import하지 않습니다. 메뉴 링크의 자동 prefetch를 꺼 아직 선택하지 않은 경로의 데이터를 미리 읽지 않습니다. `LiveDate`만 한국 날짜를 분 단위·focus·visibility 이벤트로 갱신합니다. 입력과 결과 경로에서 필요한 패키지와 콘텐츠를 로드합니다. 불필요한 worker·상태 라이브러리·ORM은 없습니다.

Git은 코드·콘텐츠 변경 이력 저장소, JSON은 조건부 문장 저장소, 메모리는 개인 입력 상태입니다. 추후 콘텐츠를 SQLite/CMS로 옮기면 `ContentRepository`를 구현하고 사전 검증된 배포 JSON을 만드는 방식으로도 전환할 수 있습니다. 방문자의 생년월일 DB가 필요한 것은 아닙니다.
