# AI 사주 2.5.0 후속 개선·배포 시도 결과

검증일: 2026-10-29. **서버 반영 미완료: 배포 사전 조회가 실행 환경의 프록시 403으로 차단됐다.** 후보 버전 2.5.0 / 콘텐츠 2.4.1. 대상은 기존 https://spring-voice-4bdc.eogjs9595.workers.dev/ 이며, 이번 코드가 반영된 주소로 안내하지 않는다. 현재 공개 버전은 이번에 조회하지 못했다. 마지막 보관 증거는 2.4.1 / Cloudflare version 92f7ac21-ea3e-4885-8211-8dc6de7364fa / source 3944cf0이며 작업 출발 HEAD는 4bae012다.

## 이번 변경과 증거

1. **동일 공개 Worker의 실제 서버 구성**: 기본 wrangler.json과 wrangler.ai.jsonc를 동일한 Worker entry+assets+SQLite DO로 정리했다. api/auth는 실제 서버로 처리하고 민감 응답은 no-store다. 분리 스테이징은 spring-voice-4bdc-ai-stg이며 DB/세션/키를 공유하지 않는다. 운영 코드 bundle에 로컬 IdP나 모의 AI가 포함되지 않는지 검사했다. 외부 설정이 미완료인 로그인·AI·저장 플래그는 false다.
2. **카카오 연결 해제**: `/auth/webhooks/kakao/unlink`에서 KakaoAK 대표 어드민 키·숫자 앱 ID·요청 길이·중복 파라미터를 검증한다. 인증 뒤 durable outbox와 철회 장벽을 먼저 저장하고 세션/가입 대기를 철회한다. persistent alarm이 해당 계정·저장 자료를 삭제한다. 잘못된 키/앱·중복·재시작·늦은 AI 저장·과거 OAuth 재개를 검사했고 실제 로컬 DO alarm도 실행했다. 계약은 이번 첨부 지시문을 근거로 구현했으며 **최신 공식 페이지 및 실제 원격 3초 SLA는 미확인**이다. 시각/전송 ID가 없는 정적 키 계약에 암호학적 freshness를 만들어냈다고 주장하지 않는다. 재가입 후 오래된 통지의 순서는 실제 공급자 재전송 정책으로 확인해야 한다. 구글·네이버에 카카오 계약을 복제하지 않았다.
3. **비저장 답변 유실 안내·기기 내 내보내기**: 장기 저장을 몰래 켜지 않고 대화 복사/텍스트 내려받기를 추가했다. 새로고침하면 답변과 문맥은 사라지며 같은 출생정보를 다시 입력하면 남은 후속 질문을 쓸 수 있다. 실제 브라우저에서 첫 진단→파일 저장→새로고침→후속 질문을 검증했다. **응답 도착 전에 연결이 끊기면 답변을 받지 못한 채 이용 횟수가 반영될 수 있는 한계는 남는다.** 동일 완료 요청을 다시 유료 생성하지 않는다.
4. **비용·운영 통제 보강**: watchdog 이후 실제 usage가 늦게 도착하면 금액만 한 번 보정하고 실패 상태/삭제 자료를 되살리지 않는다. 원문 없는 단계별 지연·thinking·재시도 지표를 추가했다. private operations summary가 가격 만료 7일 전 경고/종료일을 제공하며 확인일을 자동 연장하지 않는다. 이메일 알림을 발송한 것은 아니다. isolate별 경량 요청 제한과 미개방 환경의 불필요한 DB 조회 방지를 추가했지만 Cloudflare 전체 청구액의 절대 상한은 아니다. 제공자별 명시적 개방 플래그와 카카오 웹훅 검토 플래그도 필요하다.
5. **문구·공개 정책 범위**: 준비 중 기능을 이미 개인정보를 수집하는 서비스처럼 쓰던 설명을 고쳤다. 기본 무료 기능 설명은 유지하고 AI 개방 전 별도 고지가 필요함을 명시했다. 기존 오문 ‘있을 거입니다’와 월간 공통 연결 문장은 현재 활성 src에 없음을 확인했다. 2027년 조합의 여섯 분야를 다시 읽어 총운=평가/보람, 학업=설명/이해, 재물=수입/지출, 건강=식사/휴식, 연애=관심/대화, 사업=경험/요구로 구별됨을 확인했다. 이번에 이미 교정된 본문을 다시 일괄 생성하지 않았다.

원국·시간 미상·선정 조건·기존 점수·원고 본문은 바꾸지 않았다. 상단 6개와 기존 4×2/3×3 디자인은 유지한다. 계산 파일 35개 해시, 고정 선정 33,564건, 활성 1,197레코드/15개 완성 예시와 기존 140개 후속 교정 검사가 통과했다. UI/안내 변경의 인벤토리·해시·작성자 재검토 기록을 갱신했으며 독립 전문가 승인을 받았다고 표시하지 않는다.

## 실제 배포에서 막힌 단계

- 기존 자격증명을 비밀 출력 없이 재사용하려 했으나, **첫 GET `https://api.cloudflare.com/client/v4/accounts` 이전 프록시 CONNECT에서 `403 Forbidden`**이 발생했다. 공개 사이트와 공식 문서도 같은 유형으로 접근하지 못했다. 토큰 활성/만료/권한이나 계정 플랜을 확인했다고 볼 수 없다.
- 자동 승인 검토가 한 번 이전 ‘배포 전 중단’ 지침을 근거로 거부했다. 최신 첨부의 제한 대체·기존 Worker 배포 허용 문구를 다시 확인하여 읽기 전용 검사는 허용됐지만 네트워크 403은 계속됐다. 이후 network 권한을 승인받아 재검사해도 동일했다. 현재 남은 차단은 자동 승인 거부가 아니라 네트워크다.
- 마지막 실제 사전 조회 기록은 `reports/ai-saju/preflight-deployment.json`. 원격 스테이징/운영 배포 0건, 원격 migration 0건, 공개 신규 코드 검증 0건이다. 새 Worker를 만들어 기존 서버 반영으로 보고하거나 모의 성공으로 대체하지 않았다.
- [cloud-environment-onboarding:setup](skill://plugin_connector_1p_ed5feb9070a08191b08c81c47947bc16/setup/SKILL.md)의 절차로 환경 설정 초안을 읽었다. 기존 Cloudflare 허용 도메인 3개는 이미 초안에 있었으므로 누락이라고 단정하지 않았다. 그 목록을 보존하고 공식 문서 호스트 6개를 추가했으며 AI Worker 실행/검증/배포 재개 안내를 start_skill에 저장했다. install_script·저장소 목록·기존 비밀 요구는 보존했다.
- 도구가 **status=saved / requires_publish=true**를 반환했다. 초안 저장은 런타임 적용이나 게시가 아니다. 환경 설정에서 변경사항을 검토·저장한 뒤 환경을 게시하고, 적용된 실행 환경에서 사전 조회부터 재검사해야 한다. 새 환경 복원을 독립 검증했다고 주장하지 않는다. 저장된 목록이 현재 실행 프록시에서 유효한지 아직 확인하지 못했다.

## 다음 진행

현재 필요한 첫 조치는 **환경 설정 초안 적용/게시 후 Cloudflare 접속 재검사**다. 토큰 값을 채팅에 다시 보내거나 새 토큰을 만들도록 요구하지 않는다. 준비된 순서는 preflight → staging 배포 → 실제 staging 검사 → 같은 빌드 production 배포 → 실제 공개 검사다. 서로 호환되는 추가 스키마만 적용하며 플랜 전환/파괴적 자료 삭제를 자동 실행하지 않는다.

실제 가입/유료 AI는 별도 미완료다. 운영 주체·문의처·도메인/제공자 승인·AI 데이터 처리 조건/현재 모델·실제 가격·일/월 상한·정책을 확정한 뒤 실제 OAuth/웹훅/합성 한국어 최소 20건/실기기를 확인해야 한다. 실제 20건을 실행하지 않았으며 예시 비용·모의 token으로 실측 비용을 꾸미지 않았다. [운영자가 할 일](../../USER_ACTION_REQUIRED.md)은 네 묶음으로 정리했다.
