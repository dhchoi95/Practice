# 정통사주·기간 운세·콘텐츠·한국어 통합 고도화 — Codex 실행 지시문

작성일: 2026-10-22.

이 문서 전체를 현재 프로젝트와 함께 Codex에 전달한다. 기존 소스가 연결된 Codex 작업에서는 이 문서만 붙여도 되며, 현재 저장소에 이전 검토 자료가 없다면 함께 제공한다. 이 문서는 구현용 지시이며, 아래에 등장하는 예시 명식·대운·해석을 이미 검증된 정답으로 인증하는 문서가 아니다.

## 실행 지시 시작

너는 기존 한국어 무료 사주 사이트를 고도화하는 개발자이자 콘텐츠 설계자다. 현재 소스를 직접 읽고 계산·해석 규칙·원고·조립·화면·검증을 연결해 구현하라. 설계나 원고 생성 계획만 제출하고 끝내지 않는다.

사용자가 원하는 것은 다음과 같다.

- 전통 사주명리학의 규칙을 바탕으로 설명이 이어지는 깊이 있는 정통사주.
- 같은 출생정보·조회기간·계산정책·공개 콘텐츠 버전에서는 같은 결과.
- 시간이 흐르면 해당 연·월·일의 간지와 원국의 관계에 따라 달라지는 운세.
- 같은 일간이라도 다른 원국 구성과 기간 조건을 실제로 반영하는 설명.
- 한 세트를 통째로 재탕하거나 짧은 문구를 날짜로 돌리는 수준을 넘는 원고 조합.
- 한국어 독자가 읽었을 때 자연스럽고, 충분한 이유·상황·구체성을 가진 본문.
- 운영 중 LLM API 없이 일반 코드와 정적 원고 저장소로 실행되는 저비용 구조.

성공 기준은 미래 예측 적중률이 아니라, 전통 규칙의 일관성, 설명과 계산의 연결, 기간별 변화, 원국별 차이, 문장 품질, 실제 사용성이다. 그렇다고 근거 없이 미래 사건을 만들어내거나, 아무 글에 명리 용어를 붙여 개인화한 것처럼 보여서는 안 된다. 사용자는 문학적인 감성 문구보다 명식에 연결된 구체적인 풀이를 원한다.

이 문서는 과거 요구 중 ‘진태양시·대운·강약·용신 등을 이번 범위에서 제외한다’는 제한을 **이번 고도화 범위에 한해 변경**한다. 현재 지원 계산과 개인정보 보호, 무료 이용, 결정성은 보존한다. 실제 공개 배포·원격 push·결제·도메인 구입·외부 메시지·유료 서비스 호출은 하지 않는다. 서비스 실행 중 OpenAI·Claude·기타 LLM을 호출하지 않는다.

## 1. 현재 상태와 변경 전 기준을 확인하라

먼저 AGENTS.md 등 저장소 지침과 사용자의 미완료 변경을 확인한다. 다음 자료가 있으면 읽는다.

- 원래 실행 요구사항과 지금까지의 독립 검토·지적 대응.
- 콘텐츠 1.2.0·1.3.0 개선 문서와 한국어 비교안.
- `src/domain/calendar`, `src/domain/saju`, `src/domain/fortune`.
- `src/domain/interpretation`의 schema·repository·knowledge·reasoning·engine·period-reading·review·quality.
- `src/content/rules.json`, 공통 설명, 근거 정의, 용어·출처·날짜별 문구.
- `content-review`의 조건 초안·의미 사례·검토 기록·원문 스냅샷·supersedes 구조.
- 결과·입력·사주표·공유·인쇄 컴포넌트, 기존 평가·테스트·빌드 도구.

이전 자료 기준은 정상 원고 210개, 공통 설명 5개, 내부 근거 25개, 별도 복합 draft 4개, 기간 원고 일·월·연 각 10개였다. 1.3.0 제출 검사 수는 단위·통합 296개, Chromium 63개, 실제 PDF 13개였다. 이 숫자를 현재 상태라고 가정하지 말고 실제 저장소와 비교한다. 이후 한국어 수정이 반영됐다면 그 변경을 보존한다.

변경 전 원고·규칙·계산정책·콘텐츠 버전·검토 상태와 대표 입력 결과를 기록하라. 서로 다른 정책의 결과를 섞어서 비교하지 않는다. 기존 표준시 정책은 호환 프로필로 남기고 새로운 고급 정책과 명확히 구분한다.

작업 범위는 다음의 연결된 구현이다.

1. 정통사주 계산·해석의 확장.
2. 원국 + 대운 + 세운 + 월운 + 일진의 기간 해석.
3. 정적 원고·근거·조립 구조와 원고 확충.
4. 한국어와 상세 결과 화면.
5. 기존 가벼운 유형 메뉴의 정직한 변화 방식 보완과 MBTI 메뉴.
6. 회귀·결정성·장기간 결과·독립 검토 묶음.

위 순서로 진행하고, 중간 단계 하나를 완성했다는 이유로 전체 목표가 완료됐다고 보고하지 않는다. 되돌릴 수 있는 구현 선택은 스스로 진행한다. 단, 검증 자료가 없는 해석을 검증 완료로 꾸미거나 불확실한 입력을 임의 확정하지 않는다.

## 2. 계산 사실·명리 판단·문장 편집을 분리하라

다음 네 층을 구분한다.

| 층 | 예 | 저장할 정보 |
|---|---|---|
| 계산 사실 | 일간, 원국 간지, 지장간, 절입 순간, 대상 연도 간지, 특정 지지의 출현 | 입력 의존성, 정책, 실제 값, 계산 버전 |
| 명리 규칙 판단 | 통근·투간, 신강 경향, 격국 후보, 조후, 구조 성립·미성립 | 채택한 판단법, 충족·불충족 조건, 반대 근거, 출처 상태 |
| 주제 해석 | 이 구성에서 직업·관계·재물의 어떤 주제를 읽을지 | 실제 전제, 해석 규칙 ID, 적용 범위, 상충 조정 |
| 원고·화면 | 설명, 구체적인 상황, 작은 행동, 표와 요약 | 원고·문단·제안 ID와 버전, 표시 이력 |

기본 흐름은 ‘입력 정규화 → 원국·기간 계산 → 해석 조건 평가 → 주제와 우선순위 결정 → 원고 선택 → 충돌·중복 조정 → 출력’이다.

한글 문장을 먼저 생성한 뒤 거기에 근거 ID를 사후로 붙이지 않는다. 또한 단어가 있다는 검사만으로 구조가 성립했다고 판정하지 않는다.

정적 JSON·TypeScript 등의 현재 구조를 확장해도 된다. SQL·벡터 DB·RAG·별도 CMS 서버는 이 규모에 필요성이 입증되지 않는 한 도입하지 않는다.

## 3. 출생 시각·도시·태양시 정책을 구현하라

### 3.1 입력

기존 생년월일·양음력·윤달·시간 모름을 유지한다. 정밀 분석에 필요한 선택 입력을 추가한다.

- 출생 도시 또는 사용자가 직접 선택한 지역 좌표. 국내 도시 목록을 로컬 데이터로 제공하는 방식을 우선한다.
- 계산 시각 정책: 기존 한국 표준시 / 지방평균태양시 / 진태양시 중 실제 구현한 방식.
- 전통 대운의 순역 계산에 사용하는 분류. 사용 목적을 설명하고 선택하지 않을 수 있게 한다.

정확한 주소·GPS 권한·현재 위치·전화번호는 요구하지 않는다. 도시 중심 좌표는 실제 출생지의 정확한 좌표와 다르다는 정도만 간단히 알린다. 도시 정보의 출처·정밀도도 기록한다.

기존 기본 흐름은 표준시로 계속 동작한다. 고급 분석에서 시각 정책을 쉽게 선택·비교할 수 있게 한다. 경기도처럼 넓은 지역명만 주어졌다고 수원 등의 도시를 조용히 대입하지 않는다. 출생 도시가 없으면 진태양시를 분 단위로 확정하지 말고 표준시 결과와 제한을 제공한다. 계산 가능한 범위가 있다면 후보로 제시하되 확정과 구분한다.

### 3.2 시간 계산

출생 당시 현지 시계 시각 → IANA 시간대·서머타임 처리 → 실제 UTC 순간 → 선택한 명리 시각 정책의 순서를 명시한다. 경도 보정과 균시차를 혼동하지 않는다.

진태양시는 구현에 채택한 부호 정의를 명시하고, 예를 들어 NOAA의 경도·시간대·균시차 공식을 출처로 검토할 수 있다. 공식의 수치 정확도와 지원 범위를 기록한다. 한국 모든 지역에서 고정 30분을 빼는 방식은 진태양시가 아니다.

입력 시각, 표준시 환산, 경도 보정분, 균시차, 최종 시각, 날짜 이동, 시주를 구분해 표시한다. 가능한 입력 정밀도보다 더 정확한 분·초를 아는 것처럼 쓰지 않는다.

천문학적 절입 순간은 동일한 실제 순간으로 비교한다. 출생 시각에만 보정을 더하고 절입 시각은 다른 기준으로 남겨 두는 등의 시간축 혼용을 금지한다. 절입 경계 판단·시주 산출·대운 시간차에 어떤 시간축을 쓰는지 각각 문서화한다.

자정·23시 자시·절입 직전후·서머타임 전환·지역 차이에서 정책별 차이를 검사한다. 기존 자정 기준과 새 프로필을 구분하고 라이브러리 기본 자시 정책으로 조용히 바꾸지 않는다.

### 3.3 불확실성 전파

시간이나 도시가 없어 확정할 수 없는 시주는 그에 의존하는 통근·삼합·강약·격국·용신·대운·주제 문장에도 영향을 줘야 한다. 설명 끝에 작은 경고만 붙이고 본문은 확정형으로 출력하지 않는다.

표준시와 진태양시에서 시주가 달라지면 ‘같은 점 / 달라지는 점’을 보여준다. 한쪽 정책의 시주와 다른 쪽 정책의 해석을 섞지 않는다. 대운 분류가 없으면 임의로 성별을 추측하지 않고 공통 원국 분석을 제공하거나 순·역 후보를 구분한다.

## 4. 원국·십신·지장간을 완성하라

네 기둥의 천간·지지·한글·한자·음양·오행을 보여준다. 기존 단순 오행 개수는 그대로 정확하게 설명하고, 고급 강약 판단과 다른 자료로 취급한다.

지장간 대응표는 출처·정책이 있는 단일 데이터로 관리한다. 본기·중기·여기 구분을 채택하면 적용법과 가중 여부를 명시한다. 한 글자를 여러 표에서 서로 다른 십신으로 표시하지 않도록 중앙 관계 함수를 사용한다.

천간 십신과 지지의 본기 십신, 지장간 전체의 십신을 구분한다. 화면에서 ‘일지의 십신’을 쓰면 어느 지장간 기준인지 알려준다. 천간에 안 보인다는 것과 지장간에도 없다는 것은 다르다.

원국에서 득령·통근·투간·생조·설기·극제 등 판단에 쓸 기초 사실을 구조화한다. 한 글자의 중복 출현을 별도 자리의 사실로 보존하되, 동일한 삼합 후보를 중복 집계해 힘이 두 배인 것처럼 계산하지 않는다.

## 5. 합충과 구조의 ‘존재’·‘작동’·‘변화’를 구분하라

기본적으로 천간 관계와 지지의 합·충·형·해·파·삼합·방합 중 실제로 지원할 항목을 출처와 함께 정리하고 구현한다. 모든 항목을 무조건 길흉 점수에 더하지 않는다.

특히 다음 단계를 구분한다.

1. 구성 글자가 있다는 사실.
2. 선택한 규칙에서 관계 후보가 확인됨.
3. 위치·계절·투간·방해 조건 등을 적용한 작동 판단.
4. 합화·격 성립처럼 더 강한 해석으로 확장할 수 있는지.

‘亥·卯·未가 있음’만으로 모든 수·토가 목으로 변했다고 처리하지 않는다. ‘식신과 편관이 함께 있음’만으로 완전한 식신제살격을 확정하지 않는다. 재성의 존재와 식신생재 구조의 성립도 구분한다.

중복되는 관계와 서로 충돌하는 조건은 평가 순서를 정한다. 원국 관계, 원국↔대운, 원국↔세운, 대운↔세운, 월·일 관계를 구분한다. 미래 연도의 관계를 원국 고유 구조처럼 기록하지 않는다.

계산된 관계의 출현은 충분히 구체적으로 설명하되, 충 하나로 이별·사고, 재성 하나로 돈 유입을 확정하지 않는다. 사용자는 구체적인 전통 풀이를 원하므로, 전부 ‘상황에 따라 다르다’라는 문장으로 대체하지도 않는다.

## 6. 신강·신약·격국·용신을 하나의 채택한 방법으로 평가하라

### 6.1 방법의 일관성

여러 학파의 결론을 편한 대로 섞지 않는다. 주된 해석 프로필 하나를 정하고 그 안에서 신강·격국·용신 판단 순서를 문서화한다. 대안이 필요한 경우 별도 프로필이나 후보로 표시한다.

기본 대응표·절기 계산이 소프트웨어 문서에 있다는 사실만으로 고급 해석까지 검증된 것으로 취급하지 않는다. 직접 읽을 수 있는 명리 자료와 그 적용 위치를 확인한다. 자료를 확인하지 못했다면 확인되지 않은 부분을 솔직히 기록하면서 검토 가능한 규칙과 후보를 구현한다. ‘전문가가 없으니 아무것도 할 수 없다’는 이유로 가능한 계산·자료 구조·후보·화면 구현 전체를 생략하지 않는다.

### 6.2 신강·신약

오행 단순 개수만으로 판정하지 않는다. 월령·계절, 일간의 뿌리, 생조와 설기·극제, 합화 판단 등 채택한 방법이 요구하는 요소를 반영한다.

결과에는 ‘판단 / 지지 근거 / 반대 근거 / 경계·미확정 요소’를 남긴다. 필요하면 신강·중화·신약 또는 경계 판정을 쓸 수 있다. 내부 편집 점수를 쓴다면 계산식·범위·정책을 문서화하고 실제 에너지 측정치나 확률로 표시하지 않는다. 보기 좋은 강약 막대를 먼저 만들고 그 수치에 이유를 맞추지 않는다.

### 6.3 격국과 구조

월령·지장간·투간 등을 어떤 순서로 판단하는지 정한다. 격 이름과 ‘식신생재처럼 해석하는 흐름’을 별도 필드로 둔다. 격국 후보가 여러 개거나 예외가 있으면 주된 후보를 선택한 이유를 기록한다. 단정할 수 없는 특수격·종격을 억지로 출력하지 않는다.

### 6.4 용신·희신

억부와 조후 등 서로 다른 목적의 판단을 구분한다. ‘화가 필요하다’는 계절 해석과 ‘현재 구성에서 목을 더 반기는가’라는 판단을 한 줄로 섞지 않는다. 용신 후보, 선택 이유, 이미 충분해 추가를 경계하는 요소, 반대 조건을 함께 관리한다.

후보를 제시할 수 있으나 모든 원국에 하나의 원소를 정답으로 강제하지 않는다. 화면에는 전통 판단으로서 ‘이 방식에서는 화를 우선 살핍니다’처럼 이유를 설명한다. ‘빨간 물건을 사면 운이 좋아짐’ 같은 구매 유도는 넣지 않는다.

## 7. 대운 계산과 현재 대운을 실제 날짜로 연결하라

채택한 순역법의 입력과 기준을 명시한다. 예를 들어 연간 음양과 전통 남녀 분류를 쓰는 방법을 채택한다면 그 방법에 맞는 표와 반례를 구현한다. 전통 분류는 실제 성격·관계 선호를 단정하는 정보로 확대하지 않는다.

순행·역행 각각에서 어느 이전/다음 절을 사용하는지 명확히 한다. 12절을 사용하는지 등 채택 방법을 기록하고 중기와 무작위로 섞지 않는다. 경계 시각과 정확히 같을 때의 취급도 정한다.

대운 개시 계산에서는 다음을 보존한다.

- 적용한 절의 이름과 실제 순간, 원자료 시간대.
- 출생의 실제 순간과 계산에 사용한 시간차.
- 삼일일세 등의 환산법과 분·초, 절삭·반올림 처리.
- 개시 연·월·일수 또는 개시 나이와 실제 개시 날짜.
- 월주에서 진행하는 대운 간지와 10년 구간의 시작·끝.
- 현재 조회일이 어느 대운 구간에 들어가는지.

만 나이·세는나이·절입 기반 환산 나이를 섞지 않는다. 한 대운이 시작되기 전에는 그 상태를 표시하고, 임의로 첫 대운을 이미 진행 중이라고 하지 않는다. 현재 연도만 보고 대운을 선택하지 말고 실제 시작 날짜를 사용한다.

10년 대운 8~10개를 제공하고, 각 구간의 간지·십신·주요 관계·해석을 보여준다. 표는 단순 복사된 고정 문자열이 아니라 입력에 따라 산출한다. 라이브러리의 대운 기능을 사용해도 시간대·자시·순역·환산법의 적합성을 어댑터에서 확인한다.

## 8. 원국·대운·연·월·일을 함께 보는 기간 엔진

현재 원국 일간과 대상 기간 천간의 십신만 고르는 구조를 확장한다. 하루 운세 10종이 10일마다 전체 본문을 반복하는 수준에서 벗어나야 한다.

추천 문맥은 다음과 같다. 이는 구현 설계이며 특정 학파의 유일 공식이라고 주장하지 않는다.

- 연간: 원국 + 해당 시점 대운 + 대상 세운.
- 월간: 위 배경 + 대상 월운.
- 일간: 위 배경 + 대상 일진.

같은 천간이 돌아와도 지지가 다르고, 같은 일진이 돌아와도 월·연·대운 배경이 다르면 적용되는 조건이 달라질 수 있어야 한다. 다만 결과를 다르게 보이게 할 목적으로 무관한 feature를 조건에 붙이지 않는다.

현재 서비스의 양력 연도·월 표시를 유지하면서 명리 구간은 입춘·절입 경계로 나눈다. 연간 조회에 입춘과 대운 전환이 모두 있으면 실제 해석 문맥이 달라지는 경계를 함께 고려한다. 월간은 절입·대운 전환 등 필요한 경계를 처리한다. 하루 중 경계가 생기면 하나의 관계를 하루 전체에 적용했다고 쓰지 말고 구간을 설명하거나 채택한 대표 시점 정책을 공개한다.

연간 결과는 조회 연도 안에서 날짜가 매일 바뀐다는 이유로 요약이 뒤바뀌면 안 된다. ‘올해 전체 분석’과 ‘오늘 시점의 올해 안내’를 구분한다. 월간·일간에도 같은 원칙을 적용한다. 연간 표의 현재 대운을 모든 미래 연도에 고정해서 쓰지 말고 해당 세운 구간에서의 실제 대운을 연결한다.

같은 정규화 출생정보·조회 범위·정책·콘텐츠 릴리스에서는 다음을 보장한다.

- 새로 조회하거나 10분 뒤 조회해도 동일한 본문·적용 이력.
- 기기 시간대가 달라도 한국시간 기준 조회가 동일하면 동일.
- 다음 날·월·해에 해당 문맥이 바뀌면 그 조건에 맞는 결과.
- 조회수·방문 세션·새로고침 횟수·난수·요일 번호에 따른 개인 운세 교체 없음.

조회 UI에 오늘/어제/내일, 대상 월, 올해/내년/연도 선택과 5년 세운을 제공한다. 지원 연도 밖은 명확히 제한하고, ‘내년’ 버튼이 같은 결과에 제목만 바꾸는 구현을 하지 않는다.

## 9. 고급 정통사주의 결과 구성과 분량

사용자가 제공한 긴 예시처럼 이유가 이어지는 상세 보고서를 구현한다. 기본 화면은 요약부터 보여주고 세부 분석은 모바일에서 읽기 편하게 나눈다.

필수 항목:

1. 입력 요약·선택한 계산 기준·시주 경계 여부.
2. 원국과 천간·지지·지장간·십신 표.
3. 원국의 주요 특징과 근거가 되는 실제 자리.
4. 신강·신약 판단과 반대 근거.
5. 격국 후보와 주요 구조의 성립 수준.
6. 용신·희신과 조후·억부 등 판단 목적.
7. 십신별 역할과 구성상 주의할 점.
8. 대운 시작 계산과 10년 대운표, 현재 대운.
9. 직업·재물·연애·관계 주제별 풀이.
10. 선택 연도부터 5년 세운 상세. 예시 재현에서는 2026~2030.
11. 5년 주제 비교표.
12. 전체 흐름을 연결하는 종합 총평.
13. 다른 시각 정책에서 실제로 달라지는 내용이 있으면 비교.

분량은 입력이 충분한 고급 결과의 경우 본문 약 4,000~7,000자 정도를 출발 목표로 삼되, 원고를 반복해 숫자를 채우지 않는다. 짧은 생활 운세에는 이 길이를 강제하지 않는다. 불확실한 경우 해당 항목을 줄이거나 후보를 보여준다.

각 항목은 ‘판단 → 실제 근거 → 다른 조건이나 예외 → 주제 의미’의 연결이 있어야 한다. 모든 항목을 이 형식의 똑같은 문장으로 시작하라는 뜻은 아니다. ‘왜 이 분석인가’는 쉬운 근거를 제공하고, 긴 내부 ID·규칙 JSON은 로컬 진단 자료에 둔다.

과거의 종합 1,800자 제한을 새 고급 분석 전체에 그대로 적용해 뒤 항목을 잘라내지 않는다. 간단 보기와 정밀 보기의 분량 정책을 구분한다. 5년 표와 본문, 요약에서 서로 다른 용신·대운·원국을 쓰지 않는다.

## 10. 원고는 조건이 있는 여러 모듈로 확장하라

하나의 완성 보고서를 모든 사람에게 재사용하거나, 16개·60개 타입 전체 세트로만 묶지 않는다. 내용의 연결을 유지하는 문단 모듈을 조합한다.

정통사주용 모듈은 원국 특징·강약·격국·조후·구조·대운·주제 해석·대안 설명을 맡는다. 기간용 모듈은 핵심 흐름·원국 연결·일과 학습·관계·소비와 관리·보완·작은 행동을 맡는다.

원고마다 최소한 다음 정보를 관리한다. 기존 schema를 재사용·확장해도 된다.

- 안정된 ID·주제·기간 단위·문단의 역할.
- requires·적용 조건·제외 조건·우선순위·구체성.
- 필요한 모든 factual premise와 실제 기준값.
- 해석 주장과 채택 방법·출처·검토 상태.
- 본문·제안·문장 결합에 필요한 문맥.
- 같은 결과에서 충돌하거나 겹치는 의미 축·행동·대상.
- 표현한 주장 강도와 허용되지 않는 확대 해석.
- 내용 버전·변경일·해시·검토 기록.

복합 원고가 ‘식상 2 이상 + 재성 1 이상 + 특정 기간 관계’를 쓰면 모든 전제를 남긴다. requires만 여러 개 적고 실제 근거는 하나만 남기지 않는다. any 조건의 모든 분기가 전제를 보장해야 하는 기존 규칙을 유지한다.

원고 확장 설계의 시작 규모:

| 범위 | 작업 목표 | 수량의 의미 |
|---|---|---|
| 기존 정상 210개 | 유효한 내용 보존·한국어 교정·새 엔진과 호환 | 전부 새로 썼다고 계산하지 않음 |
| 기간 모듈 | 현 30개에서 약 150~250개 규모로 확대 검토 | 다른 역할·조건이 있는 실제 고유 모듈 |
| 고급 정통 모듈 | 약 100~180개 규모로 조건표와 함께 설계 | 기간 모듈과 중복 집계 금지 |
| MBTI | 16유형×6주제 약 96개를 초기 검토 규모로 사용 | 단어만 다른 같은 원고는 제외 |

이 숫자는 제품 설계의 출발점이지 검증된 최소 충분량이 아니다. 먼저 조건·역할·출력 coverage 표를 만든다. 필요한 조건이 빠지면 수량을 넘어도 보완하고, 의미 없는 항목을 채워 목표 수를 맞추지 않는다. 원고 총수·활성 규칙 수·공통 설명·초안·검토 기록을 구분한다.

사용자 입력을 영어로 바꾸고 운세를 만들어 번역하는 집필 흐름은 사용하지 않는다. 한국어로 직접 작성한다. 남의 운세 풀이를 대량 수집하거나 결과를 복제해 원고 수를 늘리지 않는다.

## 11. 선택·조립·반복·충돌을 함께 관리하라

서로 다른 조건이 같은 원고를 공유하는 것은 허용한다. 그러나 서로 다른 원국을 전부 일간 하나로 묶거나 날짜가 다른데도 같은 주기 문구를 그대로 돌려서는 목표를 충족하지 못한다.

구체적인 복합 규칙을 우선하고, 해당하지 않으면 덜 구체적인 정상 원고로 fallback한다. 중립·정보 부족 안내를 마지막 단계로 둔다. 충돌 축과 독점 그룹을 이용해 양립하지 않는 해석을 동시에 출력하지 않는다.

연간 ‘확장’과 일간 ‘신중함’은 반드시 모순은 아니다. ‘올해의 큰 방향 / 오늘 실행할 때의 조건’처럼 범위를 연결한다. 반대로 같은 일에 즉시 실행과 보류를 동시에 요구하면 우선순위나 조건을 정해 하나의 안내로 정리한다.

동일 문장 제거만으로 중복이 해결됐다고 하지 않는다. ‘완성도 점검’, ‘마감 확인’, ‘수정 기준 정하기’처럼 뜻이 겹치는 모듈을 결과 전체에서 읽는다. 출처·정책 설명은 고유 풀이와 구분하되 불필요하게 곳곳에 반복하지 않는다.

한 결과의 실제 적용 원고, 표시 문단, 제안, 주장, feature, 구간, 정책 버전을 정확히 추적한다. 길이·중복·충돌 때문에 빠진 내용을 적용했다고 남기지 않는다. 여러 구간이 같은 원고를 공유하면 실제 표시와 각 구간 참조를 함께 보존한다.

운영 LLM으로 마지막 문장을 연결하지 않는다. 연결 문구·한정 표현·요약은 검토 가능한 결정적 코드와 원고로 구성한다. 단어 몇 개를 이어붙여 조사가 틀리거나 주어·대상이 갑자기 바뀌는 템플릿을 피한다.

방문 기록을 저장해 매번 다른 원고를 고르지 않는다. 내용 릴리스가 바뀔 때 결과도 바뀔 수 있으므로 공개 버전을 기록하고, 가능하면 운세 기간 중 수시 교체를 피한다. 버전 간 결과를 같은 조건의 결과로 비교하지 않는다.

## 12. 사용자가 제시한 정밀 분석 예시를 재현 사례로 포함하라

### 12.1 입력과 기대 경험

- 양력 1995-11-08, 15:03, 전통 대운 분류 남성, 출생 지역 경기도.
- 도시는 처음에 미지정. 이후 수원·성남·안양 등 명시적으로 선택한 도시 좌표를 사용해 비교한다.
- 표준시와 진태양시 프로필을 별도로 계산한다.
- 세운 비교의 대상은 2026~2030으로 고정한다. 현재 대운 비교용 기준일도 테스트에서 명시한다.

사용자가 원하는 예시의 수준은 다음과 같다.

“먼저 시주 경계를 설명하고, 원국과 지장간을 제시한 뒤 신강·격국·용신을 이유와 함께 읽는다. 그 구성에서 십신·직업·재물·연애를 연결한다. 대운 개시 계산과 10년 표를 보여주고, 2026~2030의 간지·원국 및 대운 관계를 해마다 달리 해석한 뒤 표로 비교한다. 시각 정책이 달라지면 무엇이 달라지는지 마지막에도 연결한다.”

이 흐름을 결과 화면과 실제 출력 예시로 완성하라. 이 한 사람에게만 적용되는 하드코딩이나 특정 출생일을 감지하는 문장 분기를 넣지 않는다.

### 12.3 시주가 달라질 때 실제로 달라져야 하는 것

표준시 庚申과 진태양시 己未가 실제로 산출되는 조건에서는 다음을 비교한다.

- 시간·시지·지장간·십신·통근.
- 亥卯未 후보의 존재 여부와 다른 관계의 출현.
- 그 차이를 전제로 한 강약·격국·용신 후보.
- 그 후보를 근거로 선택한 직업·재물·관계 원고.

대운 순역이나 개시가 같게 유지되는 항목도 있을 수 있다. 모든 항목을 억지로 바꾸거나, 반대로 시주 표만 바꾸고 본문은 그대로 두지 않는다.

이 예시 하나에 맞는 결과가 나왔다는 이유로 전체 입력 지원이 완료됐다고 판단하지 않는다. 다른 일간·계절·성별 분류·절입 경계·시간 미상·대운 전환으로 검증을 넓힌다.

## 13. 직업·재물·연애 메뉴에도 기간 흐름을 연결하라

‘기본 성향’과 ‘선택 기간의 흐름’을 화면에서 구분한다. 기존 메뉴를 오늘 날짜 때문에 매번 다른 성격으로 바꾸지 않는다. 올해·내년을 바꾸면 같은 원국의 주제 해석이 기간 조건에 따라 달라져야 한다.

직업은 어떤 십신·구조·기간 관계를 어떤 일의 방식·협업·성과 주제로 해석하는지 연결한다. 출생정보만 보고 특정 회사·직무·경력을 이미 안 것처럼 쓰지 않는다. 대화 기억이나 사용자의 실제 직업을 운세 생성 입력으로 몰래 사용하지 않는다.

재물은 재성의 존재, 뿌리·계절·대운 관계를 구분해 설명할 수 있다. 바로 투자수익·당첨·손실 확률로 바꾸지 않는다.

연애·결혼은 일지와 주제 관련 관계를 해석하되 현재 상대·혼인 여부·성적 지향·실제 갈등을 추정하지 않는다. 전통 배우자성 규칙을 채택하면 그 규칙과 현대적인 일반 관계 안내를 구분한다. 결혼 주제를 검토할 시기를 설명할 수 있지만 특정 연도 결혼 확정·외도·이별 확정을 넣지 않는다.

서비스 원고는 전통 상징 해석이라는 공통 안내를 분명하게 제공하되, 모든 문단마다 같은 면책 문장을 반복해 읽을거리를 망치지 않는다. 필요한 전제·예외는 해당 내용 가까이에 둔다.

## 14. 띠·별자리·혈액형과 MBTI를 같은 근거로 포장하지 마라

사주 고급화와 함께 기존 가벼운 메뉴도 주기·내용을 정리한다. 현재 7개 문구의 7일 반복만으로 새 운세라고 보이게 하는 구조를 보완한다.

- 띠: 출생 연지 수준의 거친 분류라는 한계를 유지한다. 사주형 기간 해석을 적용하려면 선택 띠와 실제 연·월·일 지지 관계 중 채택한 규칙을 계산하고 그 근거를 제공한다. 전체 출생 사주를 분석한 것으로 표시하지 않는다.
- 별자리: 선택 별자리의 정적 이야기와 날짜별 편집 내용을 구분한다. 실제 행성 위치·트랜짓을 구현하지 않았다면 천체 분석으로 설명하지 않는다. 정밀 서양점성술 엔진을 이번에 무리하게 덧붙이지 말고, 사용한 기준에 맞는 완성된 메뉴를 유지한다.
- 혈액형: 생년월일·절기·행성으로 성격이나 오늘 사건을 연결하는 가짜 규칙을 만들지 않는다. 가벼운 유형별 읽을거리로 두고 필요한 편집 내용만 확충한다.

새 MBTI 메뉴는 16유형을 직접 선택해 볼 수 있게 한다. MBTI를 모르거나 선택하지 않으면 추측하지 않는다. 검사 문항이나 정식 평가도구를 복제하지 않는다.

MBTI는 ‘유형별 기본 설명 + 주제별 상황 + 선호를 참고한 행동 제안’으로 구성한다. 초기에는 16유형×6개 생활 주제 규모의 실제 구별되는 원고를 검토한다. 4글자의 단어만 바꾸어 같은 내용을 반복하지 않는다.

예: 일정 변경이라는 편집 주제에서, 계획을 먼저 정하는 방식을 선호하는 경우 조정할 항목을, 선택을 열어두는 방식을 선호하는 경우 결정할 시점을 제안할 수 있다. 이는 편집 설계 예시이며 실제 개인 행동이나 사건 예측이 아니다. E/I·S/N·T/F·J/P의 선호와 제안을 연결한 이유·고정관념을 피하는 반례를 관리한다.

날짜별 주제 배정은 편집 정책으로 표시한다. 일별로 고정되는 풍부한 편집 일정이나 규칙을 사용할 수 있으나, MBTI의 별도 천문 주기가 있다고 꾸미지 않는다. 사주 메뉴에는 이런 날짜 배정 방식을 가져와 사주 분석으로 위장하지 않는다.

가벼운 메뉴의 모든 타입에 매일 새로운 완성 문장을 강제할 필요는 없다. 7개 반복의 한계를 개선하되 실제로 다른 내용과 상황을 확보한다. 같은 타입·조회일·콘텐츠 버전의 결과는 일관돼야 한다.

## 15. 한국어 편집은 korean-skills를 기본으로 적용하라

사용자는 제목에 대해 ‘상황이 바로 보이는 담백한 방향’을 선택했다. 비교안의 A 후보를 모두 승인한 것은 아니다. 본문·생활 제안·근거·안내까지 자연스러운 해요체로 다듬는다. 문장마다 사용자에게 선택을 요구하지 않는다.

`https://github.com/DaleSeo/korean-skills`의 실제 humanizer·grammar-checker·style-guide 지침과 필요한 참조 문서를 읽고, 교정·문법·일관성 점검을 적용한다. 필요한 스킬의 사용 버전·출처를 기록한다. 프로젝트 범위에서 필요한 문서와 지침만 사용하고 운영 앱의 런타임 의존성으로 넣지 않는다. 실행 스크립트나 전역 설정을 무검토로 변경하지 않는다.

사용자 기준이 스킬의 일반 규칙보다 우선한다. 단어 출현 횟수·AI 탐지 점수·자체 자연도 등급·기계적인 변경률로 승인하지 않는다. 의도적인 오타·띄어쓰기 오류·문장 길이 난수를 넣지 않는다. 문법 예시나 권장 표기는 실제 한국어 허용 범위와 문맥을 확인한다.

구체적인 편집 기준:

- ‘섬세한 기준을 나에게도 다정하게’는 거절된 제목이다. 뜻이 드러나는 상황·내용으로 다시 쓴다.
- ‘기준·관점·소재·여백·성장·리듬’ 같은 단어를 전부 금지하지는 않되, 추상적인 단어 연결로 실제 설명을 대신하지 않는다.
- ‘만나는 사람이 없다면 이 일을 새로 만들 필요는 없어요’처럼 대상이 모호한 안내는 독자가 실제로 어떻게 읽으면 되는지 직접 설명한다.
- 명리 용어는 한글 이름과 짧은 설명을 제공하고, 필요 없는 영어·개발 용어는 화면에서 덜어낸다.
- 고급 풀이를 전부 일반적인 업무·자기계발 조언으로 바꾸지 않는다. 실제 글자·자리·관계가 왜 그 해석으로 이어졌는지 충분히 남긴다.
- 제목과 본문을 따로 검토한다. 본문이 바뀌었는데 예전 제목이 엉뚱한 내용을 가리키지 않게 한다.
- 원문의 뜻을 평범한 말로 정리한 뒤 다시 쓰고, 마지막에 전제·조건·한계와 대조한다.
- 원고마다 왜 고쳤는지 구체적으로 기록한다. 모든 비교표에 동일한 ‘추상 표현을 줄임 / 의미 보존’ 문구를 자동 채우지 않는다.

이번 예시의 12개 분석 항목은 내용·깊이 기준이다. ‘정밀 분석’이라는 제목을 달았다는 이유로 권위·검증을 주장하지 않는다. 전체 말투는 사이트의 해요체로 자연스럽게 통일할 수 있다.

## 16. 상세 UI·인쇄·모바일 흐름을 완성하라

기존의 익숙한 한국어 운세 포털 분위기와 큰 글자, 3×3 진입 구조를 유지한다. 고급 기능을 이유로 영어 히어로·보라색 그라데이션·AI 채팅 화면으로 교체하지 않는다.

정통사주 결과 상단에는 핵심 요약과 선택한 시각 기준, 입력 수정·기간 선택을 제공한다. 상세 목차로 원국·강약·용신·대운·세운 등에 이동할 수 있게 한다. 긴 본문을 한 화면의 거대한 단락으로 출력하지 않는다.

사주표는 순서를 명시하고 한글·한자를 함께 보여준다. 대운과 세운은 현재·선택 구간을 분명히 하고, 표가 모바일 폭을 넘으면 열을 줄이거나 카드 형태로 읽을 수 있게 한다. 색상만으로 오행·선택 상태를 구분하지 않는다.

고급 비교에서 바뀐 시주와 그에 따른 해석은 같이 갱신한다. 계산만 새 프로필이고 요약은 이전 프로필인 상태를 만들지 않는다. 로딩·오류·미확정·정보 부족 화면도 완성한다.

인쇄·PDF에는 기본 요약뿐 아니라 선택한 정책, 원국·지장간·대운·세운·해석에 필요한 상세가 포함되게 한다. 인쇄용 상세 열기와 종료 후 상태 복원을 유지한다. 간단 결과와 정밀 결과를 각각 검증한다.

## 17. 개인정보·운영 비용과 상태를 보존하라

새 도시·대운 분류·시각 정책 입력도 브라우저 메모리에만 유지한다. 출생정보·선택 도시·개인 결과·추적용 해시를 요청·URL·분석 이벤트·콘솔·localStorage·sessionStorage·쿠키에 기록하지 않는다. 도시 선택을 외부 지오코딩 서버에 전송하는 방식은 피하고 로컬 목록을 우선한다.

공유에는 일반 메뉴 링크만 넣는다. URL로 개인 사주를 복원하는 기능은 추가하지 않는다. 인쇄물에는 개인 입력이 들어갈 수 있으므로 실제 출력과 안내를 일치시킨다.

로그인·결제·유료 잠금·모델 호출·운세 상담 서버를 추가하지 않는다. 고급 원고 양이 늘면 필요한 코드·정적 데이터만 나누어 불러오되 개인 데이터가 요청 경로에 실리지 않게 한다. 현재 프로젝트가 정적 export로 운영될 수 있는 구조를 유지한다.

## 18. 출처·정책·검토 이력을 유지하라

계산 정책과 명리 해석 정책, 콘텐츠 버전을 각각 관리한다. 새 고급 규칙은 과거의 단순 집계 기반 해석과 구분할 수 있어야 한다. 버전은 실제 변경된 항목에만 올린다.

출처에는 실제 제목·저자·위치·URL/식별자·확인일·사용 범위·채택 정책·검토 상태를 남긴다. 직접 읽지 못한 원전은 후보로 남기고 가짜 쪽수·확인 날짜·전문가 이름을 만들지 않는다. 소프트웨어 README에 기능이 있다는 것과 전통 판단의 타당성이 확인됐다는 것은 다르다.

독립 검토 승인 상태를 자동 부여하지 않는다. 작성자 교정, 자동 구조 검사, 독립 한국어 편집, 명리 규칙 검토의 범위를 구분한다. 고급 규칙을 구현하면서 편집 규칙을 정했다면 ‘서비스 채택 해석’으로 표시할 수 있으나 학계·전문가의 단일 합의라고 쓰지 않는다.

기존 review-history와 supersedes 구조를 유지·확장한다. 과거 원문 스냅샷과 기록을 덮어쓰지 않고, 현재 원고·주장 해시가 맞는지 판단한다. 다른 원고의 claim으로 검토를 채우는 것을 막는다. 과거 승인이 변경된 원고에 그대로 유효해지지 않게 한다.

내부 계산 근거는 방문자 정보를 서버에 남기지 않는 로컬 진단과 합성 fixture에서 재현한다.

## 19. 검증은 계산·판단·선택·문장·전체 경험으로 나눠 실행하라

### 19.1 계산 고정 사례

- 사용자 예시 1995-11-08 15:03의 도시 미상·명시 도시·표준시·진태양시 비교.
- 자시·자정·15시 등의 시주 경계 직전·정확·직후.
- 입춘·입동 및 월 절입 직전·정확·직후.
- 양력·한국 음력·윤달·DST·시간 미상·날짜 이동.
- 10일간×10천간 십신 표, 12지지 지장간과 해당 십신.
- 순·역 대운, 절입 직전후, 출생과 절입이 같은 시각, 대운 개시 전·정확한 시작·직후.
- 2026~2030 간지, 대운 전환을 포함한 다른 5년 구간.

같은 라이브러리로 만든 기대값을 같은 라이브러리와 비교한 것을 독립 검증이라고 부르지 않는다. 시간대와 정책이 같은 자료끼리 비교하고 차이는 기록한다.

### 19.2 해석 규칙과 반례

- 구성 글자만 존재하는 경우와 합화 조건까지 충족하는 경우를 구분.
- 후보의 한 글자·시주가 빠지면 그 전제에 의존하는 판단도 사라짐.
- 단순 오행 개수는 같지만 월령·뿌리·투간 등이 달라 판단이 달라지는 사례.
- 신강·중화·신약 경계에서 근거와 후보가 일관됨.
- 억부와 조후가 다른 목적의 결과를 가질 때 무작정 합치지 않음.
- 식신·재성·편관의 공존만으로 완전한 구조를 확정하지 않음.
- 모르는 feature를 0으로 채우지 않고 미확정이 전파됨.
- any의 잘못된 분기, 기준값 축소, claim·basis·조건 불일치를 거부.

### 19.3 결정성과 원국별 차이

- 같은 입력·조회기간·정책·릴리스를 10분 차이로 재실행해 동일함.
- 새로고침·세션·브라우저 시간대·규칙 배열 역순·무관 feature에 의해 결과가 바뀌지 않음.
- 같은 일간의 다른 원국에서 실제 관련 조건이 달라지면 해당 원고·설명이 바뀜.
- 달력 날짜만 바꾸고 간지·문맥이 같으면 억지로 새 글을 선택하지 않음.
- 정적 기본 성향이 조회 날짜 때문에 바뀌지 않음.
- 같은 연간 조회 안의 ‘현재 날짜’ 변경으로 전체 해석이 임의로 변하지 않음.

### 19.4 반복과 기간 경험

대표 원국 최소 20~30개를 일간·계절·시간 미상·고급 구조 등으로 고르게 고른다. 각 원국의 365일·12개월·여러 연도 결과를 로컬에서 생성하고 다음을 분석한다.

- 완성 본문의 동일 반복과 적용 원고 ID 조합의 반복을 구분.
- 한 결과 내 의미 중복, 반복 행동, 상충 지시를 후보로 수집하고 대표 전체 결과를 직접 읽음.
- 동일한 천간이 돌아오는 10일 후에도 지지·월·연·원국 관계가 달라 실제 다른 내용이 생기는 사례.
- 같은 간지 반복이 정당하게 같은 설명을 재사용하는 사례.
- 연간·월간·일간의 내용이 서로 모순되는지와 기간별 범위.
- 대상 구간이 짧은데 ‘분기마다·올해 내내’ 조언을 붙이지 않음.

365일 전부 다르다는 인위적 목표, 난수·날짜 해시로 문구만 바꾸는 방식, 반복률 숫자만 낮추는 동의어 치환을 사용하지 않는다. 반복이 남으면 어떤 입력·조건에서 왜 남는지 보고하고 실제 빠진 규칙·원고를 보완한다.

### 19.5 실제 화면과 회귀

기존 유효한 단위·통합·E2E·PDF 검사를 유지하며 변경에 필요한 의미 있는 검사를 추가한다. 테스트 개수를 늘리는 것을 목표로 삼지 않는다. 문구가 자연스럽게 바뀐 기대값은 이유를 기록하고 수정할 수 있다.

입력→정밀 결과→정책 비교→기간 변경→근거→다른 메뉴→인쇄를 직접 확인한다. 320/390px·확대·키보드·기존 별자리 195px·긴 한자표·5년 표를 확인한다. 실제 PDF의 포함·부재·페이지 분리·한글·열림 복원을 검증한다.

외부 요청·URL·콘솔·저장소·쿠키와 도시·대운 입력의 개인정보 회귀를 확인한다. 정적 빌드에서 draft ID·제목 유출과 새 메뉴의 실제 연결도 확인한다. 원격 운영·실기기·인스타 인앱·원격 CI를 실행하지 않았다면 미실행으로 남긴다.

tsx IPC 등 환경 제한은 우회 명령과 별도로 기록한다. 전체 verify가 중단됐는데 개별 성공을 합쳐 명령 전체 통과라고 쓰지 않는다. 가능한 검증은 직접 실행하고, 제출 로그를 읽은 것과 직접 실행을 구분한다.

## 20. 구현 순서와 완료 기준

다음 순서로 진행하되 문서만 작성하고 멈추지 않는다.

1. 기존 상태·대표 실패·반복·정책 기준 고정.
2. 출생 시각·도시·태양시·지장간·대운 등 계산과 고정 사례.
3. 고급 명리 판단·불확실성 전파·반례.
4. 기간 문맥과 원고 선택·조립·해석 trace.
5. 조건별 원고 확충·한국어 편집·정밀 화면.
6. 기존 가벼운 메뉴 보완·MBTI.
7. 장기간 결과·화면·PDF·개인정보·빌드 회귀와 검토 묶음.

완료로 보고하려면 다음이 실제로 확인돼야 한다.

- 사용자 예시 수준의 12개 분석 항목과 대운·5년 세운 표가 입력별로 생성됨.
- 예시 수치에 맞추는 하드코딩이 없고, 계산 정책별 차이가 근거와 본문에 전파됨.
- 기본 성향은 안정적이며 기간별 내용은 실제 명리 문맥의 변화에 맞춰 구성됨.
- 여러 조건별 모듈을 조합하며, 어떤 모듈이 왜 사용됐는지 재현 가능함.
- 원고 확장 수량·역할·활성·초안·출처·검토 상태가 정확히 구분됨.
- 같은 조건의 결정성과 다른 원국·기간의 유의미한 차이를 각각 보여줌.
- 한국어와 모바일·인쇄 품질이 실제 출력에서 확인됨.
- 기존 무료·정적 실행·개인정보 보호를 유지함.

계산과 규칙으로 뒷받침할 수 없는 고급 판단은 조용히 확정하지 말고 후보·범위 제한을 제공한다. 이 경우 무엇이 구현됐고 어떤 판단이 제한됐는지 항목별로 적는다. 짧은 기존 결과에 ‘정밀 분석’이라는 제목만 붙여 완료 처리하지 않는다.

## 21. 최종 제출물

- 실제 수정 소스와 콘텐츠, 설치·실행 방법.
- 계산·시간·명리 판단 정책과 출처·버전.
- 기존 지적 및 이번 요구의 대응표.
- 사용자 예시의 표준시/진태양시 전체 결과와 차이표, 계산 검증 자료.
- 다른 원국의 정밀 결과와 2026~2030 또는 선택 5년 세운 비교.
- 기간별 원고·조건·역할 coverage 표와 실제 증가·유지·비활성 수.
- 같은 사람의 오늘/내일·이번 달/다음 달·올해/내년 전후 결과.
- 같은 일간의 다른 원국 비교와 시주 경계·대운 전환 비교.
- 장기간 반복·충돌·의미 검토 후보와 실제 수정 내역.
- 한국어 수정 전후와 사례별 구체적인 편집 이유.
- 실제 테스트·화면·PDF·빌드·개인정보 검사 결과, 실패·우회·미실행 구분.
- 독립 검토자가 원래 요구·소스·원고·계산·근거·최종 화면을 대조할 수 있는 검토 ZIP과 START_HERE.

최종 사용자 설명은 핵심 변화와 제한만 짧게 쓴다. 원고 수·자동 통과를 과학적 적중률·전문가 승인·AI의 자율 학습으로 표현하지 않는다. 실제 휴대전화로 접속할 공개 URL을 이번 작업에서 만들지 않았다면 로컬 검사 상태와 구분한다.
