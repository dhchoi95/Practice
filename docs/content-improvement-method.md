# 콘텐츠를 반복해서 고도화하는 방법

현재 구현은 모델의 가중치를 스스로 학습시키는 기능이 아닙니다. 원고·조건·근거·평가 사례를 저장하고 수정 결과를 반복 점검하는 작업 흐름입니다. 모델이 쓴 문장을 같은 모델이 좋다고 평가하는 것만으로 정확도가 높아졌다고 판단하지 않습니다.

## 반복 작업 흐름

1. 짧은 원고·반복 문장·조사·적용 조건을 분석하고 `content-review/issues.json`에 지적 출처와 상태를 기록합니다.
2. 계산 전제를 확인합니다. `interpretation-bases.json`의 25개 정의는 일간 10개, 기간 십성 10개, 확정 천간 관계 5개입니다. 원고 수에 합산하지 않습니다.
3. `evidence`에 근거 키·확장 이유·반대 사례·한계를 씁니다. 주제별 상황과 실행 방법을 작성하고 이름만 바꾼 문장을 피합니다.
4. `npm run content:evaluate`로 조건·근거 연결·반복·선정 조사를 검사합니다. `verify`, `build`, 브라우저와 실제 PDF 검사로 기능 회귀를 확인합니다.
5. 독립 검토자와 가능하면 명리 검토자의 교정을 받습니다. 새 오류를 고정 평가 사례로 추가한 뒤 수정하고, 검토한 버전만 운영에 반영합니다.

평가 사례는 `tests/fixtures/editorial-evaluation.json`에 있습니다. 합성 출생일과 feature 수준의 정상·반례 사례를 사용합니다. 현재 23개는 구현자가 만든 수용 기준이며 전문가가 확정한 예측 정답이나 독립 학습/검증 분할이 아닙니다. 결과에 맞춰 실패 사례를 지우거나 기준을 완화하지 않습니다.

GitHub의 `.github/workflows/content-quality.yml`은 저장소에 반영된 뒤 PR 또는 수동 실행에서 검사·미리보기·빌드를 수행합니다. 자동 집필·운영 배포·모델 API 호출은 없습니다. Actions 사용 범위와 비용은 계정 정책에 따릅니다. 세션이 끝난 뒤 모델이 무기한 백그라운드에서 집필하는 구조도 아닙니다.

## 정확도를 더 높이기 위한 자료

현재 근거는 서비스의 대응 정책과 독립 편집 원고입니다. 확인하지 않은 원전·쪽수·인용을 새로 붙이지 않았습니다. 다음 단계에는 사용권과 출처가 확인된 원전·해설, 적용 학파와 정책, 독립 검토자의 수정 예시를 확보해야 합니다.

계산 사실·전통 해석의 주장·서비스의 생활 제안을 구분하고 서지 정보·위치·확인자·검토 상태를 기록합니다. 서로 다른 해석은 하나의 정답처럼 합치지 않습니다. 명리 검토자에게는 권장 문장과 함께 그 문장이 성립하지 않는 사례도 요청합니다.

월령·지장간·합충 등 현재 계산하지 않는 항목을 쓰려면 계산 정책과 독립 기대값부터 정하고 검증해야 합니다. 오행 개수와 확정 천간 집계를 강약·용신·전체 사주 판정으로 확대하지 않습니다. 달력 일치와 풀이의 적중률도 구분합니다.

자료가 충분히 쌓이면 전문가가 검토한 작성 예시와 별도 평가 예시를 분리할 수 있습니다. 필요할 때 검색을 통한 근거 참조나 외부 학습 작업을 검토하되 비용·데이터 범위·평가 기준을 먼저 정합니다. 현재는 버전이 있는 정적 원고와 검증된 조건으로 낮은 운영 비용을 유지합니다.

## 사용자 피드백

`content-feedback-template.json`이 예시입니다. 메뉴·문장 인용·모호하거나 부정확한 부분·원하는 설명 방향이면 충분합니다. 방문자 출생정보를 수집하지 않습니다. 재현이 필요하면 가상의 평가 사례 ID와 계산 feature를 연결합니다.

독립 검토 전에는 원고를 `human-reviewed`로 바꾸지 않습니다. 이번 지적도 `implemented-pending-independent-review` 상태로 남깁니다.

## 1.2.0에서 추가한 절차

현재 수용 사례는 29개(기존 23개 보존)다. 자유문 counterExample의 존재와 의미 검증 완료를 구분한다. `semantic-cases.json`의 10개는 사람 검토 대기로 유지한다. `content:review`로 실제 원고·주장 해시와 출처 상태를 확인하고, `content:assembled`로 전체 결과의 반복·충돌·구체성·범위를 검토한다. 시범 복합 조건 4개는 `content:compound`의 명시적 로컬 실험에서만 포함한다. 검토 전 draft는 일반 repository와 빌드에 들어가지 않는다.

새 작업에서는 먼저 baseline 해시와 실패 입력을 고정하고, 수정 후 verify/build/브라우저/실제 PDF를 실행한다. 기존 검토 해시와 달라진 주장은 새 버전의 검토 기록으로 연결한다. 자동 스크립트는 human-reviewed나 독립 승인 상태를 부여하지 않는다. 1.2.0의 상세 구조·실제 명령·남은 검토 후보는 `content-schema-1.2.0.md`, `content-improvement-1.2.0.md`, `content-review/assembled-notes.md`를 따른다. 이 문서 앞부분의 23개/135개는 1.1.0 당시의 기록이다.

## 1.3.0의 한국어 편집과 기록

현재 작업은 정상179개 본문 등을 교정하고31개는 유지했다. 원고 수나 모델 성능 대신 생활 장면·중복·기간·관계의 전제를 편집했다. 자세한 기준과 전후24쌍은 editorial-standard-1.3.0.md 및 생성 보고서를 따른다.

과거 검토를 새 해시로 덮어쓰지 않는다. review-snapshots.json으로 이전 원문을 보존하고 supersedes로 후속 기록을 연결한다. content:record는 명시적 로컬 실행에서 구현자 교정만 추가하고, content:review는 과거/현재의 해시·주장 소유·연결을 검사한다. 독립 편집/명리 승인을 자동 부여하지 않는다. 세부 방법은 review-history-1.3.0.md를 따른다. content:editorial은 기존36개 기록과 선택 필드 보존, 변경/유지/13메뉴,24쌍,빈도와6개 실제 표시 이력을 확인한다. 이 역시 의미 승인이나 모델 학습이 아니다.
