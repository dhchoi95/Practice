# 콘텐츠·검토 구조 1.2.0

## 세 층과 기존 210개 호환

`rules.json`의 조건 규칙 210개와 기존 evidence 형식은 유지한다. `reasoningFor()`는 기존 원고를 읽을 때만 다음 구조로 올린다. 어댑터는 원문·reviewStatus·contentVersion을 고쳐 저장하지 않는다. evidence가 있는 135개는 계산 전제와 내부 해석 주장을, 모든 원고는 생활 제안 참조를 제공한다. evidence가 없는 기존 원고 75개에 검증된 전통 주장을 새로 꾸며 붙이지 않는다. 그 원고의 실제 조건 입력은 `usedFeatures`로 추적한다.

| 층 | 실제 필드 | 뜻 |
|---|---|---|
| 계산 사실 | `premises[]`: basisKey, feature, op, value / 실행 trace의 observed | 조건이 보장하는 값과 계산 결과의 관측 값. 성격·사건의 증거가 아님 |
| 해석 주장 | `interpretations[]`: id, text, sourceIds, status=internal-policy | 계산 사실에서 어떤 관찰 주제로 확장했는가. 출처 ID의 존재가 진실성 인증은 아님 |
| 생활 제안 | `proposals[]`: id, tipIndexes, status=suggestion | 원고의 실천 문장 인덱스. 사용자의 행동을 알아낸 사실로 분류하지 않음 |

시범 원고는 `reasoning.schemaVersion:2`를 직접 작성한다. 신금+식상>=2+재성>=1 원고는 세 전제를 각각 저장한다. 모든 전제는 requires에 포함되고 전체 조건에 의해 보장돼야 한다. `any`는 모든 분기가 전제를 보장해야 한다. 조건에 쓴 사실을 전제에서 빼거나 실제 기준 2를 1로 낮춰 기록하면 실패한다. 현 V2의 직접 주장은 internal-policy만 허용한다. 확인된 외부 문헌을 도입할 때는 별도 검토와 schema 변경이 필요하다.

근거 kind·feature·연산·값의 대응은 `validateBasisDefinitions()`로 검사한다. 일간은 eq 정수 0~9, 기간 관계는 eq 십성명 10개, 확정 천간 관계는 gte 정수 1~3이다. 기존 25개 정의는 내부 정책이다. 범위·출처 문자열이 있다는 이유로 전통 해석의 진실성을 승인하지 않는다.

## 실제 사용 이력

`interpret()`의 ruleTraces에는 원고/버전, 근거 ID, 표시 주장 ID, 전제와 관측 값, 본문·조언 표시 인덱스, 공통 설명 ID가 있다. `usedFeatures`는 그 규칙의 requires·조건·제외·순위 필드 중 입력에 존재한 의존 값만 담는다. 비교와 정렬의 설명을 위한 의존 값이며, 인터프리터의 CPU 단위 단락 평가 접근 로그는 아니다. 누락 feature를 0으로 만들지 않으며 별명·생년월일은 담지 않는다.

`composePeriodReading()`은 기간 start/end/label과 관계 feature를 각 구간에 보존한다. 전체 appliedRuleIds는 실제 표시 원고의 합집합이다. 같은 원고의 동일 본문을 두 구간이 공유하면 본문은 한 번 표시하고 두 구간 이력에서 그 문장을 참조한다. 다른 원고의 완전히 중복된 문장이나 길이 제한으로 빠진 원고는 적용으로 기록하지 않는다. 제외 이유는 segmentTraces 안에만 둔다. 공개 화면에는 ‘앞 구간 · 편재’ 같은 제목으로 연결하고 내부 ID나 전체 JSON은 표시하지 않는다.

본문을 버리기 전에 중복 집합을 갱신하지 않는다. 결과의 생활 제안은 화면과 엔진 모두 최대 4개로 맞추고 보이지 않는 조언 주장은 trace에서 제외한다. 종합 본문 상한은 1,800자다. 기간 조립도 기본 상한 1,800자를 두며 현재 연간/월간 두 구간은 모두 이 범위 안에 들어간다. 제한으로 모든 원고가 빠지면 중립 안내를 제공하며 이 안내는 원고 분량 예산과 별도다. 표시되지 않은 원고의 제목·적용 주장을 남기지 않는다. 진단은 함수 반환값과 로컬 산출물이며 서버 전송·영속 저장을 추가하지 않았다.

## 버전과 해시

- 콘텐츠 묶음 1.2.0 / 규칙 엔진 2.0.0 / reasoning schema 2.
- 교정한 기존 원고 36개만 contentVersion을 1.2.0으로 변경했다. 본문은 210개 모두 1.1.0 기준과 동일하다. 나머지 174개 원고 버전과 reviewStatus는 보존했다. 근거 정의 중 fact 6개를 고쳤다.
- 달력·사주 계산 정책 `KST-MIDNIGHT-1.0`과 계산 소스는 변경하지 않았다.
- `content-review/reviews.json`의 원고·주장 해시는 정렬된 JSON 키의 UTF-8 SHA-256이다. 원시 파일 해시와 구분한다. 변경된 원고·주장을 기준으로 작성한 구현자 교정 기록 36개이며 모두 독립 검토 대기다.
- 원문 파일 해시와 기준 커밋은 패키지의 baseline/snapshot.json, 최종 소스/아티팩트 해시는 SHA256SUMS와 source-snapshot.json에서 확인한다.

## 실행 평가와 의미 검토

기존 23개를 삭제하지 않고 출처와 입력 종류를 붙여 29개로 확장했다. 예상·금지 원고뿐 아니라 해석 주장 ID도 확인한다. 모든 사례에 저장소 역순과 무관 feature 추가 안정성 검사를 적용한다. 출생일 기반 합성 사례는 완전한 런타임 집계 불변식을 검사하지만 부분 feature 사례에는 그 검사를 강요하거나 값을 채우지 않는다. 잘못된 schema·any·basis·ranking, 길이 제한·중복과 기간 조립은 단위/통합 검사에 별도로 있다. 이 자료는 구현자 수용 기준이며 독립 holdout이나 예측 정답이 아니다.

기존 counterExample 자유문 135개는 보존한다. 본문과 같은 105개도 내용 자체를 무조건 버리지 않는다. 글자 수나 존재 여부는 의미 검토 통과가 아니다. `semantic-cases.json`의 10개는 상황·빠진 전제·수정 질문·주장 ID를 가진 사람 검토 대기이며 숨은 사용자 feature로 실행하지 않는다.

## 출처와 검토 도구

`sources.json`: 종류, 제목, 저자, URL/식별자, 실제 확인 위치/날짜, 적용 정책, 사용 범위, 확인자, 상태. 외부 3개는 실제 웹 자료를 이번 작업에서 열지 못했으므로 author·확인일·확인자는 null, pending-external-check다. 기존 계산 라이브러리 사용과 원격 자료의 새 확인 완료를 구분한다. 내부 2개는 읽은 소스 위치와 내부 정책 상태를 기록한다. 존재하지 않는 문헌 후보는 만들지 않았다.

`reviews.json`: 실제 원고/주장 해시와 버전, 검토 역할, 날짜, 수정·반례·문제 ID·상태. 작성자 자동 점검을 독립 검토로 승격하지 않는다. 독립 승인 상태는 역할과 실제 검토자 이름을 요구하나 그 이름의 진위를 schema가 인증하는 것은 아니다. 스크립트는 검토 기록을 자동 생성하거나 human-reviewed를 부여하지 않는다. 원고나 주장을 고치면 기존 해시와 달라져 stale 오류가 난다. 새 검토자는 검토한 버전의 새 기록을 추가해야 한다.

`npm run content:review`는 정상 원고와 별도 draft를 함께 검증하고 139개 근거 원고의 독립 검토 대기 목록을 만든다. `--preview`는 로컬 JSON 예시 두 개를 보여준다. `npm run content:assembled`는 6개 전체 결과·6차원 검토 후보를, `npm run content:compound`는 4개 복합 초안의 입력·본문·일반/실험 비교를 만든다. 모두 로컬 파일 작업이다.

## 시범 포함 정책

연애/직업재물 각각 식상2+재성1, 식상2+인성1의 총 4개다. 수를 채우기 위해 추가하지 않았다. `compound-drafts.json`에만 저장하며 모두 draft, 1.2.0-draft.1이다. 일반 repository는 이 파일을 import하지 않는다. 환경 변수나 공개 실험 메뉴도 없다. 도구에서 `experimentalRepository({includeDrafts:true})`를 명시한 경우에만 포함한다.

기존 관계 보완 priority55보다 구체적인 시범 priority65를 먼저 적용하고 같은 exclusiveGroup을 공유하여 단일 보완과 중복되지 않는다. 동수는 기존 결정적 정렬을 유지한다. 식상생재의 성립·강약·학력·매출 등을 판단하지 않는다. 재성형은 실제 전달/시간/비용, 인성형은 학습/적용을 묻는다. 일반 빌드는 기존 단일 관계 원고로 fallback한다. 실제 out/ 202개 파일에서 시범 ID/제목이 없는지도 확인한다.
