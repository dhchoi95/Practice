# 출시 점검 결과 · 2.5.1 후보

**개선·로컬 검증 완료 / 공개 배포 미완료.** 대상은 기존 https://spring-voice-4bdc.eogjs9595.workers.dev/ 이다. 배포 사전 검사 시각 **2026-10-30 08:23:16 KST**에 Cloudflare 연결이 프록시 403으로 차단됐다. 배포 완료 시각/새 Cloudflare version ID는 없다. 이번 변경이 공개 주소에 반영됐다고 보고하지 않는다. 이전에 보관한 공개 버전은 2.4.1이며 현재 응답을 조회하지 못했으므로 최신 상태를 확정할 수 없다.

## 실제 개선

- **기존 화면·브랜드 유지**: 소스의 실제 브랜드인 하루사주, 상단 6개·4×2·3×3·색상·만세력 배치·원고·계산 엔진을 보존했다. 프롬프트 제목의 도하사주를 새 브랜드 승인으로 해석하지 않았다.
- **도움말·개인정보**: FAQ를 5개에서 8개로 보완하고 안내 페이지에서 입력 초기화/서버 자료 삭제/탈퇴의 범위를 나눴다. 개인정보 안내에서 기본 출생정보·짝궁합·선택 유형을 지울 수 있고 하단 공통 문의·삭제 링크가 실제 anchor로 연결된다. 필수 세션/인증/가입 대기 쿠키 3개의 이름·목적·기간·보안 속성을 설명했다. 문의 이메일이 없으므로 가짜 mailto나 접수 완료 화면을 만들지 않았다.
- **검색·공유**: 환경 변수가 없으면 canonical과 sitemap을 생략하던 상태에서 실제 기존 운영 주소를 기본값으로 사용하도록 바꿨다. 공개 23개 페이지에 기능별 제목/설명/canonical/OG URL과 1200×630 브랜드 PNG·Twitter 미리보기를 맞췄다. WebSite와 공개 계층 BreadcrumbList만 사용한다. 개인 결과·AI·종료한 혈액형은 sitemap에서 제외한다. 결과·AI는 검색 봇이 noindex를 읽을 수 있게 robots 차단을 풀고 HTML/HTTP noindex와 민감 응답 no-store를 유지한다. 404에 실제 메뉴 링크를 보완했다.
- **접근성과 삭제 인증**: 본문 테마를 바꾸지 않고 입력·버튼 경계 대비, textarea/쿠키 표 초점을 보완했다. 320/390px·200% 글자·키보드·표/레이더의 텍스트 대안·모달 초점 복귀를 확인했다. 오래된 로그인 세션으로 서비스 계정을 삭제하던 경로에 최근 10분 인증 검사를 추가하고 같은 계정 재확인 안내를 제공했다. 최근 인증 상태의 서비스 우선 삭제는 유지한다. 제공자 장애로 재인증까지 안 되면 실제 운영자 권리 행사 경로가 필요하며 미확정 문의처 상태에서 가입을 열지 않는다.
- **분석은 비활성 준비만**: 선택 분석 업체·측정 ID·전송기·스크립트·대기열이 없다. 공개 이벤트명/메뉴 enum만 허용하고 개인 결과·AI·계정·query/hash·임의 필드는 거절하는 필터를 준비했다. 미설정·허용·거절·철회 모두 통신하지 않는다. ID만 넣어 자동 활성화되도록 만들지 않았고 실제 UI 추적 훅도 연결하지 않았다.

수정 문구·페이지 인벤토리/해시·작성자 재검토 기록을 갱신했다. 기본 원고 JSON과 계산/선정 파일은 바꾸지 않았으며 원국 엔진 35개 해시·고정 선정 33,564건·15개 완성 예시·기존 140개 교정 검사를 통과했다. 독립 명리·편집 승인을 받았다고 표시하지 않는다.

## 이미 있던 것과 추가하지 않은 것

이미 있던 공통 약관/개인정보, 기본 비회원 계산, 결과 입력 지우기, 계정/자료 소유권·암호화·선택 저장, 키보드 모달·스킵 링크, 그래프 텍스트 값, 로컬 인쇄/PDF, 실제 404 처리는 유지·재검사했다. 쿠키 배너·고정 가입 CTA·후기·가짜 성공 사례·환불 절차·결제/구독·마케팅 메일·CRM·외부 폰트·분석 SDK·유료 이미지 생성 API는 신설하지 않았다. 전체 37개 사진 항목의 상태와 근거는 [출시 점검표](checklist.md), 자산/글꼴은 [권리 확인 기록](assets.md)에 있다.

## 배포 실패 원인 재확인

- 기존 배포 자격증명을 값 출력 없이 재사용한 첫 계정 조회가 `Tunnel connection failed: 403 Forbidden`으로 실패했다. **Cloudflare가 토큰을 검사하기 전 프록시 CONNECT 단계의 실패**다. 토큰 만료/권한 오류라고 판정할 근거는 없다.
- 같은 실행에서 토큰 없는 Cloudflare API 루트와 홈페이지도 같은 연결 오류를 냈고, 대조군 npm registry는 HTTP 200이었다. 개인정보 포털·W3C·Google 검색 문서도 프록시에서 차단돼 최신 공식 본문을 읽지 못했다. 공식 문서/법률 검토 완료로 쓰지 않는다.
- 환경 초안 revision 4의 custom 허용 목록에는 이미 api.cloudflare.com와 *.workers.dev가 있다. 따라서 단순 도메인 누락이라고 단정하지 않는다. 현재 실행 프록시의 정책 적용 여부/환경 연결 문제를 확인해야 한다. 저장된 초안이 실행 중인 프록시에 반영됐다는 관측은 없다.
- 계정/기존 Worker·플랜의 실제 확인을 통과하지 못했으므로 스테이징/운영 배포·원격 migration·공개 사이트 검사는 수행하지 않았다. 토큰을 새로 요청하거나 다른 주소 배포를 기존 주소 갱신으로 대신 보고하지 않았다.

최신 사전 검사와 네트워크 결과는 `reports/launch-2.5.1/deployment.json`, `network.json`이며 추적 가능한 요약은 [verification.json](verification.json)이다. 공개 서버가 반영됐다는 버전/시각은 없다.

## 다음 조치와 되돌리기

배포에 필요한 첫 조치는 실행 환경에서 Cloudflare API 및 기존/스테이징 workers.dev 접속 허용이 실제 적용되도록 확인하는 것이다. 기존 초안 검토·저장/게시 후 적용된 환경에서 `npm run ai:deploy:preflight`를 재실행한다. 같은 CONNECT 403이 계속되면 프록시 정책/환경 연결 쪽 점검이 필요하다. API 토큰 값을 채팅에 다시 보내지 않는다.

접속 복구 뒤 현재 기존 배포/바인딩을 읽어 기준 버전을 저장하고 → 분리 스테이징 배포 → 실제 SQLite/파일/무료 기능 확인 → 동일 빌드로 기존 Worker 배포 → 공개 URL의 기능/헤더/모바일 확인 순으로 진행한다. 검증된 변경의 배포에 추가 사용자 승인을 요구하지 않는다. `scripts/deploy-ai.py`는 동일 빌드의 실제 스테이징 검사 기록을 요구한다. 실제 운영 정책·OAuth·AI·분석 준비가 없는 플래그는 계속 꺼둔다.

되돌리기는 실제 조회한 이전 코드/바인딩과 호환되는 Worker로 수행하고 신규 namespace를 삭제하지 않는다. 원고·회원 자료 삭제 migration과 무작정 백업 복원은 하지 않는다. 마지막 보관된 정상 공개 release 2.4.1과 실제 현재 배포 상태가 같은지도 먼저 재확인한다. 코드 복귀와 DB 삭제/복원은 다른 작업이다.

문의 이메일/운영 주체·사업 상태, 실제 AI 처리 업체/국가·법적 근거·연령/보유·정책은 아직 운영자 입력이 필요하다. SITE_CONTACT_EMAIL을 주면 실제 mailto를 빌드하며 확인되지 않은 연락처·답변 시간은 지어내지 않는다. [USER_ACTION_REQUIRED.md](../../USER_ACTION_REQUIRED.md)에 필요한 값만 추가했다.

실제 iOS/Android·인스타 인앱, 실제 OAuth·웹훅·AI 한국어 최소 20건, Cloudflare 대시보드의 주입 SDK·플랜·데이터 위치/백업 정책, 법률/전체 WCAG 준수·검색 반영은 **미검증**이다. 자동 검사만으로 완벽/인증/검색 노출을 보장하지 않는다.
